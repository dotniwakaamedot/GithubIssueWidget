## ユーザーの承諾と GitHub の状態

- 対象は公開リポジトリ `dotniwakaamedot/GithubIssueWidget`。ユーザーは、必要な `status:todo` と `status:done` の追加、検証用 Issue を１件作成して列間移動し、最後にクローズすることを承諾した。作成したラベルと公開 Issue の履歴は残す。既存 Issue・PR の変更は対象外。
- `status:todo` と `status:done` は追加済みで、2026-11-21 の一覧読戻しでも `status:in-progress` と共に存在を確認した。
- 検証用 Issue は**まだ作成していない**。マーカーは `giw-live-d295bc126897471ba7ddcc661216143b`。作成結果が不明な場合は同じ POST を再送せず、全ページでマーカーを照合する。
- 承諾は継続する。再開時に同じ承諾を求め直さず、ユーザー指定の停止条件と、追加の実行前レビューに従う。

## 実装と対象版

- `widget/` に Tauri 2・React・TypeScript・Rust のアプリがある。接続設定、Credential Manager による認証情報保管、Issue 一覧・同期、作成、カード移動を実装した。
- 移動時はステータスラベルを個別に追加・削除し、各応答を確認してから次の更新へ進む。非ステータスラベルの全置換を避け、結果不明や途中失敗では再取得を促す。複数の GitHub 操作は原子的ではなく、他ユーザーとの同時更新や部分反映は残る。
- 現行製品ソース SHA256: `main.rs` = `021488C4C1615EBEFA3185EBDF024A43547657E357715957128F403541A67A97`、`creation.rs` = `61FB68E208B231664DB236E50A37BBB4870763AD61C0071383BACA5730982A87`、`movement.rs` = `ED49F4BA52C6887BCE427E4A6664D335092A1C3311E1B1ED61B4CE322791ABA5`。
- リリース EXE SHA256: `4A58C1363D5ED1A9B2F1FFF7AE45C04DCDA95650E7FB060B2C9B31B40D241C68`。`main.rs` の実 GitHub 読み取り用 ignored テスト追加前にビルドされた版であり、その追加は `cfg(test)` 内に限る。両者を完全に同じビルドとして扱わない。

## 検証済みと未検証

- 製品ソースの Rust 通常テストは65件成功・10件 ignored、URL 範囲のテストは１件成功。ラベル削除応答の修正は独立レビュー済みで、そのリリースビルドは成功した。
- 現在の公開リポジトリについて、アプリと同じ Rust の読み取り処理で repository と Issue を GET し、10件を取得。別途 GitHub CLI でも Issue 10件、Open 10件、Closed 0件、Pull Request 0件と集計した。取得は同時ではなく、Closed と Pull Request の実データ検証にはなっていない。
- Windows 11 でリリース版の設定画面表示・終了を確認。非表示起動時の OS 拡張スタイルに最前面フラグがあることを確認したが、通常表示時の重なりやボタン操作後の OS 属性は未確認。
- GitHub リンクをクリック後に Brave で `https://github.com/` の表示を確認したが、クリック前からブラウザーが開いていたため、今回の操作による新規タブ生成は未証明。
- 実 UI での PAT 登録・更新・削除、再起動後の Credential Manager 読取り、接続先切替、Issue 作成・全列移動、権限不足・レート制限・通信障害・競合時の実動作、各 DPI と秘密の非露出確認は未完了。PAT やトークンはチャット・ログ・ファイルに出さない。

## 停止した実 GitHub 検証

- 承認された計画: [live-plan-02.md](agent-runs/20261120-current-review/live-plan-02.md)、[計画レビュー](agent-runs/20261120-current-review/live-plan-review-02.md)。アプリの Rust 作成・移動処理を隔離コピーで使い、対象をマーカーと番号で固定し、Todo→In Progress→Todo→Done→In Progress→Done→Todo→Done の順に確認する予定。
- 隔離コピー: `docs/agent-runs/20261120-current-review/live-fixture-d295bc126897471ba7ddcc661216143b/`。製品の未追跡ソースと区別し、削除せず保護する。
- 隔離 `creation.rs` SHA256 `82CBF93605B7E6214C39C581C8DA57073A7D4CAB369E1D75928F29E697E0D30A`、隔離 `movement.rs` SHA256 `ADDD844D3CBF35859A15499390DBD083FA482F640C8A51E2D9123B8C3D01C583`。この隔離版のビルドは停止時に中断され、成功していない。
- [ハーネス再レビュー](agent-runs/20261120-current-review/live-harness-review-02.md) は要修正。`live_check_identity` の番号と URL の `assert_eq!` が不一致時に取得値をパニック出力し得る。タイトルの指摘後にも同種の値露出可能性が残ったため、２回の同種問題として停止した。実データの漏出は確認されていない。
- 再開時は、番号・URL を固定メッセージの真偽判定に変更し、各不一致を合成値で検証する。隔離版をビルド・対象 SHA を記録し、実行手順と子プロセス・秘密保護を含め独立レビューするまで実 GitHub に書き込まない。
- 問題発生時は後続操作を中止し、作成結果不明のまま再作成しない。ユーザー指定の「同じ失敗が一度の処理で２回」の回数は、過去の累計と分けて当該処理内で数える。
