# 繰り返しの失敗から得た教訓

作業に関連する項目を参照する。項目は [失敗記録](failure-log.md) で同じ失敗が累計3回以上になったときに転記し、元の発生記録は残す。各項目には失敗 ID、適用場面、確認済みの事実、具体的な予防策、未確認事項を記す。

## F-001: 大量の出力が切り詰められる

- 適用場面: ファイル列挙や長文ガイドの取得など、出力が大きくなる操作。
- 確認済み: 広いファイル列挙、長文ガイド、コンパイル進捗、レビュー時のエラー出力、整理手順や記録の取得、複数文書の一括レビューなどで出力の一部が表示され、従来の累計28回に直近の4回を加え暫定32回とした。発生10・21・23・32は報告等に基づく暫定、26〜28は失敗記録内で確認できず累計は要照合。行数や一致件数を絞っても長い行・複数パターン・コンテキストの重複で上限を超える。複数の長い結果を JSON でまとめた表示や、大量ファイルの Git 操作の警告も切り詰められた。
- 予防策: 長い行や複数の結果を含む合計の出力量を考慮し、必要な範囲を分割して取得する。並列実行と表示を分け、各結果から終了コード・件数・必要な短い範囲を選び個別に表示する。JSON の包装・エスケープによる増加分と全結果の合計も上限に含める。大量ファイルの Git 操作では標準エラーの警告も出力量に含め、機密情報に配慮して処理結果を確認する。ビルド等は機密情報に配慮して可能なら最初からログへ保存し、切り詰め後は既存ログまたは安全に再取得して保存したファイルから必要箇所を分割して読む。終了コード、ログ保存、表示の成否を区別し、失敗記録・独立分析とユーザー指定の停止条件に従う。詳細は [AGENTS.md](../AGENTS.md) の作業の基本方針を参照する。
- 未確認: 3回目で実際に切り詰めた出力層は特定できていない。

## F-012: 存在を確認していないパスを検索する

- 適用場面: 別の作業ディレクトリや依存クレートのファイルを検索するとき。
- 確認済み: 誤った相対パスや存在未確認のパス指定、Windows で未展開の `*` を含む引数により少なくとも3回、対象ファイルを検索できなかった。
- 予防策: 作業ディレクトリと実在する対象を先に確認し、実際のディレクトリを指定する。
- 未確認: 過去 run の類似事例との累計、初回の元出力。

## F-016: 検索条件が期待した結果を返さない

- 適用場面: コードや Issue の検索、テスト名による実行対象の選択。
- 確認済み: 想定した宣言の誤り、PowerShell のワイルドカード特殊文字、完全テスト名の不足などにより、少なくとも6回、期待する対象を取得・実行できなかった。直近の引用符を含む検索の原因は未確定。
- 予防策: 対象と演算子の文字列解釈を確認し、必要な場合は完全な名前を指定する。結果が空でも対象の不存在とは断定せず、テストの終了コードに加えて実行件数も確認する。
- 未確認: 初回事象の元コマンドと終了コード、過去 run との総件数。

## F-022: テストの待機に上限がない

- 適用場面: ローカル通信、補助スレッドや子プロセスを伴うテスト。
- 確認済み: 少なくとも5回、受入れ・通信・終了確認の待機に期限がない箇所がレビューで見つかった。直近は移動テストの２箇所で受入れに期限がなく、１箇所では EOF 後も読取りを続け得た。実際のハングは観測していない。
- 予防策: 受入れ・読み書き・終了確認の各経路に期限を設け、終了が確認できない場合は試験データを保護して報告する。
- 未確認: 過去 run の類似記録との総件数と、期限超過時の全経路の動作。直近の移動テストでは接続なし・送信なし・EOF を個別に確認した。

## F-017: ウィンドウ終了操作の座標を取得・使用できない

- 適用場面: 装飾のない Windows ウィンドウをアクセシビリティ上の閉じるボタンから終了する操作。
- 確認済み: 3回は座標情報を取得できず、1回は座標がウィンドウ範囲外として拒否された。
- 予防策: 座標や要素の有効性を画面状態で確認し、失敗時は対象を再取得して別の終了方法を検討する。
- 未確認: 各事象の内部原因と共通原因。直近は Alt+F4 送信後、対象ウィンドウの消失を確認した。

## F-014: パッチの検証段階で変更が拒否される

- 適用場面: `apply_patch` による既存ファイルの変更。
- 確認済み: 同一パスの操作重複と、指定文脈が見つからない事象が計4回発生した。直近は既に変更された行を誤ってパッチ文脈に指定した。
- 予防策: 適用直前の実ファイルを読み、アンカーの内容・順序と一意性を確認する。同一パスは単一の更新操作にし、独立した変更は小さく分ける。
- 未確認: 過去2件の当時の独立した前後ハッシュと、検証ツール内部の探索方式。

## F-015: 自動ドラッグ後にウィンドウ位置が変わらない

- 適用場面: Windows ウィジェットのドラッグ移動を自動操作で検証する場合。
- 確認済み: 過去の debug 版2回と release 版2回で、自動操作後に位置不変を観測した。ほか1回は重複の可能性があり、累計は4〜5回。過去の対象 release 版はユーザーの手動操作で移動・サイズ変更ができた。
- 予防策: 自動操作の結果だけで製品の移動不能と断定せず、対象版、入力到達、IPC、OS の状態を分けて記録する。同じ指示の処理中の失敗回数と、履歴集計を分けて扱う。
- 未確認: 自動操作で位置が変わらなかった原因と、過去の1件が別発生かどうか。

## F-034: 自動ドラッグ後もウィンドウのサイズが変わらない

- 適用場面: Windows ウィジェットのサイズ変更を自動操作で確認する場合。
- 確認済み: 異なるリリース版で累計３回、右下の自動ドラッグ前後の取得画像が 902 × 522 のままだった。うち最新２回は同じ処理で発生し、停止条件に従い調査を中断した。
- 予防策: 入力が対象領域に到達したか、IPC と OS のサイズ変化を別の証拠で確認する。自動操作だけを根拠にアプリの不具合と断定せず、１処理内の停止条件と累計を分けて扱う。
- 未確認: 入力経路、OS の実寸と自動操作の制約、およびアプリの実際のサイズ変更可否。

## F-032: GitHub CLI の jq 式の引用が変わる

- 適用場面: Windows PowerShell から gh の jq 式に文字列を渡す場合。
- 確認済み: 引用符を含む jq 式が期待どおりに渡らず、解析エラーになる事象が累計３回発生した。各段階での正確な引数変換は未確認。
- 予防策: シェルをまたぐ式内の引用を避け、必要な項目を JSON のままメモリー内で安全に絞り、対象・件数・出力を限定する。失敗時は元の処理の終了結果と欠落を区別し、ユーザー指定の停止条件を優先する。
