# 失敗記録

このファイルは、失敗記録の手順と索引です。索引に記載した分冊を合わせて発生記録の正本とします。担当者はユーザーの個別の指示を待たずに記録します。これはアシスタントへの作業手順であり、プロセスの強制終了やアシスタントを介さない操作を自動検知する仕組みではありません。

## 記録と集計

1. 期待した操作・検証が失敗したと確認できたら、原因が未確定でも記録する。原因や対策は確認された事実と推測を分け、未確認を明記する。意図的に失敗させるテストの期待どおりの結果は含めない。
2. 既存項目を確認し、同じ失敗として再発防止策を共有できるものは同じ ID にまとめる。関連が不明なら別項目にし、根拠なく統合しない。別々の発生を各1回とし、同一事象の再表示、報告、原因調査や意図的な再現は二重計上しない。回数は期間や連続性を問わない累計とする。
3. 発生ごとに日時、作業、事実、原因の確認状況、対処・再発防止策、回数を記す。回数は発生記録の件数と一致させる。資格情報、非公開 Issue の内容、不要な個人情報は記録しない。
4. 同じ ID が累計3回以上になったら、発生記録を残したまま [繰り返しの失敗から得た教訓](recurring-lessons.md) に ID、適用場面、確認済みの事実、具体的な予防策と未確認事項を転記する。既存の ID は重複作成せず、新たな知見があれば更新する。転記先の内容と件数を読み戻す。さらに下記の複数エージェントによる検討を行う。
5. 更新前に索引、該当する分冊と教訓の最新版を確認し、他者の変更を保持する。並行更新や別 worktree の記録がある場合は失敗 ID と各発生を照合し、統合できなければ件数を確定せず報告する。書き込みや読戻しに失敗したら成功扱いにせず、作業終了時に未記録・未転記の内容と理由を報告する。

## 累計3回以上の対応検討

1. 3回目以降の各発生時に、担当者は事実・原因の確度・既存ルール・未確認事項を整理し、別エージェントに独立した原因分析と予防策を依頼する。初めて閾値を超えた場合だけでなく、既に3回以上の ID の再発も対象とする。依頼と結果は [複数担当の手順](agent-workflow.md) に従い共有 run の確定ファイルに記録する。
2. 担当者は独立分析と既存の予防策を照合し、具体的で実行可能な対策を決定する。対策を `recurring-lessons.md` の該当 ID に反映し、全作業に適用すべき指示は適切なルールにも反映する。既存ルールで足りると判断した場合は根拠と適用方法を記録する。対象版、参加者、判断、変更先、確認結果、未確認事項を記録し、変更箇所を読み戻す。
3. エージェントの利用や独立分析ができない、または反映を確認できない場合は完了扱いにしない。失敗記録と暫定的な予防策は可能な範囲で残し、未完了の理由、再開条件と次の作業を報告する。ユーザーや上位指示による停止条件・権限を優先し、検討のために禁止された操作を再実行しない。

## 分冊と索引

- 発生記録は `failure-log-001.md` から連番で保存する。索引には各分冊へのリンクと、記録対象の期間・ID の範囲を記載し、新しい分冊の作成時と対象範囲の変更時に更新する。既存の分冊を上書きしない。
- UTF-8 のファイルサイズが 100 KiB（102,400 バイト）を超える追記になる場合は、追記前に次の番号の分冊を作り、そこに記録する。１件の記録を分断しない。１件だけで上限を超える場合はその１件を新分冊に記録し、索引に例外を明記する。
- 同じ ID の発生が複数の分冊にまたがる場合も、全分冊の該当 ID を照合して累計する。既存の累計表示は記載時点の値として扱い、最新の累計を新しい発生記録に記す。過去の記録を移動・削除して件数を合わせない。既存の累計に欠落や暫定値がある場合は確定したと扱わず、引き続き明記する。
- 読み取り時は索引と必要な ID・範囲を使い、全分冊の本文を一括表示しない。サイズや長い行によって表示上限を超える場合はさらに分割する。
