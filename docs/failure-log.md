# 失敗記録

このファイルは、作業中に認識した失敗の記録と累計の正本です。担当者はユーザーの個別の指示を待たずに記録します。これはアシスタントへの作業手順であり、プロセスの強制終了やアシスタントを介さない操作を自動検知する仕組みではありません。

## 記録と集計

1. 期待した操作・検証が失敗したと確認できたら、原因が未確定でも記録する。原因や対策は確認された事実と推測を分け、未確認を明記する。意図的に失敗させるテストの期待どおりの結果は含めない。
2. 既存項目を確認し、同じ失敗として再発防止策を共有できるものは同じ ID にまとめる。関連が不明なら別項目にし、根拠なく統合しない。別々の発生を各1回とし、同一事象の再表示、報告、原因調査や意図的な再現は二重計上しない。回数は期間や連続性を問わない累計とする。
3. 発生ごとに日時、作業、事実、原因の確認状況、対処・再発防止策、回数を記す。回数は発生記録の件数と一致させる。資格情報、非公開 Issue の内容、不要な個人情報は記録しない。
4. 同じ ID が累計3回以上になったら、発生記録を残したまま [繰り返しの失敗から得た教訓](recurring-lessons.md) に ID、適用場面、確認済みの事実、具体的な予防策と未確認事項を転記する。既存の ID は重複作成せず、新たな知見があれば更新する。転記先の内容と件数を読み戻す。
5. 更新前に最新の両ファイルを確認し、他者の変更を保持する。並行更新や別 worktree の記録がある場合は失敗 ID と各発生を照合し、統合できなければ件数を確定せず報告する。書き込みや読戻しに失敗したら成功扱いにせず、作業終了時に未記録・未転記の内容と理由を報告する。

## 発生記録

### F-001: 広すぎるファイル列挙で出力が切り詰められた

- 累計: 1回
- 発生 1: 2026-11-20、終了時記録の運用調査。対象の除外条件が不十分なファイル列挙で出力が切り詰められた。原因は列挙範囲の広さと出力上限。範囲を絞った検索をやり直した。今後は検索対象と除外条件を先に限定する。

### F-002: GitHub の認証確認が失敗した

- 累計: 1回
- 発生 1: 2026-11-20、完了後の整理確認で `gh repo view` が HTTP 401 を返した。原因は未確認。GitHub の状態を未確認として扱い、認証設定やリモートを変更しなかった。再確認時は対象環境の認証方式に従い、資格情報を出さずに接続を確認する。

### F-003: 他の worktree の状態を取得できなかった

- 累計: 1回
- 発生 1: 2026-11-20、完了後の整理確認で他の worktree の `git status` が所有者相違の `dubious ownership` により失敗した。所有・利用状況は未確認として保持した。再確認時は実際の所有者と利用状況を調べ、Git の安全設定を勝手に変更しない。

### F-004: Git インデックスへの書き込みが拒否された

- 累計: 1回
- 発生 1: 2026-11-20、プッシュ準備中に `git apply --cached` が `.git/index.lock` の作成を権限不足で拒否された。対象環境では `.git` が通常の書き込み許可範囲外だった。許可された方法で再試行し、失敗したインデックス操作を成功扱いにしない。

### F-005: 部分ステージで既存変更を除外できなかった

- 累計: 1回
- 発生 1: 2026-11-20、プッシュ準備中に部分ステージした差分に既存の変更が含まれた。除外処理が想定どおり一致しなかった原因の詳細は未確認。コミット前の差分確認で発見し、対象行をインデックスから除外した。部分ステージ後は必ずステージ済み差分と残る作業差分を確認する。
