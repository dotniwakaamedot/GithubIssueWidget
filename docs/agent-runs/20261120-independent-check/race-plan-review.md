# 競合テスト計画の独立レビュー

- 担当: `/root/snapshot_review`。計画の作者とは別。対象 `race-plan.md` SHA256 `7D3DE7D1DA1C2C61B8C0C39761CFCF20745190AC8499FE09ECC30E0A540D2F7A`。
- 判定: **要修正**。実ストアと別プロセスを使う方向は前回 B-01 の不足に対応するが、実行前に同期の成立、安全な隔離とクリーンアップ、正常系を検証可能な形に具体化する必要がある。対象計画の実行許可や製品の完成承認ではない。

## Blocking 指摘

### B-01: ロック解放後の順序を保証する同期方法が未定義

- 根拠: 計画は「HTTP ヘッダーを送り本文を止め、ロック解放後に別プロセスが設定を更新」とするが、ヘッダーの送信完了は受信側の `get_api_response` 完了や `_rate_guard` の解放を示さない。現在の `process_lock_at` は待機ではなく `try_lock_exclusive` であるため、早く開始した子プロセスはロック取得に失敗し得る。
- 影響: テストがタイミング依存になり、意図した競合を検証せず失敗する、あるいは設定変更の成立を証明できない。
- 対応案: 受信側がヘッダーを処理して `get_api_response` から戻り、ロックを解放した後のテスト専用通知を設ける。子プロセスが実ロックを取得、対象の設定と合成資格情報を更新し、ロック解放まで完了したことを独立した応答で確認してから本文を送る。各段階と順序を記録し、通知・更新・解放の不明や期限切れは失敗として終了する。ネットワーク待機中の他プロセスへの干渉を避け、単なる待ち時間による推測や失敗したロック操作の反復をしない。

### B-02: 合成資格情報と設定の隔離・失敗時の後始末が具体化不足

- 根拠: 製品の `entry` は固定サービス名 `github-task-widget` を使い、ユーザー資格情報と同じ Windows Credential Manager を参照する。計画は UUID と専用 `APPDATA` を指定するが、生成 ID が未使用であること、親・子プロセスが同じ正しい隔離領域を使うこと、失敗・強制終了時の残存記録や削除対象の検証方法を定めていない。
- 影響: 誤った環境変数、既存領域の利用、部分作成後の失敗などで、既存設定を参照・更新したり合成資格情報を残したりする危険を十分に排除できない。
- 対応案: 書込み可能な明示的な絶対パス配下に未使用の専用領域を新規作成し、解決済みパス、実体、所有・用途、想定の空状態を確認する。親・子へ専用 `APPDATA` をプロセス単位で設定し、共有ランナーの環境は変えず、変更が必要なら必ず復元する。事前に固定サービス名と新規 UUID の組合せが未登録であることを確認し、生成した合成 ID と作成段階だけを機密を含まない証跡に残す。両方の合成資格情報について成功・エラー・panic 時の削除処理を用意し、削除後の不存在を確認する。プロセス強制終了などで後始末が保証できない場合は、残存可能性と対象を明記して保留し、他の資格情報を対象にしない。子プロセスとサーバーも対象 PID・所有を固定し、期限切れ時の扱いを定める。

### B-03: 正常系と実行対象版の完了条件が不足

- 根拠: 計画は変更時にエラーになることのみを挙げる。取得後の共通関数が常にエラーを返す実装でも、その否定系だけでは通り得る。また、変更対象ファイル・基準 SHA、テストの正確な単独起動方法・証跡と実施前後の状態照合が計画にない。
- 影響: 通常のボード取得の回帰を見逃すほか、何をどの版で検証したかを独立に再確認できない。
- 対応案: 接続・資格情報が変わらない対照ケースで期待した Issue が返ること、変更ケースで返らないこと、秘密や Issue タイトルがエラーへ混入しないことを検証する。テストの実行範囲を Windows 専用 ignored テストの単独起動に固定し、並列実行を避ける。対象ソースと設定・lock の変更範囲、着手前後 SHA、起動時の絶対作業場所、コマンド、終了コード、停止条件、ログ保存先と対象版の関連を計画に記す。

## 確認できた点と残る限界

- 実 GitHub・実トークンを使わず、ローカル HTTP と合成データを使う方針は適切。実 Credential Manager を使うため、隔離と記録は上記 B-02 を満たす必要がある。
- 計画は別プロセス、期限、予期せぬ失敗時の別担当調査、停止回数を今回の指示と処理内で数える方針を明記している。ただし具体的な同期・終了手順は B-01 / B-02 に残る。
- 実 WebView と GitHub を結合しない制約を計画が明示している。テスト成功後も、UI での旧応答抑止・実認証・外部サービスに対する統合確認を完了と扱わない。
