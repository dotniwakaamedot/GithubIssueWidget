## 実装・実行レビュー時の確認事項（non-blocking）

1. HTTP の待機先はループバックに固定し、テストクライアントでは proxy やリダイレクトで外部へ転送されない設定を確認する。本文を待たせる応答のヘッダー・長さは有効な HTTP とし、秘密を含まない合成値だけを使用する。
2. 親テストがユーザーの実設定ディレクトリを触らず、製品の `settings_path`・共有ロック・リカバリー関数を呼ぶ子と孫は同じ新規隔離領域を使うことを確認する。パスの解決結果と一意な ID を実行前に照合し、既存エントリや予期しないパスを削除しない。子・孫を含む補助プロセスは表示やフォーカスを奪わない方法とする。
3. 限定的なテストフックが通常の製品ビルドには入らず、該当する取得に一度だけ反応することを確認する。サーバー・子孫の期限、終了確認、panic と異常終了後の残存報告を実装と証拠で照合する。ログに合成トークン値を残さない。
4. 実行結果の対象 SHA と変更後の製品・テスト差分を再レビューする。計画承認を実装版の承認として流用しない。
