# 状態確認時の失敗分析

## Git の状態取得

- **確認された事実:** `git -c core.excludesFile=NUL status --short` は `fatal: cannot use NUL as an exclude file` を返し、状態一覧を返さなかった。作業ツリーの状態はこの結果から判断できない。
- **原因の確実性:** Git が指定された `NUL` を除外ファイルとして使用できないことはエラーから分かる。一方、その指定が拒否された内部の具体的な理由や、OS・Git の各設定の影響は提示情報だけでは特定できない。
- **再発防止:** 除外設定を一時的に変える必要がある場合は、対象環境で実在・読取り可能と確認した通常のファイルを指定する。除外設定の変更は結果に現れる未追跡ファイルを変え得るため、使用した設定と確認範囲を明記し、取得に失敗した結果を成功扱いにしない。

## 失敗記録の出力切り詰め

- **確認された事実:** 末尾8行の取得結果は約469 tokens だったのに対し、出力上限は450 tokens で、一部が切り詰められた。欠落部分は未確認である。
- **原因の確実性:** 出力量が指定された上限を超過したことは確かである。各行の長さや、出力経路のどの層で切り詰められたかは提示情報から特定できない。
- **再発防止:** 行数だけで出力量を推定せず、必要な項目を絞り、長い行の表示を制限するか分割して取得する。必要に応じて出力をファイルに保存し、内側と外側の上限を確認する。

元の操作の再試行、追加のファイル読み取り、GUI・資格情報の操作は行っていない。
