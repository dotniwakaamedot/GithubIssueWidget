# IPC 書き込み失敗診断の静的レビュー

判定: 指定版の診断変更は静的確認の範囲で承認する。失敗済み fixture と資格情報の独立確認が終わるまで、テスト再実行は承認しない。

- 対象版をレビュー前後に照合: `main.rs` SHA256 `91E544E355597D8A90EE0D26E9A5E12DD7433AB7F2191CE9F787B318AE8F2835`、`Cargo.toml` `81A24FB82B063F7E89307808E22A554404544F181A1086A8F220EE28D614C2CE`、`Cargo.lock` `E81559E3D646FE6B25220590E64B5F3CAB3ACAAECDB120392E7EB8285E6B5AD9`。確認担当 `/root/snapshot_review` は実装担当と別。
- 書き込み失敗時は keyring エラーを列挙型の固定カテゴリへ変換し、panic はカテゴリを表示する。各 variant の内部値やエラーオブジェクトを展開しない。未知の variant は固定の `other`。診断コードから秘密や合成値を出力する経路は見当たらない。
- 書き込み前に cleanup guard が作られ、失敗時の unwind では試験専用 service と ID に対して取得値が期待した合成値に一致する場合だけ削除する。不在は受入れ、照会・削除の失敗や値の不一致は削除を確認できない旨を警告する。静的確認であり、実際の cleanup 成否は未確認。
- 子起動前の fixture と試験用 service の隔離、子終了確認後の cleanup、dev-only feature、試験用 service の純粋な検証と拒否テストは対象コード上維持されている。旧版実体との全差分はここでは検証していない。
- 前回失敗の直接原因は未特定。今回の修正は固定カテゴリを次回観測するためのもので、原因を証明しない。前回の fixture、対象資格情報の現在の状態と利用終了、ログオン環境の確認は別途必要。実 WebView・実 GitHub・製品資格情報での動作も未検証。
- テスト実行、GUI、資格情報・外部サービス操作、製品コード変更を行っていない。今回認識した失敗はない。
