## 指摘

### B-01: 実際の一覧呼出し中に資格情報が変わるケースの検証が不足

- 根拠: `fetched_board_is_not_returned_after_credential_change` はローカル HTTP からの `fetch_pages` を完了させた後、テスト自身が変更済み `Settings` を `validate_board_snapshot` へ直接渡す。`list_issues` の実呼出し、通信中の別操作による設定更新・削除、設定の再読込み、資格情報ストアへの照合は実行していない。UI の `ignores an old repository response after switching connection` は旧 Promise を遅延解決するが、`invoke` はモックであり Rust 側と接続されていない。
- 影響: 個々の分岐と呼出し位置は確認できるものの、通信中の実際の並行変更で古い Issue が UI へ表示されないことを、この対象版のテスト結果だけでは証明できない。親 Issue #1 は接続先切替中の応答競合の検証を完了条件に含む。
- 修正案: 合成資格情報と隔離設定を使い、ローカルの制御可能な HTTP 応答を停止・再開させる統合テストで、取得中に別操作から接続先または資格情報を変更・削除し、実際の `list_issues` 相当の入口とフロントエンドで旧 Issue が表示されないことを確認する。外部サービスや実資格情報は不要。テスト用の依存注入が必要なら製品の制御対象を限定する。

### N-01: 対象版の実行時表示には版の隔たりがある

- 根拠: 診断記録の手動移動・サイズ変更は実行ファイル SHA256 `C228...5A90`、小さい画面の観測は `C5F9...B79B`。今回確認した Rust テストログと後続リリースビルドログはさらに後の変更を含む。対象 CSS 自体は SHA 一致だが、後続実行ファイルの実画面をこの担当は確認していない。
- 影響・対応: 表示に関する既存証拠を対象 CSS と過去実行ファイルに限定して扱う。最終リリース版で初期サイズ、最小サイズ、移動・リサイズ、最前面と外部リンクを再確認する。

### N-02: 最終照合後の別プロセス変更は別の競合として残る

- 根拠: `list_issues` は取得終了後、ロック下で設定・資格情報を再読込みして `validate_board_snapshot` を実行する。関数終了後の応答配送と別プロセスの次の設定変更が完全に原子的である証拠はない。ローカル画面の設定切替では UI の `requestVersion` による旧応答抑止がある。
- 影響・対応: 今回の照合が防ぐ範囲を「最終照合までに観測された変更」として扱い、複数ウィンドウでの後続変更・既表示のデータの扱いを検証する。実際の不具合としては未再現。
