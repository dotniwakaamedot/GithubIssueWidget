# 合成資格情報の読み取り確認スクリプト：最終静的レビュー

## 判定

**対象ハッシュの静的レビューを承認。** 前回指摘したログの実体固定は、指定ハッシュと照合した同一バイト列から対象を抽出する形に修正されている。実行の成否や OS の資格情報の状態を承認・証明するものではない。

対象スクリプト SHA256 `645D3C30EDE6AB838BD246DD717BB38BF37BB2E67435A283AB0A66F5663A40E0`、対象ログ SHA256 `6B63EE432EF646B5BFAB1E065C57C1D7989B76324128302E5648E1E90958BEA6` は、レビュー開始時と終了時にそれぞれ依頼値と一致した。

## 確認結果

- スクリプトはログを一度バイト列として取得し、その SHA256 が指定値と一致しなければ停止する。一致した同じバイト列をデコードし、行全体に一致する候補が1件の場合だけ対象を組み立てる。指定ハッシュのログについて、資格情報を出力しない文字列検査で該当行が1件あることを確認した。
- 出力は存在・同セッション内の不在・不明の3分類に限り、識別子・値・Win32 エラー数値を出力しない。スクリプトには `CredWrite` / `CredDelete` の呼び出しはない。
- `keyring` 3.6.3 の Windows 実装にある `username.service` 方式と組立てが整合し、`CredReadW` の Generic 種別・flags と、成功時の `CredFree` を静的に確認した。前回の切り出し境界と余分なエラー出力の指摘も修正されたままである。

## 限界

- `CredReadW` は資格情報のデータを呼出しプロセス内のメモリへ渡し得る。コードは値を参照・表示せず解放するが、メモリ消去までは確認していない。
- 不在の結果は**実行するユーザーとログオンセッション内**の照会結果に限る。依頼では失敗した試験の実行ユーザー・ログオンセッションを独立には特定できていないため、同じ領域を見ていることや他のセッションを含む不存在は証明できない。
- 承認対象は上記スクリプトとログのハッシュに限定する。レビュー後のスクリプト差替えは排除できないため、親担当は実行直前に対象版と実行環境を確認する。ログはスクリプト自身が読み取ったバイト列のハッシュを検証する。

## 実施範囲

静的なコード検査、対象実体の存在・SHA256、識別子を出力しないマーカー件数検査を実施した。依頼に従い、対象スクリプトの実行、資格情報の照会・変更・削除、GUI 操作、値や ID の出力は行っていない。
