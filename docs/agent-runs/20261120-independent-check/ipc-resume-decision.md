# 隔離 IPC テスト再開条件の確認

判定: 現時点の記録だけでは別環境での再実行を判断できない。前回の実行セッションが独立記録されておらず、今回の資格情報不存在は照会したユーザー・セッションに限定される。前回の残留物を全領域で否定できないが、それ自体が独立した新規試験領域の利用を不可能と証明するものでもない。

別環境で 1 回実施する判断には、少なくとも次の確認が必要である。

1. 実行予定のユーザー、ログオンセッション、実行権限、資格情報ストアの利用可能範囲とプロセスの隔離を明確に記録し、当該環境で合成資格情報を作成・照会・削除する操作が認可済みであること。前回セッションとの同一性は推測せず、不明のまま記録する。
2. 実行直前に source・設定・実行ファイルの対象版とレビュー承認の対応を照合し、前回の純粋検証と通常テストが新しい対象版で成功した証拠を確認する。対象や機能を変更した場合はその版を再レビューする。
3. 新規生成した試験専用 service・ID と root を使い、作成前の不存在確認、root の正規化・所有・他プロセスによる使用状況、製品設定との分離、試験前後の対象範囲を実行計画で固定する。前回の root と資格情報の状態は未確定として保持し、操作対象に混ぜない。
4. 子プロセスの期限・終了確認、cleanup が合成値に一致した対象だけを扱うこと、失敗時に対象を保持して調査できる記録、ログに秘密や合成値を出さないことを確認する。書き込み時は固定カテゴリを記録し、根本原因が判明したと扱わない。
5. 失敗時の停止条件を今回の指示と処理の間で数え、同じ失敗の再発時はユーザーの指示と記録された手順に従う。前回の失敗を安全な再試行の根拠としない。

根拠: `ipc-resume-execution.md` は前回 root と marker、設定不存在、および現ユーザー・現セッションでの資格情報不存在を記録する。`inspect-ipc-credential-review-03.md` は照会がそのユーザー・ログオンセッションに限定されると明記する。`ipc-write-failure-analysis.md` は前回書き込みの原因と cleanup の独立確認が未確定とする。`ipc-diagnostic-review.md` は診断変更の静的承認であり、再実行の承認ではない。

この判断は記録の読み取りによる条件整理であり、上記条件が成立したこと、異なる環境の安全性、資格情報の全領域の不存在やテスト成功を保証しない。環境変更、テスト、GUI、資格情報への操作は行っていない。今回認識した失敗はない。
