# 合成資格情報の読み取り確認スクリプト：独立レビュー

## 判定

**修正後の再レビューが必要。** 対象 SHA256 `ABF584EF8F190BC107AF331DD6A5A60C3380DF179725A242C740D0BDE1B8BE57` は依頼値と一致した。スクリプトは実行しておらず、資格情報への照会・変更・削除や GUI 操作も行っていない。

## 指摘

1. **出力範囲の不一致:** `CredReadW` が見つからない以外のエラーを返す場合、スクリプトは `credential_state=unknown` に加えて `win32_error` の数値を出力する。依頼は存在分類だけの出力を求めているため、数値も出すなら依頼側の許容範囲を明示するか、分類だけに変更する。
2. **対象の切り出し境界:** 固定プレフィックスと UUID 形式の組を1件に限定しているが、正規表現は行頭・行末や UUID 終端の境界を要求しない。ログ中の長い文字列の部分一致を別の対象として読み取る可能性を排除できない。ログ行の形式とフィールドの完全一致を検証し、取得後に対象を一意に確認できなければ照会を中止すること。

## 確認した事項と制約

- スクリプトは固定の一時ログを読み、候補が1件以外なら停止する。今回の読み取り専用の文字列検査では候補1件、対象候補の末尾は行境界だった。これは将来のログ変更や、その候補が該当テストの本人・同一セッションの対象であることを保証しない。候補・値・識別子は出力していない。
- `keyring` 3.6.3 の Windows 実装は Generic 資格情報のターゲット名を `username.service` と定義する。今回の試験コードは service と ID を `Entry::new` の順に渡しており、スクリプトの `identifier + '.' + service`、種別1、flags 0 と整合する。
- `CredReadW` の結果を構造体として読み出したり表示したりせず、成功時は `CredFree` している。`CredWrite`・`CredDelete` の呼び出しはない。ただし `CredReadW` は資格情報全体をプロセスメモリへ渡し得るため、「値を読み込まない」ではなく「値を参照・出力しない」という限界がある。メモリ消去は確認していない。
- `not_found_in_this_session` はその実行ユーザー・ログオンセッションでの結果に限る。ユーザーやログオンセッションが異なる場合を含め、他の資格情報領域での不存在は証明しない。アクセス拒否等は unknown のままにする。
- 検査した試験コードの現行 SHA256 は `91E544E355597D8A90EE0D26E9A5E12DD7433AB7F2191CE9F787B318AE8F2835` で、既存失敗分析に記載された対象版とは異なる。実行前に失敗ログ・試験対象版・実行ユーザー・ログオンセッションを対応付ける必要がある。スクリプトとログは検査時点の実体であり、後の変更は排除できない。
