# 実ストア・共有ロックを使う競合テスト案

## 目的と方法

- `list_issues` のページ取得後に実行するロック・設定読戻し・資格情報照合を共通関数にし、製品側とテスト側で同じ関数を呼ぶ。
- Windows 専用の ignored テストを、専用 `APPDATA` と固有 UUID の合成資格情報で単独実行する。テスト用の環境変数と空の設定領域を確認できない場合は安全に中止し、実トークンを使わない。
- ローカル HTTP サーバーがヘッダーを送り本文を止める。製品と同じ共有レート制御・ファイルロックを通す取得処理がヘッダーを受けてロックを解放した後、別テストプロセスが実際の設定ロックを取得して設定を別の合成資格情報へ更新し、その後に本文を送る。
- 製品と同じ取得後関数が実際のファイル・Windows Credential Manager を読み、古い Issue を返さず安全なエラーにすることを確認する。設定、資格情報、Issue 内容は合成値だけを使用し、生成した資格情報はテスト終了時に削除する。

## 制約と確認

- 実 GitHub・実トークン・ユーザーの既存設定は使用しない。外部への書き込みは Windows Credential Manager の UUID 付き合成エントリに限定する。
- 別プロセスと共有ロックの成立、同一プロセス内の UI モックとは異なることを記録する。実 WebView と GitHub の組み合わせはなお未検証。
- サーバー・子プロセス・待機には上限を設け、失敗や応答不明時のクリーンアップを確認する。user の停止条件は一度の指示と処理の間で数え、予期せぬ失敗時は別担当に原因調査を依頼する。
- 実装前に独立レビューを受け、実装後は対象 SHA を指定して再レビューする。

## 独立レビュー後の具体化（改訂）

- 基準: `widget/src-tauri/src/main.rs` SHA256 `E2B09800F1DECBCFE45C189945F73C861173B4CA617DFAB94BD03AD56784F04D`、`Cargo.toml` `82A440BA35FA24E315B3A458721021A43CC7CB2EEE39D1968B0C9B52BADA0540`、`Cargo.lock` `E81559E3D646FE6B25220590E64B5F3CAB3ACAAECDB120392E7EB8285E6B5AD9`。変更予定は `main.rs` のみ。
- 基準更新の理由: 親が前回の基準 `00A8A973753DBD1A90E9337C5724247ABC6A10CDA871D87881DC27FE3B2BFCEF` から、取得後の製品処理を `finish_board` に分離し、Windows のテスト時だけ使うヘッダー後の一度限りの同期フックを追加した。両変更は親が所有し、この更新時点で実体 SHA を再確認済み。計画の旧 SHA のまま実装を継続せず、新しい基準に対する独立レビューを受ける。
- `cfg(test)` の一度限りの同期フックを、`get_api_response` がヘッダーを受けてファイルロックを解放した後、本文の読み取り前に置く。フックは通知と子プロセスの完了待ちを行い、推測の待機やロック取得失敗の反復をしない。テスト対象は単独の ignored テストに限定し、他の通常テストとは別プロセスとする。
- 親テストが OS 一時領域内に新規の一意ディレクトリと UUID 2件を用意し、固定サービス名と各 ID の組合せが未登録であることを確認する。子プロセスの `APPDATA` のみを一時領域に設定し、親プロセスやユーザーの環境は変更しない。子は環境変数・実在する絶対パス・一時領域内を照合し、空の設定領域でのみ実行する。孫プロセスも同じ `APPDATA` を継承し、実際のファイルロックを一度取得して設定を更新、ロック解放と終了成功を親へ通知する。子プロセスは非表示で起動する。
- 合成資格情報の ID と作成段階はログに記録するが、値は出力しない。親は正常・エラー・panic の場合に自分が生成した ID だけを削除し、不存在を確認する。強制終了等で親の終了処理が動かない場合の残存可能性と ID をログに残す。子とサーバーに期限を設け、終了を確認できないものは推測で消さず報告する。
- 対照として、設定が変わらなければ合成 Issue が返ることを先に確認し、変更時は Issue が返らず合成トークン・タイトルを含まないエラーを確認する。対象ハッシュ・コマンド・終了コード・前後の設定／資格情報状態を記録する。
- 起動は `widget/src-tauri` で `cargo test --locked -- --exact tests::windows_inflight_guard --ignored --test-threads=1 --nocapture` を単独実行し、ログは専用の一時ファイルへ保存する。同期フックと子テストは `cfg(test)` に限定し、実 UI・実 GitHub との結合を証明したとは扱わない。
- 実装時の具体化: 既存環境を変更しない親テストがローカル HTTP／制御ソケットと専用ディレクトリを所有し、`APPDATA` を隔離した子を起動する。ヘッダー受信後の子のテスト専用通知を受けた親が実際の設定ファイル用ロックを取得し、合成資格情報を指す設定へ更新してロックを解放してから本文送信を許す。これにより製品取得側から見て設定更新は別プロセスで起こり、追加の孫プロセスは不要。親は生成した値と一致する資格情報だけを削除し、不一致は削除せず報告する。
- 上記の親による更新方式は、それ以前の孫プロセス方式を置き換える。親の `APPDATA` は変更しない。親は専用ディレクトリの実体が OS 一時領域内にあることを確認し、その絶対パスから `github-task-widget/settings.lock` と `settings.json` を導出して `process_lock_at` と `write_settings_at` を使用する。子側でも製品の `settings_path()` と親が渡した絶対設定パスが一致することを確認してから実行する。製品の `save_connection` 全体はこの更新で通らない。
- 空領域・UUID 未登録確認、合成資格情報の作成、初期設定の書込み、設定変更なしの正常系、変更系の順に行う。一度限りのフックは正常系の完了後、変更系にだけ設定する。合成 ID と作成段階は各書込み前に標準出力へ記録し flush するが、値は出力しない。
