# 出力対策の独立レビュー

判定: 方向性は妥当。出力量の見積もりや欠落部分を未確認とする規則は維持し、取得前の作業を出力規模と機密性に応じて簡略化すると停止や手戻りを減らせる。ユーザー指定の停止条件と失敗時の独立分析・記録は変更しない。

対象 SHA256: `AGENTS.md` `34B6574E60017574EAF338832BD268B87E72AA31779DA8B83726D9F7CF4F31E4`、`docs/recurring-lessons.md` `512C0CEC09E36855F1756EA698DC4E44DDE50B9D44A65B903168575570DDCAAB`。レビュー開始・終了時に一致。担当 `/root/snapshot_review` は変更担当と別。

## 提案

1. **高: 小さな出力は軽量な見積もりで進める。** 現在の「取得前に対象・件数・行の長さを見積もり」「両方を確認」は、数行の既知の結果でも別々の確認操作が必要と読める。既知の短い出力は対象選択と上限設定を同じ操作で済ませ、大きさや行長が不明な場合だけ件数・最大行長等を事前に調べる、と明記する。例: 3ファイルの SHA は上限付き一括取得、未知の長文検索は狭い範囲から取得する。
2. **高: 出力予算を合計で扱う。** 今回のレビューでも、各ファイルの行数だけを指定して2ファイルをまとめた結果、合計 2596 tokens が外側 2500 tokens を超え、1回切り詰められた。件数 × 行長、複数操作の合計、エラー・見出し・検索コンテキスト、文字とトークンの換算不確実性を含め余裕を持たせる。範囲ごとに別呼び出し、または必要なフィールドだけ出し、内外の上限に余裕を設ける。切り詰め自体は失敗として所定の扱いをする。
3. **高: 出力取得失敗と元処理の成否を分ける。** 実行結果の表示切り詰めは、別に取得した終了コードや安全に保存された完全ログの存在まで失敗と決めつける理由にはならない。一方、欠落した内容は未確認で、結果の成功を推測しない。読取の再取得、ビルド等の再実行、外部副作用の再試行を区別し、独立分析とユーザーの停止条件を満たす場合のみ、欠落部分を狭く読み取る。非依存作業は権限と停止条件の範囲で継続できる旨を追加すると不必要な全停止を避けられる。
4. **中: ログの機密確認を実行可能な基準にする。** 「機密情報を含まないことを確認」は、テスト前に出力全体を知れない場合には実施不能になり得る。認証情報・非公開データを含む可能性があれば、保存しない・安全な項目のみ抽出する・アクセス制限された許可済み保存先を使う等を、適用される指示に沿って選ぶ。保存先、保持期間、アクセス権、既存ファイルの上書き、削除認可を確認する。ログへの退避を秘密出力の許可と扱わない。
5. **中: 個々の結果の完全性を明示する。** 件数や上限を絞った検索は、上限到達やページの残りを確認し、完全列挙が必要なら続きの位置を保存する。長い行は対象を安全に分割し、検索の前後を重複表示しない。検索結果が0件でも検索範囲・権限・エラーを検査し、不完全な検索を不存在の証明にしない。
6. **中: 対策を一か所に集約する。** `AGENTS.md` と F-001 にほぼ同じ手順があり、片方のみ更新されると乖離し得る。必須方針と停止条件は `AGENTS.md`、失敗の具体例・詳細は F-001 と役割を分け、相互参照する。停止の同種判定は、同一事象の再表示を重複しない累計集計と、一度の指示と処理の間の件数を分離して記録する。
