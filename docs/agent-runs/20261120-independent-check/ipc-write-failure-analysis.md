# 隔離 IPC テストの書き込み失敗：独立分析

## 対象と確認できた事実

- 対象 `widget/src-tauri/src/main.rs` の SHA256 は依頼値 `B293846185F74D23F8F6371B5F4081A5E330DCC74CEB7F3E6AB3E246036E2201` と一致した。対象ログの存在も確認した。
- ログには資格情報の書き込み直前の段階と書き込み失敗が記録され、テストは失敗した。OS のエラー種別・コードは出力されていない。
- 実装では、書き込み前に新規 ID について `NoEntry` を確認し、資格情報のクリーンアップ用ガードを用意してから書き込む。設定ファイルの作成と子プロセス起動は書き込み成功後のため、今回の失敗箇所から先には通常進まない。
- ガードは破棄時に対象が存在しない場合を成功扱いとし、既知の合成値と一致する場合は削除して再読込みを確認する。一致しない値・取得失敗・削除失敗の場合はクリーンアップ未確認の警告を出す設計である。ログに当該警告は見当たらないが、独立した不存在確認にはならない。
- テストの再実行、資格情報ストアへの操作、GUI 操作は行っていない。fixture や資格情報の現在の状態も確認していない。

## 原因の候補と未確認事項

書き込み時のエラー値が捨てられているため、失敗の直接原因は特定できない。実行環境の資格情報マネージャーへのアクセス制限、Windows のログオン・資格情報セッションの状態、OS 側の一時的な問題などが候補であり、現時点でどれかを確定できない。以前の別テストが成功していても、同じ実行環境・同じ資格情報の書き込み条件を証明しない。

panic 時にガードが走っても、取得・削除やログ捕捉が想定どおり行われたかをログの警告不在だけでは保証できない。テスト用ディレクトリが作成されている可能性があるが、現在の実体・所有・他プロセスの利用状況は未確認である。

## 安全な確認と再実行の条件

1. ログと対象コードを保全し、記録されたテスト用 root、識別子とマーカーを必要な範囲で照合する。識別子や合成値を出力・転載しない。対象が一意に特定できなければ保留する。
2. fixture は一時ディレクトリ内の正規化済みパスであること、リンク・所有・使用状況とマーカーを読み取り専用で確認する。元の設定や別プロセスの領域に触れない。確認と削除は別操作であり、削除の認可が不明なら保留する。
3. 資格情報は、別途認可された調査で記録済みの対象サービス・ID のみを照会し、存在または不在と照会結果の分類だけを出す。値を表示・ログ保存しない。対象が一致しない、照会が拒否される、他プロセスの利用が不明な場合は不明のまま保護する。削除はこの分析では行わず、対象と値の一致・所有・利用終了・個別認可を確認してから別判断とする。
4. 再実行前に別担当の原因調査結果、対象版・fixture の状態と作業中プロセス、実行ユーザー／ログオンセッション、許可された書込み範囲を固定する。書き込み失敗時はシークレットや識別子を出さず、エラー種別と安全な OS エラーコードだけを観測できるよう設計・レビューする。未確定のまま同じ操作を繰り返さない。

## 調査中の出力逸脱

分析中、検索結果に依頼で出力禁止とされた固定の合成テスト値が含まれた。実トークンではないが、依頼に反する出力であり親担当に通知済み。その後の結果は該当値を含めず記録した。
