# 合成資格情報の安全境界モデルと故障試験

## 結果

実 OS 資格情報を操作する経路を持たない Python のモデルと合成試験を作成し、9 試験が成功した。これは安全条件のシミュレーションであり、Windows の排他性・ACL・親子プロセス監督や実 Credential Manager の安全な操作を証明しない。実 OS 書込みは実装していないため有効化できない。実アプリの PAT 保存・更新・削除も未検証。

## 試験範囲と結果

専用ディレクトリから `python -B -m unittest -v test_harness` を実行、Python 3.11.15、終了コード 0、9 tests、1.343 秒、OK。プロセスは直接起動した Python 1 件で、コードに子プロセス起動はない。出力は試験名と結果のみで秘密を含まず、ツール出力に記録された。試験用の一時ディレクトリは `TemporaryDirectory` が管理し、OS 資格情報ストア・アプリ・ネットワークは使用しない。

1. 正常系は合成記憶内の保存、読取、更新、読取、削除、欠落確認と journal の readback を実施し、記録に合成値を出さないことを確認。
2. journal の作成・flush・読戻しの合成失敗、既存 journal 衝突はバックエンドへのアクセスを禁止。保存後の journal 失敗は以降の変更を禁止。
3. ACL、排他、認可、登録、監督者生存、実行体一致の各フラグの失敗、および対象不一致は後続操作を禁止。これらは真偽値のモデルであり OS の実装ではない。
4. 不存在照会の失敗・同名衝突、保存・更新・削除の前後の失敗、読取不明、削除後読取失敗、各操作前後の停止を注入。以後の再送・自動 cleanup を明示的に拒否。
5. 保存後に監督者停止・実行体不一致・登録喪失を模擬し、後続操作を拒否。既存 target と異なる名前の cleanup も拒否。

## 未完了・制約

journal は試験ディレクトリ内のファイルを初回排他作成し flush・fsync・読戻しするが、後続段階は上書きであり、電源断下の原子性、ディレクトリ flush、耐久性、ACL は検証していない。OS レベルの排他・プロセス登録・ハンドル監督・親停止時の子の停止・PID 再利用防止は実装していない。試験内 `stop` は同期的な故障注入で実プロセス kill ではない。合成値のログ非出力は journal と試験出力の範囲に限る。実 OS への書込みに使うには別依頼、実装・独立レビュー、隔離の証明、障害時の復旧検証が必要であり、このモデルを認可根拠にしない。

操作中、初回 `Get-FileHash | Select-Object Path,Hash` は PowerShell の表幅でハッシュが省略された（1回）。終了コード 0 だがその表示は完全な根拠として使わず、同じ読取を `Format-List` で取得し上記値を確認した。共有失敗記録は所有外のため進行管理に引き継ぐ。その他に認識した失敗はない。独立レビューは未実施。
