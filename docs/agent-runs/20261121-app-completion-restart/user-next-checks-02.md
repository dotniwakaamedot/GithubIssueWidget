# 残る実操作の優先順 02

`issue-11-state-03.md` の公開 API 読取りでは #11 は closed・`status:done`。履歴から5方向のラベル変更は観測できるが Done→In Progress は観測できず、非 status ラベルもない。全6方向の実環境証拠を得る最小の追加操作は、本人が #11 を **Done → In Progress → Done** と移動し、最終 closed を確認すること。途中エラー・不明時は止めて再送せず実状態を読戻す。既存 Issue やラベルの変更は行わない。

続いて最新版 EXE で、フォームの文字選択・＋開閉（送信しない）と、保存済み接続の再起動後復元を各1回行えば、今回の CSS 変更の局所的回帰と利用に直結する保存済み接続の一部を確認できる。本人が PAT をチャット・画像に出す必要はない。元の値を上書き・削除しない。実ユーザー PAT の登録・更新・削除そのもの、非 status ラベル保持、実通信障害や競合の完全防止の証拠にはならない。

`windows-credential-test-request-01.md` は本人を待たず専用の合成 service で OS 資格情報 API の保存・更新・削除を条件付きで検証する依頼。既存資格情報を操作せず、安全な識別・ cleanup を確認できなければ実行しない。
