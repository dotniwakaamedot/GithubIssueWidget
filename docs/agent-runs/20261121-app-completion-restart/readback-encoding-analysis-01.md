# 日本語読戻し比較の文字化け再発：独立分析

担当 `/root/readback_encoding_analysis`。依頼 `readback-encoding-analysis-request-01.md`。対象は `selection-fix-result-01.md` と `tasks/03/creation-test-review-01.md` に記録された各1件。元操作は再実行していない。

## 結論

両担当は、PowerShell から Python の標準入力に渡した日本語の比較文字列が文字化けし、読戻し照合が AssertionError で終了したと報告している。両者は Unicode エスケープでの比較は成功したと報告する。これは対象ファイルの破損を意味せず、原因の正確な変換境界や元のコマンド・入出力バイトは本分析では未確認である。

## 根拠と区別

- `selection-fix-result-01.md` SHA256 `A074FF9649AC53377EEEAD34C4CDAA784E5E0E18D0B0DCDFC5AD36BBE9C9FC88` は初回照合失敗の終了1、比較文字列の文字化けと代替比較の終了0を記録する。
- `tasks/03/creation-test-review-01.md` SHA256 `1531DBE93BE092C2ED21FAE2937B6462F407789D3326FFA3976ACD099351DEC5` は同種の初回 assertion の終了1と Unicode エスケープ比較成功を記録する。具体的な比較コードと元バイトは記録に含まれず、各担当の観測に基づく。
- 対象2ファイルを直接 bytes として読み、strict UTF-8 で復号し、ASCII コマンド中の Unicode エスケープで構成した代表語 `文字化け` が各1件、置換文字 U+FFFD が各0件と確認した。SHA は上記に一致、Python 終了0。これらは代表語と厳格復号の確認であり、全文章が元の意図に一致する証明ではない。ASCII `?` を含んでも元の文面との比較なしに置換の有無は判定できない。
- 既存 `encoding-analysis-02.md` SHA256 `FDEA6FB6FBFB64BC6E8D88FCC4B36BC7599CD264334A4F9B234149EB4C305277` は、別件のファイル実体が `?` に置換された事象と表示時の文字化けを区別し、正確な変換境界は未特定とする。今回の assertion 失敗と実体置換を同一の結果と扱わない。
- `docs/recurring-lessons.md` の F-057 は入出力の文字コード明示と短い日本語の往復確認、F-062 は Python へのパイプ両端の符号化明示と短い日本語往復、UTF-8 による実データ読戻しを求める。今回の各記録は先行する往復確認・両端明示の実施を示さず、適用不足が原因候補である。ただし実際の設定や変換箇所を特定した証拠ではない。

## 対応と効果確認

日本語比較リテラルを PowerShell の外部プロセス標準入力へ直接混在させず、ASCII の `\u` エスケープで Python 内に構築するか、UTF-8 を明示した信頼できるファイルを bytes で読み strict 復号する。比較対象は対象ファイルの実体から取得し、代表語だけでなく必要な原文との一致を確認する。パイプを使う必要がある場合は両端のエンコーディングを設定し、短い既知の日本語で送信から受信までの往復を本処理前に確認する。これらは予防策であり、今回の代替比較の成功から全環境での再発防止を証明しない。

両担当の実際の失敗入力バイトと Python が受け取ったバイト、PowerShell のバージョン・出力エンコーディング、元コマンドは未確認。旧事象の直接の変換原因や、対策の実環境における効果は未確定。共有失敗記録への追記・累計と重複照合は管理担当に引き継ぐ。
