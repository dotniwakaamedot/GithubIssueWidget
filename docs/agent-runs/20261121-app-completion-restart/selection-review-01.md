# 文字選択抑制の独立レビュー 01 — 対象版を承認

- 担当 `/root/selection_review` は作者 `/root/selection_fix` と別。対象 CSS、作者結果、Tauri 設定の期待・実測 SHA256 は依頼に一致。それぞれ `FFE871A15BDA8FAD0BB5E28E1717C93D2878ABB1F5885F730EC624DEC983FCFE`、`A074FF9649AC53377EEEAD34C4CDAA784E5E0E18D0B0DCDFC5AD36BBE9C9FC88`、`0132FCC92345F5D60DE84FD25197FCE853044AD63DAE28757AB4592CC72B991E`。承認はこの対象版に限る。blocking はない。
- 対象差分は CSS へのコメントと `.board-column h2, .issue-card { user-select: none; }` の追加のみ。`git diff --check` は終了 0、追加3行・削除0行。作者結果は削除対象なしと明記し、差分にも削除ファイルはない。未追跡の作者結果は実体と SHA を確認した。Tauri 設定も依頼版に一致した。
- JSX では `.board-column` 内の `h2` に列名・件数・新規作成ボタンがあり、`.issue-card` はドラッグおよびリンクを扱う button。設定フォームと作成ダイアログはそれらの子孫ではない。CSS はフォームや画面全体を対象としない。静的確認上はクリック・フォーカス・ドラッグのコードを変えないが、実際の入力・選択・キーボード操作の回帰は未検証。カードと見出しの文字は選択・コピーできなくなる。
- 利用者は Issue 自体は一件だけ移動し、複数の文字が一緒に動くと報告した。変更は文字選択の抑制という合理的な候補だが、元の選択範囲や既存選択状態を含めた WebView2 上の動作は本レビューで再現していない。画像・静的コードだけでは効果を確定しない。

## 未確認と次の確認

別担当による新規ビルドと、実 Windows UI でのドラッグ像、移動される Issue の番号、＋ボタン、リンク・キーボード、フォーム入力と文字選択を確認する。ビルド・実 UI・外部書込みは本担当では行っていない。CSS の適切性についての承認であり、問題解決や Issue 全体の完了承認ではない。

## 作業と失敗

作業場所 `D:/Projects/GithubIssueWidget`。`Get-FileHash`、限定 `git diff --check`・`git diff --numstat`・`git status`・`git diff` と JSX の部分読取りを実施。上記 Git コマンドは終了 0、Git の個人 ignore 読取りは権限拒否の警告を表示した。初回の Python による JSX 出力は Windows の cp932 で UnicodeEncodeError、終了 1、出力は途中までだった。欠落部分はその出力を証拠とせず、対象を ASCII エスケープして限定再取得し終了 0。この文字コード失敗 1 件の失敗記録と教訓反映を管理へ依頼する。その他、認識した失敗なし。製品・設定・他者成果を変更せず、削除対象なし。
