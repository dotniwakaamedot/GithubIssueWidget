## 原因と対応

実行者の説明に基づく直接の原因候補は、ファイル数・行長または一致件数の未確認により、合計出力量が内側上限を超えたこと。外側上限やファイル内容自体が欠落したことを原因とする証拠はない。`--max-columns` は一行の表示を制限するが、複数行全体の長さを保証しない。根本的な人的・環境要因の特定や再発防止効果は未検証。

`docs/instructions/work.md`（SHA256 `07404711E59932204F9C7D4A96B27F9D2E4E4D3ECE182BCEB73A4505F83FA5A6`）は対象・件数・行長と内外上限を事前に見積もり、不明なら範囲を絞るか分割し、切り詰め時の欠落を未確認として扱うよう既に要求する。`docs/recurring-lessons.md`（読取時 SHA256 `FA35AAF7018607AB9574D6BD5A6623DC7FA33C9686432F87E123D65785BF194C`）の F-001 も原則１文書ずつ、対象限定と上限見積りを記載する。既存の指示の適用が必要で、今回の事実だけから新しい一般ルールの必要性は確認できない。

次回は、まず対象ごとの件数と最大行長を出力せず集計して小さい結果だけ確認し、必要な対象を分割して、包装を含め内外の出力上限に余裕を設ける。必要なら安全な完全ログに保存し、終了コードと範囲を別に確認する。共有記録担当 `/root/remaining_audit` が F-001 の今回２操作を重複照合し、暫定集計・この分析・欠落と効果の未確認を記録する。失われた出力の確認のみを目的とする外部書込みの再実行はしない。
