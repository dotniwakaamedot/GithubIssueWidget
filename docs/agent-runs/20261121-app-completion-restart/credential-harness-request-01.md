# 合成資格情報試験の監督経路・故障試験依頼

- 担当予定 `/root/credential_harness`。親 `/root` が ID を照合して起動。作業場所 `D:/Projects/GithubIssueWidget`、共有 run `D:/Projects/GithubIssueWidget/docs/agent-runs/20261121-app-completion-restart/`。基準 HEAD `4961b25bec53a93439acdf5230de77f959908af0`。
- 根拠 `credential-safety-design-01.md` SHA256 `76057E5039F7BA536545B4F0C0247B000B32C24B7C9CD5D6CF51CBEFF789E6ED` と独立 `credential-safety-review-01.md`。Issue #3 の要求を参照し、OS の合成 service 試験と実アプリ・実 PAT のライフサイクルを区別する。
- 目的: 最小限の専用検証経路を `credential-harness-01/` に作成し、**実 OS 資格情報書込みを無効としたモックだけ**で安全境界・故障時の挙動を確認する。合成 service の事前予約・耐久記録・読戻し、合成試験 ID と完全一致対象、既存・不明・失敗時の書込み禁止、保存・更新・削除・後確認の状態遷移、秘密非出力、停止後・不明時の再送／cleanup 禁止を扱う。不要に複雑な仕組みや本番コード変更は避ける。
- 前段階の識別・ACL・排他・起動認可・子実行体監督と親停止時のふるまいの根拠を定め、予約／flush／読戻し／不存在確認／衝突／アクセス拒否／書込み直前・直後／応答不明／削除／後読取／監督者停止／実行体識別不一致を合成障害で検証。OS レベルの隔離や異常停止時の無条件終了保証を主張しない。条件付き作成不能時の専用 Windows ユーザー隔離、現在の環境での成立可否は未確認として扱い、証明できなければ実書込みを禁止する。
- 実 Credential Manager、ユーザーの PAT・設定、実アプリ、GitHub は一切操作しない。実 OS 書込みの入口を作る場合は既定無効とし、後続レビュー承認と隔離・許可等の条件を満たす別依頼なしに有効化しない。条件が安全に設計・実装できなければ未実装の理由を報告する。
- 所有 `credential-harness-01/` と新規 `credential-harness-result-01.md` のみ。他担当の成果・製品・既存ログを変更せず、既存実行中プロセスを停止しない。入力・実行方法・子孫・出力範囲・終了コードと残留確認を先に明確にし、模擬データのみで検証する。結果に変更対象・SHA・ケース別実行結果・残存リスク・実 OS と実アプリの未検証を記録。UTF-8 実データ読戻しと一時ファイルから確定後パスのみ通知。出力を絞り同種失敗2回は停止・報告。独立レビューは別担当に依頼する。
