# 実アプリ資格情報の実機確認案 01

## 結論

専用 Windows ユーザーの未使用プロファイルと、対象リポジトリへアクセスできる本人管理の異なるテスト用 PAT ２個が用意できる場合に限り、現行アプリで初回保存・再起動・更新・削除を段階的に確認できる。**現時点でその環境の存在や分離は確認されておらず、この手順は未実施である。** 現在使用中のユーザーの既存資格情報を退避・上書き・削除する手順ではない。専用環境を確保できなければ保留する。

## 対象と根拠

- 担当 `/root/manual_credential_procedure`、作業場所 `D:/Projects/GithubIssueWidget`、branch `main`、HEAD `4961b25bec53a93439acdf5230de77f959908af0`。HEAD は未コミット・未追跡を識別しない。依頼 `manual-credential-procedure-request-01.md` SHA256 `2F2FDEF9F38447A159873F61C057BE07EDC2C1A524311942901D4B5DC0FB56CB`。
- 対象 `widget/src-tauri/src/main.rs` SHA256 `AEFF1E65AD93EFA04773CEBBB9736A6BDC5B9938DB9FAF937DD88B3D9CBFE86F`、`README.md` `552827810A83303D430C143626E84ED4FAD5C94693A9CBBB3163071930778112`、ローカル EXE `widget/release-20261121-selection/github-issue-widget.exe` `0D8AB47088B7A19233EF0D7D08CF033B681B20CA0E729FEAF73EAB74DCC98F55`。各実体を読取り・ハッシュ確認した。別 Windows ユーザーから EXE とその前提環境へアクセスできるかは未確認。
- Issue #3 を GitHub コネクタで番号指定取得。接続成功後の保存、空欄時の保存済み値利用、Windows Credential Manager の初回登録・変更・削除・再起動後取得、フロントエンドへの保存済み PAT 非返却、失敗時の保護または明示を要求する。
- `main.rs` の `SERVICE` は `github-task-widget`、設定は `%APPDATA%/github-task-widget/settings.json`。`save_connection` は GitHub リポジトリ GET の成功後に保存し、入力ありなら新 UUID を発行、復旧記録・新資格情報・設定更新・未参照世代削除の順で処理する。`delete_token` は現行 ID の資格情報を削除し、設定の ID 自体は残す。`connection_info` は起動時に復旧処理、設定・資格情報読取を実行する。既存プロファイルでの起動も読取りだけとは限らない。
- ローカル依存 `keyring 3.6.3/src/windows.rs` SHA256 `BCA6EEC1115989C04607A0E303B8B44702B656E469C885DEB93E8A0607E8E42F` は Windows Generic credential を使用し、通常 `user.service` を target 名とする説明を持つ。現行呼出しでは ID と service から `<credential_id>.github-task-widget` となる設計だが、実 Windows 表示・アクセス制御・別ユーザープロファイルの隔離は本調査で確認していない。
- `user-observation-09.md` SHA256 `83D7461C97B278354C3480361738D8AD6841DAC873B7E709E1F11CFD3037A896` は既存接続での再起動報告を記録するが、一覧取得・初回登録・更新・削除の証拠とは区別する。隔離 mock 接続は `windows-ipc-adapter-connect-result-01.md` SHA256 `0C757C8C11682C954253DFBB2F276BCE28E0D3750327B7D00642FAB50116BB23` が未実施と記録する。

## 実施前の条件

1. 本人が専用の Windows ユーザーにサインインし、普段のユーザーと異なる `%APPDATA%` と Credential Manager が使われること、他者や他プロセスが当該テストプロファイルを使用しないことを確認する。単に `APPDATA` を変更して同じユーザーで起動するだけでは Credential Manager の分離を証明しない。専用アカウントの作成・切替や隔離の成否は本担当未確認。成立しなければ開始しない。
2. 専用プロファイル内の `%APPDATA%/github-task-widget/settings.json` と復旧記録が既存でないこと、Credential Manager の一般資格情報に当該アプリの既存エントリがないことを本人が確認する。値を表示・コピー・送信しない。既存や判別不能の場合は削除・上書きせず停止する。アプリ起動時の復旧処理に先立って確認する。
3. 対象の公開 `dotniwakaamedot/GithubIssueWidget` に本人が使用する異なる２つの有効な専用 Fine-grained PAT A/B を用意する。双方に対象リポジトリの `Metadata: Read` と `Issues: Read and write` を付与し、本人のみが値を直接入力できる状態にする。GET の成功は Issue 書込み権限の証明ではない。秘密は画面共有・画像・チャット・Issue・ログに出さない。１つしかない場合は更新による異なる資格情報への切替を未検証とする。
4. アプリを当該ユーザーで１プロセスだけ起動し、対象 EXE のパスとハッシュを本人または管理が確認。専用プロファイルでの権限・WebView2・ネットワーク、画面表示を確認し、不明やエラーなら書込み前に停止する。テスト中、他ウィンドウ・別操作で同じ専用プロファイルを変更しない。本人が接続先と画面を確認し、他の Issue や PAT 設定を変更しない。

## 手順と期待する観察

1. **初回登録:** 接続設定で対象 owner/repo と PAT A を本人が直接入力し「接続を確認して保存」。成功後ボードが開き、設定を再表示するとトークン欄が空で保存済み値を使用する旨となることを確認。Windows 資格情報マネージャーは値を開示せず、一般資格情報に対象 ID に対応するエントリがあることを本人だけが確認する。`settings.json` の `credential_id` と表示名の照合は本人の端末内だけで行い、内容や値は送らない。API エラーや保存成否不明時は再入力・再送をせず停止し、状態と一般的なエラー種別だけ報告する。
2. **再起動・空欄利用:** アプリを閉じて同じ専用 Windows ユーザーで再起動。トークンを入力せず保存済み状態と対象の一覧取得を確認する。必要なら設定画面で空欄のまま「接続を確認して保存」を１回行い、接続できることを確認。失敗時は停止。これは実画面での再読取の証拠であり、すべての IPC やログの非露出の証明ではない。
3. **更新:** 本人が設定画面で PAT B を直接入力して保存する。成功後に再起動し、空欄で接続できることを確認。端末内で新 `credential_id` が初回と異なり、該当する新エントリが存在し、初回エントリが除かれたかを値を開かず確認する。復旧記録や古いエントリが残る、または状態が不明なら追加の資格情報操作・手動削除をせず停止する。
4. **削除:** 対象が専用プロファイルのテスト接続であると再確認し、アプリの「保存済みトークンを削除」を１回押す。設定欄が未保存表示となり、対象 ID の一般資格情報が存在しないことを本人が確認。アプリを閉じて同じ専用ユーザーで再起動し、トークン再入力なしで未保存状態が継続することを確認する。`settings.json` は残り得るため、その存在を削除失敗と扱わない。手動で他の資格情報や設定を消さない。
5. **終了:** 専用テストの成功・失敗・未実施、各段階の一般的な表示、元プロファイルに触れていないことだけを報告する。トークン・非公開 Issue・Credential Manager の値・画面全体は共有しない。専用 PAT A/B の失効は本人の判断・既存認可に従う別操作とし、この手順で自動実行しない。

## 停止・限界

- 不明な操作の再送、資格情報の手動削除、設定・復旧ファイルの編集をしない。接続失敗・権限不足・保存中断・Credential Manager エラー・想定外のエントリ・実行環境の分離不明時は停止し、秘密を含まない状態とエラー種別を伝える。後続の復旧は現状を確認してから管理が判断する。
- 実施されても、実 WebView の全 IPC 応答、すべてのログ・ディスク上の秘密非露出、保存途中の実障害、別プロセス競合、他環境の振る舞いを網羅しない。故障系は安全な合成試験・コード照合と区別する。実際に専用環境が用意できるか、同環境での Credential Manager 表示と target 名、期待する旧資格情報の削除、初回・更新・削除・再起動は未確認。結果は独立レビューが必要。
