# ドラッグ調査中の検索失敗の独立分析

- 担当 `/root/assignment_failure`。`drag-investigation-01.md` と作者の `questions/drag-search-evidence-01.md` を照合した。元操作の再実行はしていない。
- 結論: 最初は Windows PowerShell が展開しなかったパスを `rg` に渡し、一部対象を検索できなかった。次は `docs` 全体を列挙してアクセス拒否と出力切り詰めが発生した。どちらも結果は網羅的な証拠にならず、既存の対象確認・出力量見積りを適用する必要がある。

## 事実と分析

1. `rg -n -m 4 'F-015|F-034' docs/failure-log*.md docs/recurring-lessons.md` は、未展開の wildcard パスについて Windows のパス構文エラーを出し、終了コード1。後者の資料では２見出しが表示された。92 tokens、上限500で切り詰めはなかった。対象ファイルの個別の存在確認は行っていなかった。F-012 の対象未確認と関連するが、存在しないファイルと断定せず、パターンの渡し方の失敗として記録する。
2. `rg --files docs -g 'failure-log*.md'` は `docs` 配下の GUI 観測ディレクトリ等でアクセス拒否となり終了コード1。内側出力は元544 tokensに対し上限400で切り詰め、完全ログなし。外側は他結果を含む既定上限に余裕があったと担当は報告する。事前のアクセス可否・出力量・行長の見積りは不十分。欠落内容、拒否の根本原因、全結果は未確認。F-001 の出力切り詰めに該当し、アクセス拒否は別の観測として記録する。
3. 担当は対象設定が不適切だったことを共通点として、同種２回と認識して当該検索を停止した。後に既知の正確な２ファイルを対象に必要箇所を確認したが、失われた出力の復元や全件確認と扱っていない。変更・外部書込みはない。
