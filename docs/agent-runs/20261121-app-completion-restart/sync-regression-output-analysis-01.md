## 確認された事実と限界

2. 同じ報告によれば、Issue #4 の公開 REST 読取りは HTTP 403、終了コード1であり、例外全文を抑制せず出力上限200を指定したため、エラー表示が切り詰められた。完全な元エラーは保存されておらず欠落範囲は未確認。403 とレート制限は担当者の分類であり、応答ヘッダーや制限回復時刻を本分析では独立検証していない。空結果・対象不存在・認証済み経路の失敗とは扱わない。
3. 別種の失敗として `Set-Content -NoClobber` が当該 Windows PowerShell でパラメーター未対応となり終了1、runner は未生成だったと報告されている。その後 .NET `FileMode.CreateNew` で新規作成しハッシュ確認したという報告がある。元のエラー全文と上書きの全期間の独立証拠は本分析では未確認。
4. `sync-regression-test-result-01.md` は別の隔離試験について6件成功・35件スキップとログ・終了状態を記録し、上記3件を明示する。この分析は試験や生成物の独立レビューではなく、表示欠落の復元・関連検索の網羅完了を主張しない。担当者に詳細を照会したが、本記録確定時点では回答を受領していない。

## 原因候補と再発防止

事象1は表表示による長い値の省略、事象2はエラーも含めた出力量が表示上限を超えたことが直接の原因候補。異なる境界であり、元ファイル自体の破損や外側上限超過を示す証拠はない。事象3は利用環境のコマンド定義と指定パラメーターの不一致が担当者報告に基づく原因候補。いずれも元出力の全容がないため、根本要因を確定しない。

`docs/instructions/work.md` は既に対象・件数・行長と内外上限の見積り、失敗時の安全な種別・HTTP 状態・終了コードの区別、切り詰め欠落を未確認と扱うことを要求する。ハッシュは対象と件数を絞ってプロパティの完全値を1行ずつ取得し、表示幅に左右される表を証拠にしない。エラーは秘密や本文を出さず種別・HTTP 状態・終了コードを抽出し、予想外の長さに備え包装も含め内外上限に余裕を持たせる。長い出力が必要なら安全な完全ログを先に確保する。コマンドのパラメーターは実環境で確認し、排他新規作成が必要なら実装の対応 API を確認して既存物の上書きを避ける。元の外部操作は出力確認だけのために再実行しない。対策の一般的な再発防止効果は未検証。
