# REST 403 再発の独立調査

## 結論

匿名 REST の 403 は2回発生したが、対象は同じではない。1回目はレート制限超過と表示された。2回目は HTTP 403 のみを記録しており、同じレート制限が原因かは未確認である。いずれも残量・回復時刻を示すヘッダーは取得されておらず、正確な回復時刻は特定できない。GitHub コネクタでは別の経路で Issue 本体の読取りが成功しており、REST イベント履歴は未取得のままとする。

## 確認した事実

- 担当 `/root/rest_403_analysis`。作業場所 `D:/Projects/GithubIssueWidget`。依頼 `rest-403-analysis-request-01.md` と対象 `issue-11-sync-state-01.md`・`issue-11-sync-state-02.md` の実体を確認し、両 SHA256 はそれぞれ依頼指定の `4EFB9C8039D3256291970953E75EAC2C712DFD73214CAE077A52D94C79D77F62`、`A32F09527BA15A74363362937BF63D7D9F7CD84B24C4582005E2FF79E19C894F` に一致した。
- 1回目は匿名の #11 本体 GET、2026-11-21 06:41 UTC 頃、Python 終了1。担当者回答 `rest-403-answer-01.md`（SHA256 `CBD1F9F70628DEB2F3037E61844053DC6B0D0C64F466048D4BEAC1FD483C1D1C`）は例外表示に `HTTP Error 403: rate limit exceeded` が含まれたと記録する。応答ヘッダーは取得せず、専用ログは保存されなかった。これは一次・二次いずれの制限かの確定根拠ではない。
- 2回目は匿名の #11 events 一覧 GET、同日 06:48 UTC 頃、Python 終了1。HTTP 403 のみを表示し、ヘッダー・本文を取得せず、専用ログも保存されなかった。`issue-11-sync-state-02.md` は先行の 403 rate limit に言及するが、2回目の種類の断定ではない。担当者は2回目のレート制限を推測、原因未確認と回答した。正確な発生秒はいずれも未保存。
- 失敗後の GitHub コネクタ `fetch_issue` は本体を番号指定で読み取れた。2回目の観測は #11 が closed・`status:done` とした。これは匿名 REST events の復旧、履歴ページ終端、表示同期を証明しない。コネクタの成功はアプリ用 PAT の権限を証明しない。
- 1回目のトレースバックとコネクタの不要な公開 Issue 本文表示について、担当者の記録は秘密の認識なしとする。出力の最小化が不十分だった。2回目は例外本文を表示せず HTTP 状態のみ。元の呼出し・出力取得は再実行せず、既存記録と担当者回答を照合した。

## 回復・代替方法

1. 403 を一律にレート制限と決めつけず、今後取得した安全な HTTP 状態・ヘッダー・エラー種別から権限拒否と区別する。トークン・認証ヘッダー・非公開本文・例外全文は出力や保存をしない。GitHub 公式は一次制限で `x-ratelimit-remaining: 0` の場合、`x-ratelimit-reset` の時刻以降まで再試行しないよう定める。二次制限は `retry-after` があればそれを優先し、残量0なら reset、どちらもなければ最低1分待ち、継続失敗なら間隔を伸ばす。今回の reset・retry-after は不明である。[GitHub REST API rate limits](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)
2. この依頼の2回失敗した REST 呼出しは再実行しない。再開が必要なら親が回復時刻と経路・要求範囲を確認し、連続再試行はしない。権限不足、ヘッダー不足、状況不明、再び 403/429 や途中ページ失敗なら停止して未完了として記録し、欠落・空結果を不存在としない。一次制限と二次制限には別の待機条件があり、HTTP 状態だけでどちらかを断定しない。
3. 現在状態のみが必要なら、利用可能な認証済み GitHub コネクタの番号指定本体読取りを必要項目だけ抽出して使用できる。Issue events を提供する専用コネクタは今回のツール名の限定調査では確認できず、本体・コメントをイベント履歴に代用しない。履歴が必要なら認可済みの適切な読取り経路と権限を確認し、ページ継続情報・終端・途中失敗を検証する。認証を迂回したり、他人のトークンを取得・表示したりしない。

## 未確認・実施状況

両 403 の実際の残量・reset・retry-after、2回目の理由、制限が回復した時刻、イベントとその全ページ、失敗後の同時変更は未確認。一般の GitHub 制限仕様を今回の観測値に置き換えない。アプリの同期や Issue 不在を推論しない。

`Get-Location`、対象の `Get-FileHash`、依頼・結果の UTF-8 読取り、担当者への質問と回答照合、GitHub 公式ドキュメントの読取りを実施した。REST・Issue・資格情報・設定・製品・既存記録は操作していない。新規成果は本ファイルのみ。削除対象なし。検証コマンドの終了コードはいずれも 0。認識した新たな失敗はない。自身の SHA256 は確定後に管理が取得する。
