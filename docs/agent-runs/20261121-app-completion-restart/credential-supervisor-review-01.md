## 実 OS 試験への blocking

1. **競合・所有権:** NoEntry→write と値確認→delete は原子的ではなく、別プロセスによる同名作成・変更を排除しない。影響は既存値の上書き・別値の削除。UUID と事前照合は衝突確率を下げるが排他の証明ではない。修正案: 条件付き API の可否または専用プロファイル等の実際に成立する排他条件を確認し、実行時点の対象・所有権と許容されるリスクを管理が判定する。不成立や不明時は書込みしない。別プロファイルだけが唯一の方法とは断定しない。
2. **実監督と復旧:** Python は実 launcher を拒否し、親停止・直接子の実終了・PID 再利用・ログの実行中上限・ACL・対象限定の残留確認は未実装または未実証。起動成功後に supervisor 自体が失敗した場合の終了・残留状態も未証明である。影響は終了不明のまま再実行・誤 cleanup を行う危険。修正案: 対象バイナリと子の識別・終了、ログ制御、異常時の停止・再開・残留照合を明示し、実行環境で実現できる部分を独立に確認する。OS 障害時の無条件保証は要求・主張しない。
3. **有効化版が未存在:** 現行は両実行経路が禁止され、Rust の live feature をビルドしただけでは試験できない。フラグ解除・launcher 接続後の版は現行承認に含まれない。修正案: 実行できる限定版の SHA と安全な停止条件を固定し、実 OS 書込み前に改めて独立レビューする。
