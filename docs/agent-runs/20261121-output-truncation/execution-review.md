## blocking 1: テストが実行されなくても成功と判定する

`run-live.py` は終了コード 0 だけで `live check completed` を出す。Rust テスト実行器は `--exact` の名前が存在しない場合にも 0 件実行・終了コード 0 になり得る。EXE の取り違えやテスト名の変更により、Issue 作成・移動が一度も実施されず検証成功と誤認する。合成の子プロセスで 0 件・中断・期待どおりの一連の出力を試し、0 件や不足時は失敗にすること。成功には固定された `created` の正の番号と、計画に指定された7つの `LIVE_STEP` の順序・件数、正常終了をすべて必要とする。結果不明時は再作成せず対象を照合する。

## blocking 2: タイムアウト時の子プロセスと待機上限の根拠が不足

`subprocess.run(..., stdout=PIPE, stderr=PIPE, timeout=...)` を `gh` と試験 EXE に使うが、プロセスツリーとパイプ保持子の終了確認、タイムアウト後のストリーム回収を含む全待機の上限について証拠が示されていない。特に Windows の子孫がパイプを継承すると、親プロセス停止後も回収が終わらない可能性がある。計画は子プロセス構成・終了とストリーム待機の上限の実行前確認を要求する。安全な合成子プロセスで正常・タイムアウト・子孫がパイプを保持する場合を確認し、必要な終了制御と上限を実装する。終了を確認できない場合は結果不明とし再実行しない。
