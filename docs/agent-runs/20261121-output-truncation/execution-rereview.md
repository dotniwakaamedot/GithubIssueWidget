判定: **要修正。実 GitHub 検証を実行しない。** 作者 `/root` と確認者 `/root/execution_review2` は別担当。本レビューは静的確認であり、対象コード・GitHub は実行していない。

## Blocking: プロセスツリー終了の確認が不足（前回 blocking 2 と同じ対象）

`job_process.py` は Job の終了要求と `communicate()` スレッドの終了を確認するが、Job 内のプロセスがすべて終了したことを照会・待機していない。パイプの EOF は、子孫がストリームを閉じて生存している場合には子孫の終了を証明しない。`TerminateJobObject` の呼出し成功も全プロセスの終了確認ではない。`test_descendant_holding_pipe_is_terminated` は `TimeoutError` と経過時間だけを検査し、子孫 PID または Job のアクティブプロセス数を確認していない。代入失敗、再開失敗、終了 API 失敗の経路でもツリー終了の確認がない。よって承認済み計画の「子プロセス構成・終了」の確認は未達。実行結果は不明として再実行しない方針はあるが、実行前の終了保証の根拠は不足する。

修正案: Job 内の残存プロセス数または個々の終了ハンドルを期限付きで確認し、確認できない場合は明示的に結果不明にする。パイプを閉じたまま生存する子孫、パイプを保持する子孫、API 失敗を合成データで試し、子孫の終了を独立に観測する。Job の breakaway 等の制約も明記する。待機上限は生成・終了要求・後処理全体に対して検討する。
