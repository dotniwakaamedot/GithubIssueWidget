## 検証の重複と過剰な停滞

- 確認できた同じ対象の実際の再試行: `handoff-gui-stop-02.md` は同一旧 EXE で空の異なる fixture を用いた GUI 起動が2回とも101と記録する。2回目は標準エラーを分類する診断手段が追加されたため、完全に同じ観測目的と断定できない。いずれも失敗であり原因未特定。旧 EXE を同じ低情報の方法で再起動しても原因解決の証拠は増えにくい。安全な診断を設計し現行版で検証し、同種失敗2回時は別担当へ調査・解決を依頼する。
- 33件の旧 UI テストと39件の今回の試験は、main/test の SHA が異なり、同期実装・回帰項目追加後の試験である。**同一版・同一目的の無意味な再実行とは確認できない**。今回の39件の記録は1回であり、成功を理由なく何度も繰り返す必要はない。
- `test-supervisor-result-01.md`〜`03.md` は監督器の未完成部品・引継ぎ・静的設計/構文検査であり、同じ製品テストを3回実行した証拠ではない。実用的なツール・合成テストに対し専用監督器の完成を一律の前提としたことで、実行前の準備が膨らんだ。対象・副作用・必要な保護を分けた代替方式を採用後に1回の Vitest が実施された。実資格情報や外部書込みの監督条件は、その影響に応じ維持する。
- 停止基準: 要件に対応する同一版・同一環境・同一目的の有効な成功証拠があり、版・失敗・環境・未解決リスクに新たな変化がなければ再実行しない。再実行が必要な場合は変更点と検証される新しい懸念を先に記録する。異なる実環境や変更後の回帰・具体的な失敗の再現は別目的として必要性を評価する。出力の切断だけを理由に外部書込みを再送しない。
