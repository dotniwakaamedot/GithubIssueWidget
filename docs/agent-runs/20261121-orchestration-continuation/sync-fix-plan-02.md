# Issue #4 同期周期の修正計画 02

- 目的: Issue #4 の「60 秒ごとに更新」と古い接続応答の遮断に沿って同期を改善する。ユーザー原文および制約は `plan-draft-02.md`、第一波 `implementation-plan-02.md` とそのレビューに従う。
- 根拠: `audit-b-sync-01.md` SHA256 `A94CCCCBEB77C8C58CCC28893404670115D47CFCF6123310A3A6925BE0AD80B9` と `sync-fix-plan-review-01.md` は、取得完了後60秒に次回予約するため開始間隔が取得時間ぶん延びる事実を確認した。Issue #4 の「60秒ごと」は基準や超過時の扱いを明記していない。開始基準と長時間時の単一実行は、この曖昧さに対する設計判断であり原文の明示ではない。
- 作業候補: `widget/src/main.tsx` SHA256 `01A7E8A6961BE2DC4F00D96F9369098321EF5137F6959650931E36ABFB357658` と `widget/src/main.test.tsx` SHA256 `6D1F45AFDBFC3BD66071C81FD7BA0025A186BD6A1CC0CE89022D06FB19B7D1E1`。同ファイル内の「完了後60秒ごとに同期」という画面説明を、通常は開始から60秒、取得が長い場合は完了後に再開する方式に整合させる。README の既存説明も照合し、変更が必要ならその所有権・SHA を確認した新版依頼に追加する。担当・作業場所・明確な変更版は別の確定依頼で指定。
- 動作方針: 開始時刻に基づく 60 秒周期。同一の有効な取得中に定期呼出しを重複せず、60秒を超過すれば完了後に期限切れを一度だけ処理し、過去の周期を一斉再生しない。失敗が速く続く場合も周期を守り無限即時再試行しない。接続変更時の旧応答遮断と新接続の待たされないこと、cleanup 時のタイマー停止と既存のクールダウン動作を保護する。遅い応答中の明示更新等の並行は要件を調査し、曖昧な仕様を拡大しない。
- 回帰条件: 偽時計で取得に10秒かかっても開始60秒後に次回開始。60秒超過中の定期重複がなく、完了時に期限切れを一度だけ開始。高速失敗の無限ループなし。旧接続から遅れて届く成功・失敗、アンマウント、エラー後の復帰を確認。画面説明が通常と長時間要求時の実際の方式を誤解なく伝えることを表示テストで確認。README も照合。既存テストの「完了後60秒」を新仕様に沿って更新し、他機能の回帰を検査する。
- 開始前ゲート: Issue #4 一次本文、監査の事実と設計の独立レビュー、先行計画に指定した関連 PR・担当停止/移管・worktree・未追跡を含む所有権照合、および対象 SHA の再確認を完了する。不明なら該当ファイルを保護し、読取り調査や別の独立作業を進める。
