# GitHub 更新優先に関する現行挙動の照合依頼

親が担当 ID を指定してから実施。ユーザーの質問に対する説明方針「競合検出 → 上書き・自動再試行しない → 再取得、部分反映可能性を通知、再取得失敗時は古い状態を最新と見せない」を一次 Issue #6 と現行 `movement.rs`・`main.tsx`・テストの固定 SHA で照合する。質問だけを新しい仕様変更の承認とみなさない。

事前 GET の `updated_at` 不一致、途中の競合・最終照合・部分書込み可能性、画面での再取得と失敗時のカード・エラーを区別。現実には初回取得と各書込みの間や最終読取り後の競合を完全には検出できない点を確認し、「すべて上書きしない」「GitHub が常に勝つ」と過大に主張しない。既存 `movement-audit-review-01.md` と、追加された UI 1件・未統合の隔離 Rust 通知修正を参照し、現製品と隔離案を混同しない。

既存テストの成功証拠・未実施を対応づけ、不足が Issue と整合する場合だけ最小修正と新規回帰の必要性を提案する。既合格の同一テストは変更や理由がない限り再実行しない。読み取りのみで実 GitHub・資格情報・製品を操作せず、根拠・対象 SHA・未確認を結果ファイルに確定。別担当による確認を経て必要な実装を割り当てる。
