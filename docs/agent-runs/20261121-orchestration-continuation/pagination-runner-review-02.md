| 観点 | 確認と限界 |
| --- | --- |
| 旧失敗と修正 | 前回は直接終了1・ログなしで原因未特定。旧実行器は cmd 内で複雑な多重引用とリダイレクトを組み立てた。新版は固定 cmd を分離し、PowerShell 側で標準出力・エラーを別々の新規ファイルに直接受けるため、診断情報を得やすい。これが旧失敗の原因だったとは未証明。 |
| 対象・保護 | `ValidateSet` で2件を固定、各コマンドは `--locked --offline`、正確な module/test 名・`--exact` を指定。専用 Cargo・target・user・temp を利用し、他の入力や未追跡を上書きしない。専用領域は現時点で存在するが入力の最新性は実行直前に照合する。 |
| 終了・ログ | 各ケース別の新規 stdout/stderr を `CreateNew` で確保し、両ストリームを並行排出する。直接 cmd の終了コードを返し、900秒後は同じプロセスを観測し続ける。終了コード0だけでは0件の可能性があるため、ログの `running 1 test`・対象ケースの成功・完了を確認する。 |
| 異常時 | パイプが子孫に保持されていれば直接 cmd の終了後もログ回収が終わらない可能性がある。観測中の同一セッションは生存確認し、不明状態を成功とせず保持。旧や無関係なプロセスを推測して停止しない。再び同じ失敗が発生した場合はユーザー指示どおり別担当が調査・解決し、同一方式を繰り返さない。 |

非 blocking: 実行者は対象版・依存・ツールと専用ログの不存在を確認し、ケースごとに1回実行する。終了・ケース数・出力の完全性を記録し、成功すれば同じ目的で再実行しない。製品・既存の未コミット変更は保持する。合成テストは実 GitHub と Windows UI の代替ではない。

`D:/Projects/GithubIssueWidget` で依頼・新旧スクリプト・前回レビューを読み、専用領域の存在と開始・終了 SHA を確認（ハッシュ取得終了0）。`git diff --no-index` の終了1は差分あり。実行器、テスト、製品変更、外部操作は未実施。実行方式が変更された場合は再確認する。
