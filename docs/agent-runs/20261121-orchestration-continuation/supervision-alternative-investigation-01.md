# 同期テストを進める別経路の独立調査

担当 `/root/existing_work_review`。以前の3担当とは別。実行・製品変更は行わず、`test-supervisor-result-01.md`〜`03.md`、`sync-test-runtime-review-01.md`、`sync-dependency-safety-independent-01.md`、`handoff-process-stop-06.md` を照合した。

## 結論

独自 Windows 監督器の完成をすべての前進の前提にする必要はない。対象を実資格情報・実 GitHub に触れない合成テストとし、専用コピーと限定環境を使用して、既存の実行ツールが提供するプロセス識別・出力・終了結果を正確に記録する経路を、管理と独立レビュー担当が具体的に審査できる。ただし現在の `sync-test-runtime-review-01.md` は B1・B2 を blocking としているため、現行承認のままでの実行は不可。承認者が新しい方式を対象版で評価し、残る不確実性を許容可能と明示して初めて開始できる。

## リスクの区別

- 旧事故は合成 Job の子の生成・残存と不明プロセスの識別が不明な事象であり、対象外のプロセスを終了しないことが必要。旧プロセスの不存在が証明できないことは、別領域の読み取りや限定試験の全般的な禁止を直ちに意味しない。ただし同一 OS・ユーザー・CPU・ディスク・ネットワークは共有し得る。
- 新しい対象は Tauri IPC、ウィンドウ、opener をモックする React の合成テスト。通常の Vitest と esbuild は worker・子プロセス、テンポラリ・キャッシュを使用し得る。既存ツールの終了コードは root の状態を示すが、それだけで未知の全子孫の終了を保証しない。GitHub 実書込みや実資格情報を扱う GUI 監督器とは失敗時の影響範囲が異なる。
- 同一アカウントの Credential Manager は環境変数を外すだけでは隔離されない。テスト本体のモックと静的証拠は意図した実 IPC が動かない根拠になるが、依存全体の通信・資格情報アクセスの不存在は証明しない。VM やネットワーク強制遮断は一つの選択肢であり、利用可能性は未確認。完全保証を求めず、対象・残余リスク・ユーザー既存設定の保護を評価する。

## 提案する具体手順

1. 実行案を新しい確定版として作る。対象 2 ファイルと package/lock・CSS・設定・Node・Vitest・esbuild の SHA を固定し、通常のファイル複写による専用プロジェクト、個別 TEMP/cache/log と必要最小限の環境を指定する。`.env*`、トークン、設定、旧 fixture を含めない。既存依存は共有書込みせず、コピーのパス・種別・量・ハッシュと実行オプションを事前に確認する。
2. 実行前にモックの適用・ネットワークや OS 資格情報に関する静的経路を確認し、残余リスクを特定する。ネットワークを止める手段が使えるなら実際に適用可能か事前に確認し、loopback と外部を区別。未確認なら未確認とし、既存方針上の判断をレビューに付す。実サービスの資格情報や実 GitHub の操作は試験対象から除く。
3. 通常のツールで固定 `node` と隔離 Vitest を直接、明示した単一 worker・有限のテスト期限で実行する案をレビューする。開始時は専用の実行セッションと実行体を記録し、終了コード・件数・ログの完全性とツールが提供する子孫終了の証拠を分ける。監督者停止・時間切れでは未知のプロセスを推測で kill せず、直接操作を許される所有ハンドルのみを使い、不明なら未完了・専用領域保持・後続の同一領域再利用禁止とする。OS 異常時の無条件停止は主張しない。
4. 既存の実行ツールが開始・時間切れ・終了時に実際に提供する保証と取得可能な証拠を先に確かめる。実行不可能な保証を目標に自作監督器を繰り返し拡張せず、足りない点ごとに「結果への影響」「対処」「未確認」をレビューする。必要なら、既存の隔離された CI / VM が既に使えるか調査し、権限と実際の証拠を確認して代替にする。新しい外部サービスへの書込みは別途認可が必要。
5. 指定回帰の実行件数と成功・失敗、終了コード、出力切り詰め、直接プロセス・把握可能な子の終了を個別に記録。未確認を成功としない。隔離版からの統合は PR・対象の変更と競合を再照合し、固定版の独立レビューと統合後の再試験を経る。

## 今すぐできる独立作業

隔離版の仕様・差分レビュー、プロセスツールの保証の読取り確認、依存と環境の限定、旧 run・PR の証拠照合、GUI 問題の安全な静的分析は並行可能。実 Windows UI、Credential Manager、GitHub 作成・移動は別途検証が必要で、このテストを通してもアプリ全体の完成とはならない。

3回の結果は未完成の部品を各担当が報告した事実で、同一の実行時故障が3回発生した証拠ではない。監督器の残課題は過去の成果に残し、再開する場合も対象版・担当・証拠を再確認する。本案の安全性・既存ツールの実際の保証・ネットワーク制御は未検証であり、独立レビューを必要とする。
