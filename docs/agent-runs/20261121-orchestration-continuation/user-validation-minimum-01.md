# ユーザー確認の最小範囲

`user-validation-boundaries-01.md` の補足。ユーザーの懸念「過剰テストの繰返し」を踏まえ、`remaining-verification-status-01.md` と `sync-post-integration-result-review-01.md` を照合した。読み取りのみで実行・変更はしていない。

## 結論

現時点でユーザーに求める操作を直ちに確定する必要はない。まず担当側が現行版の起動環境と安全な実行方法を整え、可能なテストと証拠の不足を切り分ける。実環境アクセスが成立した場合に本人しか実施できないトークンの準備・アプリへの直接入力などだけを、必要な時点で依頼する。値の共有は求めない。

## 既存証拠の再利用

- 同期変更は現行版と一致する隔離入力で Vitest 39件成功、型検査・Vite build が独立レビュー済み。通常の回帰確認として同じコマンドを繰り返す理由はない。直接終了コードは実行者記録依存、子孫終了は未確認という限界を維持し、単なる再実行で自動的に解消するとは扱わない。
- 旧 Rust の67件成功・10 ignored 等は実行記録があるが、対応する全ソース版と現在の要件網羅が不明な部分を区別する。現行版で差分がない範囲・対応する具体的試験の証拠が確認できれば再利用し、変更された関連コード、未実施のケース、結果と対象版の対応が示せない部分だけを追加検証する。
- 旧 Windows リリースでの表示・一部操作の記録は旧版の証拠として保持。現行ソースを含む実行ファイルとの対応、特に変更後の実 UI が未証明なので、現行版の起動・終了と変更に関係する振る舞いは必要。過去と同じ条件の操作を全部繰り返すのではなく、Issue #2・#7 の各項目について現行版に使える根拠の有無を対応付ける。

## ユーザーの最小負担

1. 現行 Windows 11 デスクトップを自動操作できるなら表示・移動・リサイズ・最前面・リンクは担当側が一連の操作で確認し、本人への重複操作を求めない。自動操作できない環境、または観測主体の本人が必要な箇所に限って、対象版と短い手順を添えてユーザーに確認を依頼する。
2. 実 PAT が必要で、安全な既存手段がない時だけ、所有者が権限と範囲を設定し、アプリに直接入力。値、画像、ログの共有は不要。PAT 自体の作成、保存、再起動後の利用、更新・削除は別要件なので、専用資格情報と安全な復旧を前提に、可能な操作を一連のセッションにまとめる。既存の個人用 credential を試験目的で上書き・削除しない。
3. 実 GitHub の操作は既承諾のテスト Issue 1件を共有し、作成と必要な全列遷移を同一の実行で確認。権限・対象・安全な中断と結果読戻しを事前に準備し、本人に結果の重複確認を求めない。応答不明なら再送より先に対象を照合する。
4. 権限不足・通信断・競合・1,000件超などをユーザーに手動で作らせず、既存の有効な合成試験を再利用し、不足のケースだけ安全な合成手段で追加する。Issue が実環境での確認を要求する箇所や合成では立証できない点は未確認として残す。

優先する本人操作は、対象環境にエージェントがアクセスできず代替できないもの、またはアカウント所有者の権限・秘密が必要なものだけ。将来の UI 品質について本人の好みを尋ねることは任意であり、技術的な完了条件を満たすために必須とは断定しない。ソース変更や観測対象の変更があれば、影響する範囲についてのみ再検証・再レビューする。
