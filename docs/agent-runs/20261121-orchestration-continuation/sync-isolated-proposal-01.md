# 同期修正を独立して準備する案

`sync-ownership-result-01.md` は現 checkout の対象がクリーンだが、旧 worktree の担当停止と全 open PR は未確認とする。このまま現 checkout や旧 worktree へ変更・統合しない。

作業を止めず具体的な修正を準備する候補として、workspace 内に新規かつ固有の隔離ディレクトリを用意し、対象の `main.tsx` と `main.test.tsx` だけを、出典と SHA を固定して複写する。別担当が複写物のみ編集・回帰テスト案作成し、現 checkout の製品ファイル、旧 worktree、キャッシュ、Git 状態へ書き込まない。元ファイルと同一か検証後、成果差分と SHA を独立レビューする。テスト実行は別方式承認と実行条件を満たすまで保留する。

これは製品への統合、既存作業の所有権、PR 状態、実行環境や実機の証明ではない。統合前に対象版・差分・PR・旧作業の競合と移管を確認し、必要な統合および再テスト・再レビューを行う。共有状態や他者のファイルを変更せず実行可能かを親が判断し、必要なら独立レビューを受ける。
