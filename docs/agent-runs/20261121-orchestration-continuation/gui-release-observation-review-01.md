## 実行時の条件と証拠の範囲

- 実行器は対象 EXE のハッシュと5ディレクトリの空、既存 status の不存在を確認し、排他的な launch_pending を書いてから、明示環境・DEVNULL の直接子を作成する。設定・復旧記録がないことと競合がないことが製品コードでの資格情報非到達の条件。実行前に専用実体・ACL・他担当の書込みと空を再確認し、条件不明なら開始しない。`Path.is_symlink()` は Windows の全 reparse point を確認するものではないため、直前に5領域とその親の再解析点・実体を別に確認する。
- 同じ保持ハンドルで実行パスと作成時刻を照会する。PID のみで他窓を操作せず、UI 上の HWND と直接子を独立に結び付けられない場合は閉じる操作をしない。CUA 環境と子の同一対話セッション、HWND/PID の取得方法は実測前であり、利用不能を表示成功とみなさない。
- 30秒は生存観測の期限であり、その後の `wait()` は明示的に観測を続ける設計で強制終了ではない。閉じた後も同じセッションで期限付きに観測し、終了不明なら launch_pending・領域を保護して再起動しない。直接子が終了しても WebView2 その他の子孫終了は示さない。未知の旧プロセスや同名の他アプリを推測して終了しない。
- 実行者は画面の非機密性を検討し、対象を識別できた場合のみ画面確認と通常の閉鎖を行う。監督停止、生成または識別不明、期限超過は別に記録。標準出力とエラーを破棄するため既存の 101 の原因診断にはならない。
- 専用環境は Windows Credential Manager 自体を隔離せず、WebView2 や依存の通信・共有資源の無条件な非干渉は未証明。既存 EXE を現在版と混同せず、本 EXE のビルド入力とテスト差分の扱いは preflight・ビルド結果の記録に依存する。実ウィンドウ、PAT、実 GitHub、サイズ変更、全 Issue は未確認。

GUI・実行器・テスト・外部操作・製品変更は行っていない。版や条件が変われば再評価する。
