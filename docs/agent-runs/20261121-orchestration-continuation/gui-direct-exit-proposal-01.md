# 識別不能な GUI の直接プロセス終了案

`gui-window-identification-01.md` と `gui-window-readonly-constraint-01.md` により、CUA が対象 HWND を列挙せず、画面の同一性・可視性・内容は未確認。通常の窓閉鎖を根拠なく操作せず、同じ一覧を無目的に再取得しない。観測を無期限に続けず、新しい GUI 起動や実資格情報を伴わない作業は別に進める。

現行 `observe.py` は所有する直接子のハンドルを保持しているが `stdin=DEVNULL` で外部から通常の終了指示を受け付けず、実際に見えるウィンドウも選べない。終了候補として、**対象の直接プロセスだけ**をプロセス識別のために開き、同じハンドルで `QueryFullProcessImageNameW` の正規実体パスと `GetProcessTimes` の作成 FILETIME が既存の保持ハンドル記録と一致することを直前に確認し、一致した同一ハンドルに限定して `TerminateProcess` で強制終了する。通常終了ではなく未保存データが失われ得るため、本 run が入力していない専用空設定のプロセスに限る。PID や名前のみで決めない。値が取得不可・不一致、対象終了済み、別物、権限不明なら何もしない。ウィンドウを推測操作しない。

前提として対象は本 run が空の専用設定で起動し、設定入力・実 credential・GitHub 書込みを行っていないこと、保持元セッションが現に live で対象の経路・時刻が確認できることを当事者が再確認する。直接終了の影響・データ保護を評価し、必要な停止操作の方式を別担当が確認してから親が判断する。停止後は元の `83178` を再度観測し、直接子の終了コードを受領する。終了コードと観測失敗を別に記録し、未追跡子孫の終了・GUI の表示・原因解決は主張しない。専用領域と記録を保持する。

上記は代替案であり、ここでは停止しない。可能なら CUA が正規に列挙する対象を用いた通常閉鎖を優先するが、列挙にない ID を推測指定しない。対象にユーザーが安全にアクセス・識別できる証拠がなければユーザーに他の窓を閉じるよう依頼しない。必要ならユーザーへの確認内容は具体的に対象と安全な方法を示す。
