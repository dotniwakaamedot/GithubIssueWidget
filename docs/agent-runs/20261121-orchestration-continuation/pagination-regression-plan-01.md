# Issue #4 大量ページ・失敗の回帰試験計画

- 目的: `pagination-coverage-investigation-01.md` で判明した、1,050件試験が件数のみを検査する不足を補い、複数ページの番号・分類・重複・失敗の証拠を得る。Issue #4 完成や実 GitHub の挙動を合成テストだけで主張しない。
- 対象基準 `widget/src-tauri/src/main.rs` SHA256 `61595B68317E15FDD8F2BED88B920A468D5516740E3D3124710384709C52FC24`。本ファイルは既存の未コミット変更を含むため、既存変更を作者不明のものとして保護。まず run 内の専用新規隔離コピーのみでテスト案を作成し、現行製品ファイルには直接書き込まない。開始前後に元の SHA を確認し、違えば中止する。
- 追加試験: 合成11ページ・1,050件以上の API 要素に Open、Closed、PR、複数/無ラベルとページ境界での番号重複を含め、返却 Issue の期待番号集合・件数・重複なし・各分類を具体的な独立期待値で検査。PR を API ページ枠に含める。100件以上成功した後の HTTP 500、切断または期限超過、不正 JSON の各場合、部分一覧を成功として返さずエラーになることを検査。既存429/403、短いページと next、循環のテストは保持する。既存ロジックの写経だけの期待値にしない。
- loopback テストサーバーの accept・read と試験全体は有限の待機・失敗時の結果・解放方法を定め、生成されるスレッドや mock サーバーを限定。故意の timeout を使う場合も試験時間を抑える。合成サーバーは外部 GitHub・実資格情報・実 Issue を使わず、他のプロセスや旧 GUI fixture に触れない。
- 開始前に Issue 原文、対象 SHA、元の未追跡・変更と他担当の所有を確認。隔離作業領域・書込み対象・使用する既存依存と build/output/temp・コマンド・直接プロセスの待機と終了・ログ・子孫の未確認を固定し独立レビューする。実行不能な完全保証を求めず、結果が何を証明しないか記す。コピーには既存のユーザー資産を上書きせず、失敗時は専用領域を保持。
- 作業者は追加テストと必要最小限の fixture のみ所有し、結果に新規/変更ファイルの SHA、基準との差分・コマンド・終了コード・件数・未実施を記す。別担当が計画・実装・結果を固定版で照合。必要に応じ変更を修正して再レビュー。合成テストで欠陥が明らかになった場合の製品修正・現行 main.rs への適用は所有権と基準版を再確認し、別の具体依頼・再テスト・レビューを経る。
- 実 GET・API 権限・通信障害・実 UI、同時更新中の完全なスナップショットは別に検証する。10000ページの上限の試験は高速な注入方法が合理的に作れるときだけ追加し、実 HTTP 10000件を無条件に要求しない。
