# 旧 release 起動失敗の独立調査

担当: `/root/startup_investigation`。旧 release の終了コード 101 の原因調査。実アプリ起動、資格情報操作、外部書込み、製品コード変更なし。

## 確認された事実

- `docs/agent-runs/20261121-issue-completion/handoff-gui-stop-02.md` は、空の隔離 APPDATA / LOCALAPPDATA を用いた実行で SHA256 `9157AB9B23BA0DD5406E5C85044BAF278AAD8A5066BCB15E40AD88761348073B` の EXE が2回連続で 101 終了したと記録する。2回目は stderr の固定分類で panic と WebView2 の文字列が検出されたが本文は保存されなかった。
- 読取時の `widget/release-20261121/GitHubIssueWidget.exe` は SHA256 `91EC5D237B71EFC4DDCD12244E0022019FD61A0D1610931CA0B9FE2D4A2D55B2`、`widget/release-20261121-02/GitHubIssueWidget.exe` は `D19A72750006DF5BB6CBCA4FB15F87F69BFF48A5785F5569C5B05E40C9B93F26` で、いずれも上述の失敗版と異なる。対象版の差を無視した回帰判定はできない。
- HKLM の EdgeUpdate Clients に Microsoft Edge WebView2 Runtime バージョン `158.0.4370.33` の登録を確認。これは実際のプロセスがランタイムを使用できた証拠ではない。
- 既存独立分析 `f078-resume-analysis-01.md` のとおり固定分類のみから panic の発生位置、WebView2 の成否、製品または環境の原因は特定できない。破棄された元の本文は復元できない。

## 次の作業と制約

現行版の表示・正常終了が必要であれば、実行ファイルの SHA、ユーザーセッション、空の専用設定先、子プロセスの特定と終了方法を事前に確認する。Credential Manager は環境変数だけでは隔離されないため、既存資格情報の読取り・変更の有無をコード経路で確認する。標準エラーの秘密を出力せず、根拠のある固定分類を合成試験してから適用する。未知の結果は不明として扱い、二度同じ失敗を繰り返さず別担当に解析を依頼する。元の失敗と現在版の不具合の因果関係、対策の効果は未確認。現時点で原因に基づく修正は選べず、解決済みとしない。

## 作業上の失敗

本担当の検索結果が2回切り詰められた。1回目は run 配下の依存ソースを含めた過広な検索、2回目は `main.rs` の検索結果に設定した出力上限不足。いずれも終了コード 0 は全文確認を意味せず、完全ログなし。該当検索を停止し `/root/output_failure` に独立分析を依頼、親に報告済み。失敗記録の共有ファイル更新は親が並行編集を調整する。
