# 存在未確認パスの検索失敗2件の独立調査

2026-11-21、調査 `/root/issue_survey`。当事者 `/root/plan_review` と `/root/existing_work_review` からそれぞれ `readme-search-failure-01.md` と `path-search-answer-existing-01.md` を受領し、既存の F-012 と照合した。元のツール画面は本担当から確認できず、各報告を一次観測の引継ぎとして扱う。製品・共有既存ファイルは変更しない。

## 確認事項

1. plan_review は作業場所 `D:/Projects/GithubIssueWidget` で `rg -n '60秒|60 秒' README.md widget/README.md` を実行。`widget/README.md` は OS error 2、終了コード1。存在確認を怠ったと報告した。同じ出力で `README.md:46` は得られているが、欠けた対象を調査済みとはみなせない。
2. existing_work_review は同作業場所から、推測した `docs/agent-runs/20261119-mvp-resume` に `rg -l -F 'issue-4-board-resume'` を実行。OS error 2、終了コード1。検索結果なしは資料の不存在を意味しない。後に親ディレクトリを列挙し、`docs` 内の Markdown から関連資料を限定検索して終了0、実在する旧 run の資料を読んだと報告。
3. 本担当が `Test-Path -LiteralPath` で確認した時点ではルート `README.md` と `docs/agent-runs` は存在、`widget/README.md` と推測 run ディレクトリは存在しない。存在したルート README のみに `rg -n -F '60秒' README.md` を実行し、46行を取得・終了0。これは過去の実行時点の存在を独立に証明せず、現在の根拠である。

## 原因と影響

両担当は対象の場所を推測し、検索前に作業場所と実在パスを照合しなかったと報告している。正しいパスが得られない、または複数対象の一部が検索されないため、失敗を空結果・全件調査完了と解釈すると結論を誤る。両者の事象を同じ F-012 の対策が必要な2件として扱うのが妥当。既存累計は `docs/failure-log-001.md` の発生5・6と履歴に不整合・未照合があるため、今回の正確な累計は決めない。

`docs/recurring-lessons.md` の F-012 は、事前に作業ディレクトリと実在対象を確認し、空結果・アクセス拒否を区別する既存の予防策を定める。今回も同じ既存策が適用できる。新たな一般規則を追加する必要性は今回の証拠だけでは認められないが、既存策の継続効果は未確認。

## 実施可能な対策

1. `Get-Location` と対象の親を確認し、既知の対象には `Test-Path -LiteralPath` と適切な `-PathType Leaf` / `Container` を使う。false やアクセス不明なら推測先で検索を続けず、存在する親から `rg --files` またはディレクトリ一覧で候補を特定する。
2. 検索対象を存在確認した後に絞り、終了コードと stderr を確認する。Windows の今回の `rg` は OS error 2 でも終了1だったため、コード1だけで不一致とみなさない。複数対象の場合、一部の一致行が得られても他対象のエラーがあれば全対象成功にしない。
3. 親ディレクトリからの探索は対象・件数・行長を絞り、出力を切り詰めない。存在・アクセス・検索失敗を区別し、見つけた資料と対象版を読戻す。今回の現行 README は上記方法で限定検索できた。旧 run の再取得は当事者の結果に依存し、本担当は再実行していない。
4. 失敗ログへの個別記録、旧記録との重複・累計の照合、教訓の採否と読戻しは共有ファイル所有者に委ねる。

本担当の操作は `Get-Content`、`Test-Path`、限定 `rg` を読み取りのみで使用。失敗は本調査中には発生していない。実操作の再発防止効果、旧 run 全資料の網羅、元の2件の完全な出力は未確認。
