# 出力切り詰めの独立分析

担当 `/root/existing_work_review`。当事者 `/root/issue_survey` とは別担当。今回の事象は管理者からの依頼に基づき、元のツール出力・具体的コマンド・上限・終了コードを直接確認していない。したがって観測の詳細や失われた部分は未確認。

## 結論と影響

管理者は、`docs/verification-20261120.md` の一括表示と広い `rg` のそれぞれで出力が切り詰められたと報告した。いずれも必要情報が表示上限に収まらない場合という共通の予防策を持つので、F-001 の候補として2発生を別々に記録することが妥当。記録済み発生との重複と暫定累計は管理者が元記録と照合する。内部で切り詰めた層、対象ファイルや検索結果の欠落範囲、コマンド終了コードは未確認で、検索に一致しない・情報が存在しないとは判断できない。

対象文書は現時点で 46,281 bytes、234 行、最大行 449 文字。全文一括表示は既存指示の「必要な短い範囲」と合わず、上限を超え得る。広い検索も対象数・行長・一致数・出力包装を見積もらなければ同様の危険がある。ただし、実際のコマンドや表示上限を見ていないため、各事象の直接原因として断定できない。ユーザーへの要件・検証の結論が欠落部分に依存していれば根拠が不足する。

## 再取得と予防

`docs/instructions/work.md` と `docs/recurring-lessons.md` の F-001 は対象・行長・件数と内外の上限を見積もり、文書を一つずつ短い範囲に分けることを既に要求している。新たな一般ルールは不要と考えるが、再発防止効果は未確認。

1. 元の呼出し情報と残った出力から欠けた範囲と終了コードの可否を区別する。失われた元出力を復元したと扱わない。外部書込みや秘密を伴う元処理は出力確認のため再実行しない。
2. 文書の見出し一覧を長さ・件数を限定して取得し、必要な見出しの前後だけを小分けに読む。行の長さと改行・包装の余裕を見て各呼出しの内外上限を設定し、区間の連続性と終了結果を確認する。資料が更新され得る場合は再取得版のハッシュを記録し、過去版と同一と仮定しない。
3. `rg` は対象ディレクトリ、ファイル種別、生成物除外、既知の識別子を事前に限定し、一条件ずつ実行する。一致数・最大行長を必要に応じて表示内容なしに計測し、短い範囲に分ける。終了コード、件数と切り詰め有無を確認し、空結果と取得失敗を区別する。検索対象と条件を特定できない部分は欠落のまま報告する。
4. 記録担当は両発生を失敗ログへ追記し、独立分析と採否・既存指示の適用・未確認を F-001 の教訓に反映、読み戻す。共同編集されるログと教訓は担当に任せる。

## 本調査中の操作失敗

ファイル情報計測時、`Measure-Object -Line -Maximum -Property Length` は PowerShell のパラメーターセットが曖昧として終了コード 1。文書のサイズは取得済みだったが行数と最大長はその操作では得られなかった。後続の別形式 `Measure-Object -Property Length -Maximum` と配列の Count で上記値を得た。失敗記録への分類・記録を管理に依頼する。これとは別に先の調査で CIM アクセス拒否が1回あったことは `existing-work-survey-20261121-01.md` に記載済み。いずれも製品・外部操作を伴わない。今回の分析は既存ファイルを編集せず、読取りと本ファイルのみ作成した。
