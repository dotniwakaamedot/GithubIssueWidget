## 根拠と条件

- 監査対象の `main.tsx`、`main.rs`、`creation.rs`、`tauri.conf.json` の SHA は依頼版と一致。初期設定状態、初回 `connection_info` と `pending_creation`、一覧取得のガード、空 credential ID の早期 return、`APPDATA` の設定先と lock、復旧処理呼出しを現行ソースで照合。新規空実体の設定領域が維持され画面操作をしない条件では、記載の製品コード経路は GitHub と credential の使用に至らないという静的結論と整合する。依存や WebView2 の通信・資格情報には拡張できない。
- 方式案は既存 EXE と現行入力の差を区別し、新規専用領域・入力一覧・依存・共有先・非リンク・環境・ログの確認を要求する。実行方式と監督スクリプトは未確定であり、実際の環境を確認した具体的方式とコードのレビューを省略できない。特に同一ユーザーによる設定領域の書込み競合への実現可能な管理と、build の依存復元・ネットワーク・共有キャッシュを明示して固定する。成立しない項目は未実施にする。
- 固定 EXE と直接プロセスの保持ハンドル・ウィンドウの対応確認、期限、正常な閉鎖と直接プロセスの終了コード、判別不能時の保全・調査が要求される。実際の WebView2 子孫の終了・同一ユーザーの資源への影響・旧不明プロセスの不在は証明しない。識別不能対象を推測して終了しない。
- 実機表示、PAT、実 GitHub、Credential Manager、ウィンドウ操作や全 Issue 完成は未検証。新ビルドと対象コードの対応、表示可能セッション、WebView2、実行経路の成立、競合抑止、スクリプトの実挙動を個別に確認する。
