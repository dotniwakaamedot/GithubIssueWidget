# 旧 Issue #4 の担当状態と同期修正の判断案

`docs/instructions/delegation.md` は「再開時は旧担当の終了と変更の保護を確認」、`docs/agent-workflow.md` は旧担当の終了・中断等により「書き込みが止まったこと」を確認して担当を変更すると定める。対象は引継ぎ範囲の旧担当による書込み停止であり、全ての無関係なセッション・将来の編集の不存在ではない。一方、レビュー待ちという文言だけでは停止確認と断定できない。

確認された証拠: `issue-04-status-20261119.md` は同対象のレビュー待ち・修正版と SHA を固定し、追加レビュー・完了判定を保留した記録。`issue-04-review-20261119-04.md` は対象版の限定承認。後続 `issue-05-start-20261119.md` は同じ旧 `/root` が #4 の暫定コミット `3d906e5` を基準に別 #5 作業を始めたことを記録し、旧 #4 の成果を後続に引き渡した事実を示す。`old-issue4-handoff-investigation-01.md` は旧 worktree の現時点の限定 git status がクリーン、現行版との主要なボード処理の静的重なりを記録するが、旧担当の現在のセッションや書込みの直接証拠ではない。

旧担当の現時点の直接状態は未確認として残す。旧固定成果は別 worktree・branch・コミットとして保持され、現在の新 checkout での対象2ファイルは基準版と一致する。後続 #5 着手を含む旧記録により、少なくとも旧 #4 の固定版の成果が後続へ引き渡されたことは確認できる。現行作業は旧 worktree への担当交代や編集ではなく、現 HEAD の別 checkout で現行版に対する局所修正であり、同時に旧 worktree の成果を変更しない。SHA と状態の着手直前・直後の照合、単独担当、差異時の中断で予期しない現行変更を保護する。

この条件で、旧成果の保護と旧固定版から後続への移行は確認できたとして、現 checkout での限定修正を進める判断を提案する。旧担当の現在のセッション終了・全 PR 不在・旧成果と現行が完全同値であるという主張はしない。旧 worktree や remote の操作は行わず、旧版との意味差・関連 PR は引き続き確認する。実際に旧対象へ担当を割り当て直す場合は、書込み停止の直接確認を別途要する。

この解釈と、ユーザーの完成指示・プロジェクト指示に対する妥当性を別担当がレビューする。blocking が残る場合は現 checkout へ適用せず、隔離版の維持と未確認の確認を進める。承認後も現行対象 SHA、作業者の所有、試験と旧資産の保護の個別条件を満たす必要がある。
