## 自動化とユーザーが担う判断・操作

| 項目 | 代理で進められる範囲 | ユーザーが必要となる条件 |
| --- | --- | --- |
| ビルド・画面観察 | 固定版のビルド、空の専用設定で表示・移動・サイズ・最前面・リンクを測定可能。画面・プロセスを特定し対象外を触らない。実行環境と方法は要検証。 | 対話デスクトップへのアクセスや操作が利用できない場合、ユーザーが指定版で操作・結果を報告。ユーザー自身の Windows 11 上の結果が必要ならその環境で確認。 |
| PAT | アプリへの保存、再起動、取得・削除の挙動を、ユーザーが安全に入力したトークン値を取得せず、UI の表示・結果から検証できる場合がある。環境だけで Credential Manager は分離されない。 | 必要な権限を持つトークンの作成・対象リポジトリ選択は、代理に適切な権限がなければアカウント所有者が行う。値はユーザーがアプリへ直接入力し、入力中の自動画面収集を止める。既に権限ある安全な資格情報が利用できる場合は新規作成を当然視しない。 |
| 実 GitHub 操作 | ユーザーが既に承諾した公開テスト対象・限定操作内で、権限と安全な監督が確認できれば作成・移動・結果読戻しを実施できる。 | 利用可能な書込み権限やテスト対象が決定できない場合のみ所有者が設定・判断。PAT や秘密を渡す必要はない。既に承諾された操作は再承諾を求めない。 |
| 障害・競合 | 合成サーバーで再現可能な接続、権限、レート制限、部分失敗、古い応答は自動テストで検証可能。実際の GitHub 障害・レート制限と区別する。 | 実サービスの権限変更やネットワーク設定を伴い、既存承諾・環境の権限から実施できない時のみ所有者が環境を整えるか未検証として残す。 |

## ユーザーに渡す具体的な操作案

実行環境・対象版・安全なバックアップ/隔離先を管理が確認し、起動方法の独立レビュー後に案内する。これは現時点でユーザーに実行させる指示ではなく、必要な際の手順案。

1. 固定した release 版を起動し、設定画面を確認。表示しない・落ちる・対象を識別できない場合は再試行を繰り返さず状態と対象版を記録する。空設定だけでも WebView2 の副作用や同一ユーザーのストアを隔離できるとは限らず、前提・残余リスクの確認が必要。
2. 接続テスト用 PAT が必要なら、所有者が fine-grained PAT を対象リポジトリに限定し、Metadata 読取と Issues の読書に必要な権限・有効期限を自身で設定。アプリの欄へ直接入力し、チャットやスクリーンショットに値を含めない。接続確認成功は Issues の書込み権限の証明ではない。画面観察は入力後に安全な状態で再開する。
3. 接続に成功したらアプリを閉じ、同じ OS ユーザー・同じ設定先で再起動し、トークンを再入力せず接続できるかを確認。設定先切替時に旧一覧・遅延応答が混ざらないことを、合成試験と実 UI で区別して確認。トークン更新・削除は、専用のテスト用資格情報と対象・復旧方針が明確な場合に限り行い、実際の既存資格情報を誤って削除しない。
4. 許可済み公開テスト対象の確認後、専用の識別子付き Issue を1件だけ作成し、許された範囲で全列の移動・Open/Closed・ステータス以外のラベルを読戻す。`docs/handoff-20261121.md` に示された既存承諾と手順を再確認し、既存 Issue・PR は変更しない。作成応答不明時は再 POST せず、全ページで識別子を照合する。部分失敗は既存記録と実状態を再取得してから次の操作を決める。最後のクローズ・履歴保持は既承諾に従う。
5. 表示・移動・サイズ変更・最前面・リンク、実 GitHub の状態・ラベルを対象版で確認し、各操作の成功・失敗・未実施と時刻を記録。Credential Manager 内のトークン値を表示・記録しない。削除テストと GitHub 側のトークン失効は別の操作であり、専用テスト用トークンの要否・後始末は所有者が判断する。

## 成功判定と残余

- Issue #7 は Windows 11 での開発起動と release build、ウィンドウ操作、設定・再起動・一覧と移動、認証・権限・障害・競合、秘密非露出を対象版ごとに求める。表示だけや合成試験だけを完了としない。スクリーンショット不取得でも、対象・時刻・観測主体・具体的な操作結果と直接終了証拠を記録し、未実行を明示する。
- Issue #3 は保存済みトークンを React に返さず、平文設定・ログ・ソースに残さないことと部分保存失敗の扱いも要求する。画面のパスワード表示だけでは非露出の証拠にならず、固定対象のコード・安全なログ／設定検査と障害試験を別に行う。実データの秘密を出力せずに確認できない場合は未確認とする。
- 対象版・所有者の操作・権限・API 読戻し・実 GUI を独立に記録する。画面・アカウント・OS 環境や子孫の追跡ができなかった場合は具体的に残し、ユーザー操作が必須だと推測して不要な依頼をしない。

Issue #3・#7 の取得と指定ファイルの読取りは成功。今回、ビルド・GUI・実トークン・ネットワーク障害注入・実書込みは未実施。新規の操作失敗は認識していない。
