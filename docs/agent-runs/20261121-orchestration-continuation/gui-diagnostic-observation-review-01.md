# GUI 診断版の固定ステージ観測レビュー

2026-11-21、確認者 `/root/issue_survey`、実行者 `/root/gui_failure_investigation` と別担当。依頼01と担当訂正02、固定ステージ診断の既存レビューおよび release 空設定観測の承認版を照合した。

**固定版の1回の診断観測を条件付きで承認。** 既存承認方式との差分は診断 EXE SHA、空ディレクトリ確認対象への `markers` 追加、専用 `GIW_DIAGNOSTIC_DIR` の設定に限る。診断対象は製品版と異なり、本承認は製品動作や原因を証明しない。追加の観測器作成や合成起動を開始条件には求めない。

## 開始前と観測時の条件

- 親の開始通知後、対象 EXE・観測器・固定入力 SHA、`observation-status.txt` の不存在、6つの専用領域と親の実体・空・アクセス権・再解析点、同時書込みなしを実行者が直前確認する。`Path.is_symlink()` は Windows の全 reparse point を判定しないので、既存レビューどおり別の実体確認を省略しない。不一致・不明なら起動しない。
- 明示された空設定で1回だけ起動し、実 PAT、実 GitHub、フォームに触れない。Credential Manager と WebView2 は OS 共有資源であり、環境変数だけで隔離・非通信を保証できない。直接子の保持ハンドル・実行パス・作成時刻と CUA の対象窓が一意に対応した場合だけ通常閉鎖する。一致不明なら他窓を操作しない。
- 30秒後も生存する場合、同一セッションを観測し続ける。通常閉鎖不能時の自己起動の直接子だけを対象とする処理は、preflight に明記された固定版・保持ハンドル・パス・作成時刻・生存を改めて確認した限定方針に従う。PID や HWND だけで停止しない。観測器が終了しない場合、直接子・未知子孫の状態を不明とし証拠を保持して再実行しない。
- marker は固定 enum の有無だけ分類し、例外や生ログ・入力値を表示しない。欠落は未到達・未処理・書込み失敗を区別できず、非同期 IPC の到達順は処理順の証明ではない。stdout/stderr は破棄され、一般 panic 内容は得られない。直接子と全子孫の終了、古い事象の原因、実 UI と認証の完成を区別する。
