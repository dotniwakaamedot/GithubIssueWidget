# 実際の対話デスクトップでの MVP 起動手段調査

担当 ID は親が確定する。`gui-diagnostic-observation-status-01.md` の `before_run` のみの観測について、他 marker の欠落は未到達・IPC 未処理・記録失敗を区別できず、原因確定とは扱わない。実行中の直接子の終了は担当の確定報告を待つ。同じ無情報起動を繰り返さない。

利用可能な Windows 対話デスクトップ・通常ユーザーのセッションで、現行ビルドを表示・識別・通常終了する現実的な手段と、その実行に本当にユーザーの操作が必要かを、既知の固定資料とツールの機能・現在の環境から調査する。MVP 起動・接続・一覧・作成・移動を優先し、通常の実行を不要な VM や追加監督器に依存させない。別環境を使う場合は実在・アクセス・ユーザー権限・秘密/設定の扱いを具体的に確認する。

読取りを基本とし、権限や既存設定の変更、対象不明のプロセス終了、実 credential/GitHub 書込みはしない。ユーザーの協力が必須なら理由と本人が安全に実施できる具体的な最小操作・必要な情報を明記し、AI が自力で進められることを区別する。短い結果に事実・仮説・未確認・次手と版を示す。既存合格試験の再実行と余分な文書を避ける。
