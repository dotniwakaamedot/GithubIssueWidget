# 同期テストの実行環境の選択肢

`sync-dependency-safety-independent-01.md` は、対象テストの Tauri IPC・ウィンドウ・Opener をモックする静的証拠と、Vite の `.env` 読取り、esbuild 子、依存全体の通信・Credential Manager 経路が未追跡であることを区別している。未追跡だけで実際のアクセスが発生すると断定しない。ユーザーの目的はアプリ完成であり、VM の新設や全依存の完全証明を前提に無期限に止めない。

## 実用候補: 現在の制限付き環境と隔離 fixture

- 専用の新規 fixture に固定されたソース・設定・依存を独立コピーし、`.env*`・既存プロファイル・cache を持ち込まない。実行の環境変数は OS 起動に必要なものと専用 TEMP・APPDATA 等だけを明示し、トークン・プロキシ・`NODE_OPTIONS`・`ESBUILD_BINARY_PATH` は渡さない。実ユーザーの Credential Manager はこれで OS レベル隔離されないと明記する。
- 対象テストの `vi.mock`、合成データと既知の依存起動経路を対象版で確認し、実 GitHub・PAT・実 GUI を意図的に呼ぶ経路がないことを記録する。未検査の依存内部について絶対保証しない。必要に応じ既存 sandbox の実際のネットワーク・権限制約を確認し、設定変更や他人の資格情報の列挙は行わない。
- Node・Vitest・esbuild の固定実体、専用出力・期限、直接の終了コードと利用可能な子孫管理を事前に固定し、監督器の版別レビューを通す。実行時に予想外の通信や実資格情報へのアクセス、出力不明、停止失敗が観測されたら中止して別担当に調査を委ねる。観測できないことを「起きていない」と扱わない。
- モックを使う単体試験なので結果は実 GitHub・実資格情報・Windows UI や OS スリープを証明しない。合成テスト後にもそれぞれの実環境要件は残る。残る未確認を含め管理者がリスクと妥当性を判断し、B2 の根拠・レビューを固定した上で実行する。

## より強い隔離を利用できる場合

既に利用可能な独立 VM や別の空アカウントが確認できるなら、秘密・旧 fixture を共有しないこととネットワーク制限の実効性を確認して使える。存在・権限・ライセンスや必要な依存は未確認であり、現時点で存在を前提にしない。OS 全体の firewall やユーザー設定を無断変更せず、実資格情報の列挙も行わない。

どちらも対象版・方式・依存・結果の独立レビューが必要。上記は選択肢と条件であり、検査も実行も済んだことを意味しない。監督器の作業と隔離 fixture 準備を並行し、レビューで実行可能な方法を確定する。
