# MVP 優先の方針

ユーザーの最新指示を優先し、使用開始可能な MVP の起動・接続・一覧・作成・移動・秘密保護に集中する。GitHub を正とし、競合を検知したら上書き・自動再試行せず GitHub の状態を再取得する。途中反映の可能性を明示し、再取得失敗時は古い表示を最新と誤認させない。Issue の要求・現行実装を確認し、必要な変更とその検証を最小限に絞る。

既に合格した同一版の試験は新しい理由なく繰り返さない。余分な競合試験、文書、調整の増加を避け、現在進行中の操作は状態と成果を保護する。新しい競合テストや準備の追加着手は MVP 必須の根拠を親が確認するまで控える。診断 GUI の対象版ビルドと、同じ無情報の起動を繰り返さない実測を優先する。

他者の変更・実 credential・非公開データ、無関係なプロセスを保護する。未実施は未確認とし、同じ失敗が2回あれば別担当が調査して解決する。
