- 判定: **指定された限定合成テストの方式を承認**。blocking なし。入力・環境・実行体等の事前条件を実行者が確認して初めて実施可能。テスト結果、実 UI、実資格情報、GitHub 操作、製品統合や Issue 全体を承認するものではない。

| 観点 | 根拠・判断 |
| --- | --- |
| 固定対象・保護 | 隔離済み fixture、manifest、対象 SHA と Node/Vitest/esbuild の実体を指定し、実行直前の追加・欠落・相違・再解析点や予期せぬ予約領域の内容で開始しない。先行の全ファイル照合は `sync-test-prepare-review-01.md` に限定。 |
| 入力・環境・通信 | 対象は Tauri IPC・window・opener をモックする単一ファイル。専用コピーと環境を用い `.env`・トークン等を持ち込まない。依存全体や OS Credential Manager の非アクセスは証明されない残余リスクだが、この合成テストに実資格情報や実 GitHub を与える・操作する目的やコード経路は確認されず、独自 VM・独自監督器の完成を一律の前提にしない。未確認は記録する。 |
| 実行と終了 | 作業場所、直接 Node の CLI と単一 worker の候補を示し、受理と実際の件数を確認する。実行ツールの説明上、`exec_command` は直接コマンドの終了コードか継続セッション ID を返し、`write_stdin` は同一セッションを待機できる。終了時に ID が返らない場合は終了コードを保持。直下の状態だけで全子孫終了を主張しない。 |
| 失敗時 | 観測タイムアウトを終了扱いせず同じセッションを確認し、異常時の再実行・領域削除を止める。旧または無関係なプロセスを推測して終了しない。ユーザー指示の2回の同種失敗時に別担当へ依頼。 |
| 検証の限界 | 直接終了コード、実収集数・成否・ログ欠落・子孫状態を区別。想定39件や未実行を成功にしない。個別検証の成功を Issue 全体完成へ拡張しない。 |

## 実行時に記録する事項

- 固定コマンドのカレントディレクトリ、実際に渡した非機密の環境変数名と専用パス、入力の再照合結果、開始・終了・必要ならセッション ID を記録する。PowerShell で Node の終了を取得する場合は `$LASTEXITCODE` を他の処理より前に捕捉し、その値を確認する。直接終了でも子孫が未確認なら別欄に残す。
- 出力は合成値の専用ログに限定し、サイズ・完全性と退出コードを確認する。CLI の未知オプション、0件収集、期限・アクセス不明などは成功とせず記録する。外部通信・資格情報ストアの非アクセスについては静的に確認した範囲と残余リスクを区別する。

`D:/Projects/GithubIssueWidget` で依頼・計画・依存の独立調査と前レビューを照合し、開始・終了の SHA を確認。記載された倍区切りの Node パスは `Test-Path -LiteralPath` で存在を確認（終了0）。テスト・GUI・外部操作・製品編集は未実施。実行中に方式が変われば別途確認する。
