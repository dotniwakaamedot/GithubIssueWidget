## 再発防止と限定確認

既存分析 `path-failure-independent-01.md` と同様、推測したパスのまま本文を読まず、まず作業場所と依頼元に記載された正確なパスを確認する。パスが未指定・不明なら実在する親から限定したファイル一覧を取得して候補を特定し、対象ごとに `Test-Path -LiteralPath -PathType Leaf` を実行する。false やアクセスエラーを読取り成功とせず、エラーと不存在を区別する。複数対象は各々が確認できるまで一括検索しない。候補と確定したファイルの位置・版を示してから短い範囲を読む。

具体例として今回の調査では、当事者が推測したパスと報告した実在パスをそれぞれ `Test-Path -LiteralPath -PathType Leaf` で一度だけ確認したところ、前者は false、後者は true、コマンド終了0。これは**今回の観測時点**の確認であり、過去の存在状態や将来の race・アクセス権を証明しない。対象内容の網羅・実装レビューにも代用しない。

各操作直前に対象リストと確認結果を対応付ける作業手順として既存ルールを具体的に適用する。指示を読んだ事実だけを適用済みの証拠にせず、結果・終了・stderr を記録する。新たな一般ルールの追加は提案しない。限定例以外の実務での継続効果は未確認であり、共有失敗ログ・教訓への記録と独立レビューは管理担当へ引き渡す。
