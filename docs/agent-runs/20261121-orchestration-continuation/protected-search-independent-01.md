# 保護領域検索の独立分析

担当 `/root/project_survey`。当事者 `/root/issue_survey` の報告と既存 F-001・F-012 の対策を照合。保護領域の走査・秘密の読取りは行っていない。

## 確認された事実

`rg -l -F 'gui-release-build-01' docs/agent-runs/20261121-orchestration-continuation -g '*.md' -g '!gui-release-build-01/**'` は OS error 5 を保護 root と他の保護サブディレクトリで表示し終了1。約370 tokens の出力が300付近の表示予算で切断された。機密ファイル本文の表示はなかったとの報告。直前の同条件で stderr を抑制した検索は終了0・9件表示したが、エラー抑制により網羅性不明。当事者は以後再帰探索を停止し、既知の `gui-release-build-result-01.md`・`observe-search-failure-01.md` を個別に読んでいる。

## 原因と対策

保護先を含む run 全体を探索し、1つの除外 glob だけで他の保護ディレクトリのアクセスや親の探索まで防げるという前提が不足していた。rg が今回どの時点で各親ディレクトリを訪れたかや、glob の解釈の詳細は出力だけでは確定できない。エラーや切断を含む検索の結果、および stderr 抑制で得た件数を全件成功と扱えない。

次回は探索対象を権限・存在が確認された既知の具体的なファイルまたは狭いディレクトリだけに限定する。対象が既知なら個別パスを指定し、未知の親全体を辿らない。やむを得ず限定されたディレクトリ内で列挙するときは、既知の保護ディレクトリを対象から外し、必要に応じ親自体も含む明示的除外を指定したうえで、stderr と終了コードを保持する。ただし除外指定は権限確認の代替ではなく、保護親への走査が不要な対象選択を優先する。表示前に候補の件数と長い行を含む出力量を見積もり、必要な範囲を分割する。アクセス拒否・出力切断・未取得は未確認として報告し、秘密が混入し得るエラーを無保護ログに保存しない。

既存 `docs/recurring-lessons.md` F-001 は対象限定・生成物除外・出力量と内外上限の見積り、F-012 は実在とアクセス確認を既に指示している。新たな一般ルールより、今回の保護 root を含めた対象選択・除外指定と stderr 抑制の限界を具体例として適用することを推奨。対策の実効性と過去発生との累計は未確認。失敗記録への反映は管理担当に引き渡す。本分析の限定読取りは終了0、試験・製品変更はしていない。
