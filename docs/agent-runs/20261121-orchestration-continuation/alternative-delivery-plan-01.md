# 製品完成への代替経路の検討計画

- 原文: 「issueを確認し、アプリを完成させてください。あなたはオーケストレーションに徹してください。２度同じ失敗があったときは、別のエージェントに調査させて解決をしてください。」独立検討とレビューを使い、製品の要件実装・検証を進める。
- 背景: `test-supervisor-result-03.md` と先行結果は専用監督器が未完成であり、同期案の Vitest は未実行であると記録する。既存の監督器を完成すること自体は Issue #1〜#7 の製品要件ではない。継続すべき安全条件と、根拠のない過大な前提を区別する。
- 対象: 既存の隔離同期案・関連 Issue・テスト方法・ローカル環境を参照し、通常の独立環境、限定テスト、ローカル実装と製品統合の現実的な選択肢を別担当が検討する。事実・仮説・残リスクを区別し、既存未コミット変更、旧 worktree、認証情報・非公開データを保護する。

| ID | 状態 | 担当と範囲 | 条件・成果 |
| --- | --- | --- | --- |
| A | 未着手 | 独立調査担当。読取り・検討と固有結果のみ。監督器作者・同期案作者とは別。 | 先行監督・テスト・GUI 障害の証拠とユーザー・プロジェクト指示を照合し、通常のツールが持つ直接プロセス待機と既存 sandbox の境界、隔離 fixture と Tauri モック、限定したテスト、権限の取扱い、証拠と不確実性を検討。存在・認可が不明な VM やシステム設定変更を前提にしない。 |
| B | 未着手 | 独立レビュー担当。結果版を SHA256 で固定。 | 選択肢の実行可能性、Issue 要件、秘密と既存作業保護、実際の危険と過大な前提、検証範囲、実行時の終了・失敗判定を確認。blocking を具体化し修正後に再確認。 |
| C | 未着手 | 方式承認後に指定する作業担当。作業場所・ファイルを固有依頼で明示。 | A/B で承認された現実的な方式について、所有権・対象版・実行対象・環境・期限・結果を固定し、安全に進められる製品コードの統合と限定テストを実施。実 GUI や実 GitHub 操作はそれぞれのリスクと認可・未確認を別に判断する。 |
| D | 未着手 | 作者以外の独立レビューと管理。 | 変更・テストの実際の版、既存作業との差分、成功/失敗/未実施を確認し、必要な修正・回帰試験と残 Issue の作業を継続。同期案の局所成功をアプリ全体の完成とみなさない。 |

## 判断・保護

- 旧合成子の状態は未確認であり、無関係なプロセスを推測して終了しない。通常の個別テストの実行と旧 GUI・不明子・実 GitHub 書込みの実際の共有資源や副作用を個別に評価する。未確認を不存在とせず、無条件の完全保証を必要以上に要求しない。
- 対象テストの依存・モック・データ、実行に引き継ぐ環境、出力先・既存キャッシュ、実行プロセスと終了コード・期限を固定し、秘密を記録しない。実行方式の限界と、未追跡子孫の終了が証明できない場合の取扱いを区別する。
- 現 checkout と旧 worktree は変更前に対象版・差分・所有者・関連 PR を利用可能な証拠で照合し、他の変更を上書きしない。未知の全セッションの不存在を無期限に求めず、保護・競合回避・記録で安全に実行可能な境界を判断する。
- この計画は代替経路の検討を承認するものであり、テストや外部書込みの即時実行を許可するものではない。個別方式と実行可能な作業を早急に具体化しレビューする。PR・merge 等の外部操作は既存の権限とユーザー承諾に従う。
