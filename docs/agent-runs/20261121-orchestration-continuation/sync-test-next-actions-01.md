# 同期案の検証を進める具体策

`sync-test-design-result-01.md` は旧監督対象と新規 Vitest の干渉を未証明とし、依存の複写・CLI・書込み・監督方式を固定する必要を挙げる。隔離版は `sync-isolated-result-02.md` の新版になっているため、旧版ハッシュを再利用しない。

1. 別担当に、インストール済み `node_modules` の容量・リンクの有無・使用する Node/Vitest 実体と CLI の対応オプション、`widget` に必要な設定・CSS・入力の一覧を読取り調査させる。テストを実行せず、共有依存の変更がない分離方式と正確なコマンドを固める。
2. 監督方式は GUI 実行の未解決問題と区別して、テスト対象自身が実 GitHub・Credential Manager・旧 fixture を使わない根拠、作業領域と環境の分離、実行の期限・結果・停止時の取り扱いを個別に設計する。旧の不明プロセスを探索・停止しない。通常のテスト起動を一律に未追跡 GUI 合成子と同一視せず、独立性を示す具体的根拠と未確認を明記する。
3. 方式と固定版を別担当が確認し、blocking を解消してから、認可範囲内の限定テストを実施。テスト本体の件数・終了コードとログ、プロセス終了と未確認を区別する。0件や出力途切れを成功としない。実際の安全な証拠を確認できない場合は実行を見送り、不能の範囲を具体的に記録する。
4. 並行して PR の一覧を正確な API・ページ終端条件で照合し、旧 worktree を保護したまま対象差分と現行版・作業場所を確認する。旧担当の不在を漠然と要求し続けず、特定の旧 run・担当・PR の利用可能な証拠に基づいて親が統合判断を記録する。対象版変更があれば再基準化・再試験・再レビューする。

これらは作業指示案であり、テスト実行や統合の承認ではない。安全条件を合理的に満たせる範囲から具体化し、GUI や実 GitHub の未確認を他の独立作業の停止理由にしない。
