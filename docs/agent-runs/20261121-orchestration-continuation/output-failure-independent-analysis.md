## 原因と対応

表示が上限を超えたことは確認できる。広い対象、複数検索条件と長い一致行、複数文書・JSON 包装の合計を事前に十分限定しなかったことがそれぞれの原因候補である。元の全文がないため各行・各文書の寄与や欠落箇所は特定できない。終了コード 0 は検索処理の成功であり、出力全体の確認を意味しない。

Windows のワイルドカード引数の失敗は別の確認済み事実であり、出力切り詰めそのものの直接原因とは断定できない。対象ディレクトリの存在を先に確認し、ファイル指定のワイルドカードをシェル展開に依存させず `rg` の `-g` で指定するか実在するファイルを個別指定する。検索範囲・条件は一度に狭くし、長い行を出力する前に行長も確認する。修正後の検索成功は未検証。

既存 `docs/instructions/work.md` と `docs/recurring-lessons.md` の F-001 は、対象限定、長い行と包装を含む内外の上限見積り、原則 1 文書ずつ必要な短い範囲の取得を既に要求する。今回も適用可能なので新たな一般ルールの追加より、各取得前に対象・範囲・出力上限を具体的に決め、結果ごとに表示する。機密のおそれがない大量出力は必要に応じて適切なログへ保存し、プロセス終了結果とログ・表示の完全性を別々に確認する。欠落部分は未確認のままとし、外部書込みを出力確認だけのために再実行しない。

これらは対応案であり再発防止効果は未検証。失敗の発生記録・暫定累計および教訓更新は同時編集を避け、親の指定した planning 担当が扱う。
