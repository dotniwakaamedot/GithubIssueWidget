- 目的: Issue #4 の同期改善を、レビューと39件の限定試験を受けた隔離版から現行製品へ最小差分で反映する。全 Issue 完成とは区別する。原文・既存資産保護と `alternative-delivery-plan-review-01.md` に従う。
- 根拠: `sync-isolated-review-02.md` は固定版の静的レビュー承認、`sync-practical-test-result-01.md` は限定版39件成功・直接終了0を報告。後者の独立レビュー完了を統合前の必須条件とする。実 GUI・API・資格情報・スリープや不明な子孫の終了は未確認。
- 対象: 現 checkout `D:/Projects/GithubIssueWidget` の `widget/src/main.tsx` 出典 SHA256 `01A7E8A6961BE2DC4F00D96F9369098321EF5137F6959650931E36ABFB357658`、`widget/src/main.test.tsx` `6D1F45AFDBFC3BD66071C81FD7BA0025A186BD6A1CC0CE89022D06FB19B7D1E1`。統合元は隔離 main `6FCF2A34145450C5029B7FF80DDB3EC1DA5E27173AAB84E57F16D6D54C0E6A3E` と test `66E118A5A7062854C23BE405D2E9578C974FA283BEA332F2A7C51DCA1BFFD13C`。README は既存の「約60秒」と整合し変更不要と静的レビューが確認した。
- 保護と根拠: `sync-ownership-result-01.md` と `sync-pr-history-result-01.md` によれば対象2ファイルは現 checkout で HEAD に差分がなく、旧 #4 worktree は別場所・別 branch として存在。旧担当の停止と全 PR は確定できない。空検索・取得失敗を PR 不在とは扱わず、旧 worktree・branch・PR に書き込まず保護する。現在の checkout への限定的なローカル差分作成は remote や旧 worktree を変更しないため、ユーザーの完成指示と現行対象版の競合確認を根拠に実施可能と判断する。これは他セッションの不存在、旧変更の統合済み、PR 不在を主張しない。push・PR・merge・Issue 状態変更は別途対象・権限・競合を確認する。
- 統合直前に現 HEAD・git status・対象2ファイルと隔離2ファイルの SHA・限定差分・旧 worktree の利用可能な状態を再確認。対象が基準と異なる、他担当による変更・所有が確認される、隔離版がレビュー/試験版と異なる場合は上書きせず中断して再評価。SHA 確認後も競合し得ることを認識し、共有 checkout の対象2ファイルは1担当のみが更新し、作業期間中の他担当へ書込み禁止を明示する。既存の main.rs 等、未追跡・他ファイルは一切変更しない。
- 実施: 別途確定依頼で担当 ID・対象・所有・版を指定し、隔離版から同期に対応する最小差分のみを適用。各対象の適用前後を読戻し、変更後 SHA を隔離試験版と照合。一致しなければ差分を分析し、既存変更を保護して再試験・新版レビューする。生成物・ログは専用 run に保管し、共有状態を不用意に削除しない。
- 検証: 適用後の現行2ファイルが上記試験済み SHA と一致することを確認し、可能な範囲で通常の型検査・ビルド・テストを安全な独立環境で再実行する。実行コマンド、入力、結果と未実施を記録。直接テストできない場合、隔離版の限定試験と実製品ファイルのハッシュ一致は同一内容の証拠として扱うが、実製品全体の結合試験や UI 確認と混同しない。
- 完了: 作者と異なる担当が最終ファイル・差分・版・テスト結果を Issue #4 と照合。blocking と未検証を記録し、版が変われば再レビューする。未確認の PR、実環境、認証と他の Issue を残作業として後続で扱う。
