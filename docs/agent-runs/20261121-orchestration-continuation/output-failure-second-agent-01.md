# 出力切り詰め2件の別担当調査

2026-11-21、調査 `/root/issue_survey`、当事者 `/root/process_safety`。依頼は今回の同種2回の失敗を別担当で調査し、実施できる限定出力方法を示すこと。製品・共有既存ファイルは変更していない。

## 事実と原因

- 当事者の直接報告によると、1件目は C 監査で `widget/src-tauri/src` に対して test・プロセス・ファイル・通信など多数の正規表現を一括 `rg` し、内側上限1万 tokens の結果を他結果と一緒に外側へ返した際の切り詰め。`test-execution-audit-c-01.md` も広い `rg` の外側切り詰めと、必要部分の限定再読取りを記録する。元出力の欠落範囲、内部ラッパー全体の正確な大きさは本担当には未確認。
- 2件目は `rg -n 'F-0(12|45)|PowerShell|ワイルドカード|brace|展開' docs/failure-log-001.md`、内側上限2500 tokens に対し2912 tokens で内側が切り詰められたと当事者が報告。元出力と終了コードは本担当に未提示。いずれの欠落も不存在の証拠にしない。
- 両者は対象・条件・件数・長い行と結果包装を事前に十分見積もらなかった可能性が高いが、直接原因の断定は元の完全なツール出力がないためできない。並列の複数結果をまとめる場合、各結果の上限と外側の合計上限は別に考える必要がある。
- `output-failure-independent-01.md` は別の担当 `/root/issue_survey` の先行する2件の独立分析であり、今回 `/root/process_safety` の2件の一次証拠ではない。同文書の短い範囲・件数・内外上限の一般的対策は適用可能。

## 合成ではない読み取りで確認した代替手順

- `rg` を一度に1ファイル・少数の具体的条件へ絞り、まず出力せずメモリ内で件数・最大行長を集計する。PowerShell 例: `$r=@(rg -n -e 'Command::' -e 'current_exe' widget/src-tauri/src/main.rs)` の後、`$r.Count`、`($r | Measure-Object -Property Length -Maximum).Maximum`、直後に保存した `$LASTEXITCODE` を短く表示。今回対象では4件・最大82文字・rg 終了0。内容の再取得 `rg -n -e 'Command::' -e 'current_exe' widget/src-tauri/src/main.rs` は4行を取得し終了0、切り詰めなし。
- 失敗記録でも限定例 `rg -n -e 'F-012' -e 'F-045' docs/failure-log-001.md` の結果をメモリ内で計測すると4件・最大297文字・rg 終了0。これは元の広い検索の代替全件ではなく、該当 ID だけの調査。必要な残条件は別の限定検索で扱う。
- 実用例では `$LASTEXITCODE` は `rg` の直後に変数へ保存してから他コマンドを実行し、0・1（不一致）・2以上（失敗）を区別する。件数と最大行長から余裕を見積もり、結果が大きければ `$r` の固定区間を分割表示し、全区間の件数・順序を照合する。非常に長い行を分割・省略する際は欠落を明示する。秘密や外部情報を含む可能性がある結果は、内容を表示・保存する前に安全性を評価する。
- この実例は今回の静的ローカル読み取りのみを対象とする。元の欠落を復元したと扱わず、長期間変更され得る対象では SHA256 を固定し、再取得後の結果と当時の結果を区別する。内側・外側の出力上限には包装と他の結果分の余裕を持たせる。不要な大きい結果を同時に返さない。
