## B01: 不正なヘッダー名の継続情報を無視して終端と扱う

- 根拠: `parse_response` は各ヘッダー行を `partition(":")` で分けた後、名前の妥当性を検証せず `name.lower() == "link"` のものだけ処理する。合成レスポンスで `Link : <...page=2>; rel="next"` のようにコロン前に空白がある行を与えると、無効なヘッダーを拒否せず `next_page=None` を返すことを独立に確認した。HTTP のヘッダー名にこの空白は不正であり、実際の GitHub や gh がその形式を出した事実は未確認。
- 影響: 異常・想定外の継続情報を終端として扱わないという前回レビュー条件を満たさず、次ページがある旨を含む不正応答で全件確認済みと誤認し得る。
- 修正案: コロン前の名前を HTTP フィールド名として検証し、不正な名前を含むヘッダーは失敗させる。合成の `Link :` や空・不正名を拒否し、通常の無関係なヘッダーと正規 Link の扱いも回帰試験する。
