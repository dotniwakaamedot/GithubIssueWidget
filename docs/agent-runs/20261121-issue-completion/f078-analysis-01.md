# F-078 GUI 起動失敗の独立分析

担当 `/root/f001_review`。依頼者 `/root` と別担当。製品・実アプリの操作を伴わない資料分析であり、原因の確定や再試行の承認ではない。

## 結論

発生3は終了コード101と Rust panic を含む標準エラーが記録されているが、本文が失われており、原因も panic 発生位置も特定できない。次に起動する場合は、同じ診断不足を繰り返さないよう、実行前に標準エラーをメモリ内で分類・安全な固定項目だけ記録できる捕捉方法を合成入力で確認する。今回の処理では GUI 起動失敗が既に１回発生しているため、同じ起動失敗が次にも起きれば指定どおり引き継ぎと中断を優先する。

## 確認事項と仮説

- F-078 発生1は終了コード未取得、発生2・3は終了コード101。発生3は stderr 363文字・Rust panic を含むと分類されたが、本文は保存されなかった。発生2までの証拠は `handoff-gui-stop-01.md` にある。実行方法・版が異なり、３件の同じ内部原因は未確認。
- 現行 `main.rs` の `main` は Tauri の `.run(...)` の失敗を `.expect("failed to run widget")` で panic する。しかしこれが今回の panic だったという証拠はない。WebView2・ディスプレイ環境・隔離ディレクトリの問題などは可能性にすぎず、既存証拠からは区別できない。
- `tauri.conf.json` は main ウィンドウを指定し、フロントエンドは起動時に接続情報と未完了操作を取得する。`settings_path()` は `APPDATA` を使うが、Credential Manager は OS のユーザー資格情報ストアを使う。環境変数の変更だけで資格情報ストア自体が隔離されるとは確認できない。空の専用設定先で開始し、設定・認証情報の変更や実 GitHub 操作を伴わないことを事前に確認する必要がある。
- 発生3で本文を保持しなかった事実は記録されている。記録設計が不足した可能性はあるが、保持しない判断の具体的な理由は当該資料から判明しない。秘密保護が理由だったと断定しない。

## 再試行前の推奨

1. 対象 EXE のハッシュ、作業ディレクトリ、隔離用の空の `APPDATA`・`LOCALAPPDATA` の実体とアクセス権、UI 環境、子プロセスの追跡方法を確認する。既存 fixture や資格情報は変更・削除しない。
2. 合成の stdout/stderr を吐いて終了する無害な子プロセスで捕捉方法を先に試す。大量出力、秘密らしい合成文字列、タイムアウト、終了コード取得を含め、上限超過や捕捉異常時は未確認扱いとし、秘密や本文が保存・表示されないことを検査する。実アプリを検査のために反復起動しない。
3. stderr は標準出力や未保護ファイルに流さず、上限を持って同時に読み取る。必要なカテゴリは事前定義の固定文字列との一致だけを記録し、未認識値・パス・ユーザー名・環境変数・トークン・自由文は出力しない。ソース位置を使う場合も、特定の許可済みファイルと数値のみを厳密に照合して扱う。一致しないものは不明と記録する。生データを保持する必要があればアクセス管理と保持期間を明示した保護先について別途適用権限を確認する。
4. 起動後のウィンドウ表示・継続とプロセス終了を区別する。想定外終了なら終了コード、固定カテゴリ、分類不能・切り詰めの有無を記録し、今回２回目の同種失敗なら追加起動せず中断する。停止の判定はその処理内の回数を用い、累計とは分ける。診断内容によっては１回でも停止が必要な場合がある。
