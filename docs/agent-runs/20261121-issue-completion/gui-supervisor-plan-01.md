# GUI 単発診断の監督方式案

目的は空の専用設定で現行 EXE を一度起動し、前回失われた stderr から許可済み分類だけを記録するとともに、ウィンドウの有無・生存・終了を区別すること。旧 `gui_diagnostic.py` は使わない。実 PAT、設定変更、Issue 操作は行わない。対象 EXE の SHA と現行ソース・ビルド証拠を実行前に照合する。

## 境界と不明時

| 境界 | 成功条件と不明時の扱い |
| --- | --- |
| fixture | 作業場所内の新規一意ディレクトリに APPDATA と LOCALAPPDATA を別々に作り、親からの再解析ポイント、空、実体とアクセスを確認する。実行中の同一ユーザーの書換えを ACL だけでは防げないため、他プロセスが触れない前提を記録する。検証できなければ起動しない。Credential Manager 自体は隔離されない。空設定・復旧記録なしの起動経路では資格情報操作しないことをコードと対象版で照合する。 |
| 予約・生成 | Windows Job Object を作成し kill-on-close を設定。子を suspended で生成し、Job 割当成功後だけ再開する。生成・割当・再開失敗時は対象を再開しない。保持するプロセス・スレッド・Job のハンドルで対象を識別し、プロセス ID の再利用だけを根拠に終了しない。 |
| 捕捉 | stdout は破棄し、stderr は匿名パイプを並行して読み、先頭 32768 bytes に限ってメモリに保持し、それ以後は破棄する。`gui_classifier.py` の固定分類のみ表示し、例外や API エラーも固定カテゴリに変換する。生データは出力・保存しない。上限超過なら不完全と記録する。 |
| 観測 | 再開後の限られた時間に直接の子の生存・終了を観測し、ウィンドウの有無は別手段で照合する。生存だけを GUI 表示成功とみなさない。待機には期限を設ける。 |
| 停止・終了 | 観測期限または中断時は Job 内の対象に終了要求し、直接の子の待機、Job の active count、パイプ回収を各期限付きで確認する。対象を特定できない場合、他プロセスを終了しない。終了・照会・パイプが不明なら未確認として fixture と情報を保持し、後続起動しない。親プロセスの異常終了時は kill-on-close に依存するが OS 障害・breakaway の無条件保証はしない。 |

## 実行前ゲート

1. この方式を独立レビューし、安全上の欠落を解消する。Win32 API 宣言・戻り値・ハンドル所有権と環境ブロックの扱いを確認する。
2. 製品の起動を無効にした合成試験で、正常終了、未認識・秘密風 stderr、出力上限、子孫のパイプ保持、時間切れ、監督者停止、生成・割当・再開・終了・照会の失敗を検証する。テストの出力全体が固定カテゴリのみであることを検査する。
3. 実装と試験を対象 SHA 指定で独立レビューする。未確認や失敗が残る場合は実アプリで実行しない。実行は１回のみとし、ユーザー指定の同種２回連続停止を優先する。

未確認: Win32 API と既存 sandbox の互換性、Job への割当、WebView2 子孫の挙動、空 fixture の競合防止、GUI の原因と提案の有効性。この文書は実行承認ではない。
