# F-081 発生1〜3の独立分析

担当 `/root/f081`。2026-11-21。依頼、保存された失敗記録、対象コード、引き継ぎと継承された操作結果を読み取りで照合した。Job 作成、プロセス起動、外部通信、既存ファイル変更は行っていない。これは修正版の承認ではない。

## 結論

発生3では、子を作らない確認が `win32job.CreateJobObject(None, None)` の呼出しを `TypeError` と分類した。発生1・2も同じ引数の呼出しを含み、共通要因の有力な候補だが、当時の例外種別は記録されていないため同一原因とは確定できない。今回の情報は OS の Job 作成権限が不足している証拠ではない。

## 確認事実と原因の確度

- 発生1の `job_list_probe.py` は `probe()` の最初に `CreateJobObject(None, None)` を呼び、後段で属性設定・子生成・Job 所属と終了を確認する。トップレベルは例外内容を捨てて `synthetic_job_list=failed` のみ出すため、引き継ぎにある終了コード1だけでは失敗位置も例外型も確定できない。モジュール初期化も `probe()` より前に行われる。
- 発生2の `job_capability_check.py` は `stage = "create"` の状態で同じ呼出しを試み、例外を固定段階だけで表示する。記録上 `stage=create` で失敗したが例外型は保存されていない。子を生成する処理は含まない。
- 発生3の `job-create-error-check.py` は同じ呼出しの `TypeError` と Windows 固有エラー等を分けて固定分類する。担当者の操作結果は `job_create=argument_type_error`、終了コード0であり、この終了コードは診断プログラムが正常終了したことを示す。Job 作成成功の証拠ではない。型エラーの詳細文字列・どちらの引数が拒否されたか・実際の Win32 呼出しの有無は記録されていない。
- 発生1・2の記録は同種失敗として保守的に中断したと記し、発生3も累計へ追加している。発生1の元の例外を後から復元・確定できない。再開後の１回と過去の停止判定を分け、ユーザーの２回連続停止条件を優先する。

## 残存プロセスと制約

- 発生1は `CreateProcessW` 成功後の `finally` で直接子の終了を試みるが、終了 API の戻り値や待機結果は記録しない。失敗位置が不明なため、元の実行で子生成に達しなかったとは断定できず、終了済みとも断定できない。発生2・3は子を生成しない。
- 継承された再開後の `synthetic-residual-check.py` による観測は、`python.exe` / `pythonw.exe` の引数が正確に `-c`, `pass` に一致する候補0、名前または対象のコマンドラインを取得できないプロセス1。観測時点の限定された一致結果で、アクセス不能の1件が何かは不明。Python 起動ラッパー、子孫、異なる引数の実行、観測時刻より前の終了はこの結果だけでは識別できない。CIM 照会も引き継ぎ上は不明。PID や名称だけで終了対象を推定しない。

## 既存ルールと具体策

`docs/instructions/work.md` は環境固有 API のメソッドの存在・前提を使用前に確認し、失敗時に安全な診断情報と未確認を区別するよう求める。既存 F-045 の API 確認と F-066 の予約・識別・親子孫の終了確認を今回のラッパー引数と例外経路にも適用する。

1. 利用中の pywin32 と Windows API を区別し、使用する版の `CreateJobObject` の引数型・匿名／名前付き Job の意味と戻り値・ハンドルの所有権を、一次資料と利用環境で確認する。環境制約を原因と決めつけない。
2. 次の診断はまず子を生成しない限定テストとして設計し、未知の例外は固定カテゴリとして扱う。型不一致、Win32 エラー、成功・ハンドルのクローズ結果を区別し、自由文・パス・識別子を出力しない。引数と期待結果を確認してから実行し、同種失敗の停止条件を適用する。
3. 発生1の残存可能性はその限定結果と切り離して扱う。実行時の子の正確な識別・終了証拠がない間は、未確認と記録して対象に無関係なプロセスを操作しない。後続の実アプリ起動は承認済みの停止・復旧計画と fixture の隔離条件を満たしてから行う。

F-081 は累計3件として、上記の事実・予防策と効果未確認を既存 `docs/recurring-lessons.md` に追加し、読み戻すことを推奨する。既存ルールの具体的適用であり、新たな一般ルール・Skill・改善 Issue の提案はない。正しい引数による成功、Job 所属、実アプリ起動、残存子の不在、再発防止効果は未検証。
