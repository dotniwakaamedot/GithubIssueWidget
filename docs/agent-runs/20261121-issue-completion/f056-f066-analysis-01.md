# F-056 発生3・4 と F-066 発生5 の独立分析

担当 `/root/failure_review`。依頼、失敗記録、レビューと対象スクリプトを読み取りで照合した。実アプリの起動、合成試験、外部操作は行っていない。対象版の合否再レビューではない。

## 結論

F-056 の２件は、診断出力として明示的に許可した固定値だけを出すという条件が、呼出し先の戻り値と例外経路まで適用されていなかった。F-066 は、観測期限後の待機と監督者中断を含むプロセス・パイプの終了を確認する設計が欠けていた。いずれもレビュー上の指摘で、実環境での情報漏出やハングは確認されていない。

## F-056 発生3・4

- 確認事実: `gui_diagnostic.py` の `diagnose` は `gui_probe.classify` の辞書を出力に含める。同関数は `os error` に続く任意の１〜５桁の数値を整数として返す。また、トップレベルには `Popen` 等の予期せぬ例外を固定カテゴリに変換する処理がない。レビューの指摘とコードは一致する。実アプリや秘密を使用した対象版の実行、漏出の発生は未確認。
- 原因の確度: 固定値リストで追加項目を分類していても、継承した分類全体と異常終了経路が同じ制約を満たすか確認できていなかったことはコード上の直接要因である。設計・レビュー時の見落としが生じた理由は不明。既存の合成試験は典型的な秘密文字列の非出力を確認するが、任意の数値や例外経路の全出力は検査していない。
- 既存ルール: `docs/instructions/work.md` は秘密を含み得る出力を安全な項目に限定し、例外全文を出さないことを求める。修正版は外部値や例外から固定の enum のみを生成し、未知・複数・切詰めは固定カテゴリとして扱う。外側を含む出力全体を対象に、秘密風の数字・文字列、既知値と未知値、複数一致、切詰め、例外を合成検査する。実値や例外全文は保存しない。継承関数とログ・traceback・終了経路を同じ範囲でレビューする。

## F-066 発生5

- 確認事実: `capture` は８秒で `None` を返し得るが、呼出し側はその後 `process.wait()` を期限なく呼ぶ。直接の子の終了と、子孫が保持するパイプの EOF は別の事実であり、監督者停止時の終了確認経路も示されていない。これはレビューの設計上の指摘であり、実際の停止不能・OS 障害は観測していない。
- 原因の確度: 各待機の期限と終了根拠を設計上つなげていないことは対象コードで確認できる。なぜ既存の F-066 対策が適用されなかったかは未確認。
- 既存ルール: `work.md` の監督プロセスの境界・不明時の禁止事項・終了証拠と、`recurring-lessons.md` の F-066 を適用する。起動・観測・停止要求・親子孫の終了・パイプ回収・監督者中断を分け、各待機上限、失敗・不明時の記録と禁止操作を定める。通常終了、期限超過、パイプ保持、監督者中断、終了・照会失敗を合成障害で検証し、対象版を独立確認する。終了の根拠が不明なら実アプリでの利用を保留する。OS 障害や breakaway に対する無条件の終了保証は主張しない。

## 判断・未確認

新たな一般ルールや Skill の提案はない。既存の秘密非出力・監督ルールを呼出し先と例外経路を含む実行全体に適用し、F-056・F-066 の各教訓に今回の事実と具体的適用、効果未確認を反映して読み戻すことを推奨する。空の fixture でも Credential Manager 自体は隔離されないため、別途その実体・アクセスと起動処理の条件を確認する。GUI 失敗の原因、修正版の安全性、再発防止効果は未確認。
