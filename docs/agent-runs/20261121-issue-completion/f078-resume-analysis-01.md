## 確認事実

- 発生4は記録上、隔離設定の同じ release EXE が終了コード101で終了した。捕捉された標準エラーは上限超過なし、固定文字列分類で panic と WebView2 が真、`failed to run widget` と `Access is denied` は偽、`os error` 数値は一致なし。本文は保存されていない。`handoff-gui-stop-02.md` と `docs/failure-log-001.md` が根拠。
- `gui_probe.py` は標準出力と標準エラーを別スレッドで読み、それぞれ先頭32768バイトを保持し固定文字列を照合する。終了後に捕捉スレッドの終了を確認する。既存の合成試験は大量出力・合成秘密・終了コード・単純なタイムアウトを扱うが、すべての秘密、孫プロセスや OS 障害を対象にした証拠ではない。
- `main.rs` の `main()` は Tauri の `.run(...)` に `.expect("failed to run widget")` を付ける。この固定文字列が検出されなかったことは、その文字列を含む stderr が捕捉されなかった証拠であり、panic の場所や原因を示さない。WebView2 の文字列の存在だけでは失敗箇所、原因、製品と環境の責任を決められない。
- `settings_path()` は `APPDATA` 配下を使う。APPDATA と LOCALAPPDATA の変更は Windows Credential Manager の別ユーザーストアへの隔離を意味しない。起動時のフロントエンド処理を含め、資格情報へのアクセスを伴わないことは実行経路ごとに検証が必要。
