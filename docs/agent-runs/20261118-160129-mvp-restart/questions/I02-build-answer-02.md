# I02 B03 lockfile 調査の回答 02

- 宛先 `/root/build_verification`。質問 `questions/I02-build-question-02.md` の、lockfile 読取り失敗2回に対する回答。旧質問と失敗記録は保持する。
- `/root/lock_failure_review` による独立調査を親が受領。package-lock の packages に空文字キーがあることは確認されたが、PowerShell の変換失敗との因果は未確定。代替 Node コマンドは引用符が失われたとの担当報告がある。失敗した2コマンドは再実行しない。
- 管理判断: 既存の build-verification-request-01.md の所有範囲と事前確認を維持し、親・scratch の正規化先、既存との非重複、リンク・権限・空き容量、対象 lockfile の実在・固定版 SHA、Node 実行ファイルの存在・版を確認後、担当専用の scratch を新規作成してよい。衝突・不明なら作成せず停止する。
- lockfile 調査は、シェルへ JavaScript を埋め込まず、scratch 内の新規 UTF-8 `.js` ファイルに明示的な `try/catch`、`JSON.parse`、想定構造の型検証を記述し、`node <scriptの絶対パス> <lockfileの絶対パス>` で実行する案を使用する。入力とスクリプトの基点・パス・存在・SHA256 を実行前に確認し、終了コード・必要な構造の要約・例外の種類を専用 evidence に記録する。資格情報や環境変数全体、不要なファイル内容は記録しない。
- この回答は lockfile 解析のための安全な手順であり、依存導入・build/dev を無条件に許可するものではない。解析結果と script・入力・出力の SHA、終了コード、未確認を管理へ通知し、その後の判断を待つ。対象が不明、想定外の副作用、失敗や結果不明なら後続操作を行わない。
- 同じ lockfile 読取り問題は2回発生して独立調査済み。今回3回目の同種失敗が発生したら全作業を直ちに中止し、親へ通知する。他の同種問題も初回を含む2回で該当操作停止・独立調査、3回で全停止。過去のドラッグ・文字破損経路は再試行しない。
