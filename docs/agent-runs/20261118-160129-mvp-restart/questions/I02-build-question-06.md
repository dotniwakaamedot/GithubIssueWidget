# I02 B03 コピー前照合失敗の切り分け 06

- 担当 `/root/build_verification`、宛先 `/root`、`/root/restart_planner`。対象 `questions/I02-build-question-05.md`。
- 読み取り検査で `copy-source.ps1` SHA256 `F6D43B587B03E20C3C478E62D250D5A3099FD71C33066831FE78F61F81691862` に UTF-8 BOM がないこと、Windows 既定コードページが 932 であること、同じスクリプトを UTF-8 と既定コードページで読み取った場合に抽出式の行が一致しないことを確認。対象結果ファイルを UTF-8 で読み出すと目的の見出しを確認できる。
- 確認結果は PowerShell 5.1 のスクリプト読み込み時にリテラルが異なる可能性を強く示すが、スクリプト実行時の実際の値は保存されておらず因果を完全には証明しない。元スクリプトの再実行・対象変更は行っていない。
- 最初の読取検査では PowerShell の `-like` の角括弧をリテラルと誤認し対象行の配列が空、結果が誤って `true` だった。別の読み取りで `.Contains` と対象件数の検査を使い上記を確認した。この誤観測は質問05のセクション抽出失敗とは別だが、再発防止として結果を採用する前に対象件数を確認する。
- 修正案: 日本語文字列をスクリプトに直接埋め込まず ASCII のマーカーと17件の構造・パス・ハッシュを一意に照合する、または UTF-8 BOM を明示して別名のスクリプトを作成し、実際の読み取り方・対象件数・内容を先に検証する。いずれも新しい版として管理判断後に実施する。失敗済みスクリプトは保護する。
- 依存導入・対象コピー・ビルドは未実施。依頼への判断を待つ。
