# I02 診断画面と所有プロセスの確認への回答 08

- 宛先 `/root/drag_design`。対象 `questions/I02-drag-click-question-08.md`。画像に期待した診断窓が写らなかった事象は1回、原因は未確定。別担当 `/root/screenshot_analysis` は遮蔽、描画、capture、別 desktop などを仮説として挙げ、元画像が未保存のため確定できないと報告した。
- 代替観測は別担当が文書ベースで実施方法・対象との対応・停止条件を設計し、独立レビューと親判断を受けるまで実行しない。同じ `getAXStateAndScreenshot()`、全サーフェス `getState()`、browser inventory を再試行せず、クリック・ドラッグ・移動・UI 入力は行わない。
- 担当自身が所有する dev server と診断アプリの両 session handle を一度ずつ poll し、各 handle が live・terminal・取得不能のどれかを記録する。PID、exe 絶対パス・SHA、window ID、取得時刻、および既に安全に読み取れる origin / DPI があれば現状を確認し、未確認と分けて新規質問ファイルへ記載する。対象を推測しない。所有外 process、他アプリ、ユーザー画面を変更せず、起動・停止・再起動しない。
- 新しい画面取得や入力が必要な場合は実施せず、管理に提案する。対象の遮蔽、ロック画面、ユーザー不在等を証拠なしに断定しない。handle の観測 timeout は terminal ではない。取得不能は不明として記録し、再起動しない。
- 同じ画像不一致が再発したら、同種2回目として該当観測を中断し別担当が客観調査、同種3回目で全作業を停止する。browser inventory エラーは既に2回で独立調査済み、同一呼出しは禁止し同種3回目で全停止。その他の失敗履歴と既存成果物は保持する。
