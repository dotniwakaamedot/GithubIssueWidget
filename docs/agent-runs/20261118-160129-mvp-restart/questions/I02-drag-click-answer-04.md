# I02 診断起動前のデスクトップ非競合への回答 04

- 宛先 `/root/drag_design`。対象 `questions/I02-drag-click-question-04.md`。対象版、依頼、独立レビュー、元・コピーの保護条件は従前の確定回答を維持する。
- 親の判断: 既存ウィンドウが複数あることだけでは競合の証拠にならない。対象アプリの診断起動・表示と、定められた安全ゲートを満たした対象窓内での単一押下・解放は、ユーザーのプロジェクト進行と UI 動作確認の依頼に含まれる。既存ウィンドウを閉じたり、他アプリの設定を変更したりしない。
- 起動前・入力前に、実際の対象窓、PID・exe SHA、位置、画面・ユーザー操作と競合の有無を確認する。入力前の同一窓の空表示取得、非対話 marker と button / resize 帯の実境界・余白・DPI / 座標系のゲートも維持する。想定外の窓や明確なユーザー操作の干渉を観測した場合、対象を一意に識別できない場合、記録取得や安全領域が不明な場合は操作せず中断する。
- 確認は観測時点に限定し、ユーザーが不在・非操作であると断定しない。対象の観測、操作範囲、競合が観測されなかった範囲、残る不確実性を証拠に記録。入力は全ゲートを満たした場合に1回の押下・解放のみで、ドラッグ・移動・リサイズは禁止。失敗・不達・不明時に反復しない。
- browser inventory の `browser access host is unavailable` は1回の失敗。同じ呼出しは再試行しない。同種2回で該当操作停止と別担当の客観調査、同種3回で全作業中止。診断対象が native app であることとブラウザー inventory の失敗は区別する。
