# 共有 run 証拠の安全な公開方法案 01

## 判明事項

- 独立担当 `/root/path_failure_review` は、質問 `I02-build-question-01.md` と `tasks/I02/evidence-geometry-01/observation-01.json` の2件が、同じ共有 run の確定名に .tmp を経ず直接書き込まれた手順逸脱に当たると分類した。部分読取りや破損の発生は確認されず、各逸脱の原因は未特定。両ファイルは保持し、書換え・削除しない。
- 同種の直接公開は今回2件。該当する直接公開操作を中断して客観調査済み。同種3件目が発生したら全作業を中止する。

## 共通の公開手順

1. 管理が書き手・所有する絶対親ディレクトリ・確定名・一時名・形式・必要な参照版を指定する。対象親と上位の所有・正規化先・リンクの有無を確認し、他人の領域や基点外への書込みを避ける。
2. 親が存在し、確定名・同じディレクトリの一時名の双方が未存在であることを確認する。既存物は上書きしない。状態が不明・競合する場合は停止し担当に質問する。
3. 一時ファイルを新規作成専用の方式で開き、UTF-8 等の合意済み文字コードを明示して書き、書込み・flush・close の成否を確認する。失敗したら確定名への rename や後続作業を行わない。
4. 一時ファイルを再読込みし、文字コード・内容の一致、対象版・必要項目、JSON なら構文と要求する構造・件数を適切な parser で確認する。利用できない parser や未確認のコマンド・以前失敗した引用符や空キー処理を推測して使わない。結果0件や不明を成功扱いしない。検証内容と限界を証拠に記す。
5. 内容が適合し、確定先が引き続き未存在の場合のみ、同一ディレクトリ内で既存確定物を置換しない rename を行う。確定後に内容・構造・SHA256 を再照合し、必要な対象版と作成者を記録してパスのみ通知する。rename や読戻しが不明・失敗なら完了扱いせず、現存物を保護して管理へ報告する。
6. この確認や rename は他環境との排他ロックではない。実施時点の競合と版変化を監視し、競合・所有不明を検出したら停止する。一時ファイルも勝手に削除せず、所有と保存を確認する。検証はデータの意味や実機での正しさの独立レビューを代替しない。

方式は進行管理による提案であり、既存の規約や user の権限を拡張しない。実作業への適用前に独立レビューと親判断を受ける。同じ問題2回で該当操作を中断して別担当に客観調査し、3回で全作業を中止する。
