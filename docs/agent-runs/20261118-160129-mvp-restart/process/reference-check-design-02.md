1. 依頼の担当 ID・作者 ID・所有範囲・出力先・権限・参照の基点と相対パス・履歴の分類と回数・停止閾値・ユーザー原文を、単一の構造化データに入れる。担当 ID は実際の割当と照合し、ユーザー原文は加工しない。
2. 出力先の親ディレクトリが存在し、確定先と同一ディレクトリの一時ファイルが共に未存在であることを先に確認する。既存ファイルの上書き・他担当領域の利用はしない。
3. 各参照は基点、相対パス、注記、SHA を別項目として扱う。指定された基点自体を確認し、正規化した絶対パスが意図する基点内に収まること、基点から対象まで再解析ポイント・リンクの有無と所有・参照先を検証する。基点外、想定外リンク、所有不明、実在・通常ファイルを確認できない場合は停止し、推測パスを使わない。全件の存在と種類を確認してから実体 SHA256 を取得し、64桁を検証する。
4. 確定文書の担当・パス・ハッシュ・履歴・閾値は、同じ構造化データから固定フィールドとして生成する。検査は担当割当、出力先、パス解決、ファイル状態、SHA、履歴・閾値、UTF-8 を個別に診断し、自由文の表現や曖昧な部分一致に依存しない。不整合なら項目と原因を記録し、依存する書込み・送信・起動を中断する。必要な根拠以外の秘密・個人情報を表示しない。
5. 一時ファイルを公開前に構造化データと照合し、同ディレクトリで確定する。確定後、固定フィールド・UTF-8・参照実体と SHA を再照合する。担当起動の直前にも ID、参照版・SHA、出力先の状態、既存担当の停止・所有範囲を再照合し、変化・所有不明なら停止して新版を発行する。
6. 上記の照合やファイル名の確定は排他ロックではなく、確認後の同時変更や他環境の競合を完全には防げない。利用可能な共有ロックは別途維持し、競合が判明したら作業を止め成果を保護する。確認前後の一致も中間変更がなかった完全な証明ではない。
7. 自由記述の仕様・権限・完了条件・安全性・残リスクは元資料と独立レビューで判断する。構造・ハッシュの一致を仕様承認や実機検証の成功と扱わない。方式自体と、その適用依頼は独立にレビューする。
