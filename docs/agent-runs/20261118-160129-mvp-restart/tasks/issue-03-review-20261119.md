## 指摘

### B01: 保存途中の終了や複数プロセスで設定とトークンが食い違う

- 根拠: `widget/src-tauri/src/main.rs` の `save_connection` は108行で共通の Credential Manager エントリを上書きし、110行で設定を保存する。その間にプロセスが終了すれば、復元コードは実行されず、旧 owner/repo に新トークンが対応した状態が残る。89〜92行の再起動時の読込みは、組の整合性を検査せず `has_token` の有無だけを返す。17〜18行の mutex はプロセス内にしか存在しないため、複数アプリ起動時に互いの書込みを直列化しない。
- 影響: Issue #3 の保存途中の失敗で以前の設定を守るか不整合を明示する条件、および再起動後の整合した接続先の取得を保証できない。たとえば新トークンの書込み後・設定置換前の異常終了で、画面は旧接続先と保存済みトークンを表示し得る。複数起動時にも設定とトークンの組が混ざり得る。これはコード上の障害経路の分析であり、実機で異常終了を再現したという意味ではない。
- 修正案: 書込み段階で旧設定に対応する資格情報を上書きしない世代別の資格情報と、アトミックに切り替える設定参照などで組のコミット点を設計するか、起動時に検出・復旧できる安全なトランザクション記録を用意する。複数プロセスを排他するか明示的に防ぎ、異常終了・保存失敗・競合を偽資格情報と隔離された設定先で検証する。

### B02: 保存失敗・不整合の通知が無関係なウィンドウ操作で消える

- 根拠: `widget/src/main.tsx` 27行は保存失敗や復元失敗を共通の `error` に表示する一方、36〜37行の `run` は成功した任意の操作の後に `setError("")` を行う。44行のタイトルバードラッグや最前面切替も `run` を利用する。
- 影響: 資格情報復元失敗後、ユーザーがウィンドウを移動または固定操作しただけで、設定と資格情報の不整合を示す警告が消える。さらに復元失敗時は `hasToken` が再読込みされず、UI が以前の状態を示す可能性がある。これらはソース上の制御フローであり、GUI 実行による再現は未実施。
- 修正案: 設定のエラー・不整合状態とウィンドウ操作エラーを分離し、再取得・修復または明示的な確認まで不整合を保持する。保存失敗後は実際に分かる範囲で設定・資格情報の存在を再取得し、不能なら不明と示す。成功した他の UI 操作で消えない回帰テストを設ける。

### B03: 要求された安全性・異常系の検証が不足

- 根拠: 現在の Rust テストは `validates_repository_components` と `replaces_settings_without_saving_a_token` の2件。依頼による `cargo test --locked` 2件成功は作者報告であり独立した実行証拠はない。実 Credential Manager、認証・接続失敗、保存失敗・復元失敗、トークン変更・削除・再起動、フロントエンドへの非返却・ログの確認は未実施と依頼に記載される。
- 影響: Issue #3 の完了条件は検証できていない。成功テスト2件では認証情報の非露出や失敗時の整合性を示せない。
- 修正案: 環境依存を分離した模擬 Credential Manager と HTTP 応答・書込み障害のテストを追加し、ユーザーの既存資格情報を保護した Windows 実機環境で初回・更新・削除・再起動と障害時の確認を行う。対象版、終了コード、証拠と未確認を記録する。
