## R01: 孤立したトークンが残り、後の削除・再起動で把握できない（blocking）

- 根拠: `widget/src-tauri/src/main.rs` の `commit_settings` 81〜90行では新しい Credential Manager エントリを保存してから設定の参照を書き換え、最後に旧エントリを削除する。新エントリ保存後・設定書込み前に終了すると新エントリが、設定書込み後・旧エントリ削除前に終了すると旧エントリが残る。設定には現在の `credential_id` 一つしかなく、`connection_info` 158〜163行もその ID だけを読む。`delete_token` 192〜200行も現在の ID だけを削除する。切替後の旧削除失敗時にはエラーを返すが、孤立 ID を設定や復旧記録に残さない。UI は後の保存または削除成功時に `setError("")` を呼ぶ。
- 影響: 中断や削除失敗後も過去または新たな PAT が Windows Credential Manager に残り得る。再起動後の画面は残存の事実を認識できず、現在の ID のみ削除した場合でも「保存済みトークンを削除しました」と表示し得る。Credential Manager に孤立した秘密が残る経路はコードからの推論であり、実 Credential Manager で再現したものではない。
- 修正案: 異常終了前から各世代を復旧可能な形で記録し、秘密値自体を平文に残さず再起動時に未参照の自アプリ資格情報を検出・安全に清掃または具体的に報告する。削除完了・警告解除の条件を残存世代と結び付け、各中断点・保存／削除の失敗・再起動と複数プロセスを隔離された模擬環境と Windows 実機で検証する。
