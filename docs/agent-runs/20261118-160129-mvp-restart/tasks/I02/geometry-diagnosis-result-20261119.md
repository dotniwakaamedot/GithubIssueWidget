# 座標取得エラーの独立調査結果（2026-11-19）

- 担当: `/root/geometry_diagnosis`。依頼: `geometry-diagnosis-request-20261119.md`。対象製品と既存証拠は読み取り専用。
- 結論: **2件とも Computer Use の入力時に同じエラーメッセージが観測されたが、根本原因は特定できない。** ウィンドウやボタンの表示・アクセシビリティ取得が成功したことは、入力座標が取得できることやアプリの閉じる機能の成否を証明しない。

## 確認した事実

1. `evidence-02/method.md` と `result-02.md` では、過去にブラウザが前面にある状態で閉じる操作を行った際、`coordinate input geometry is unavailable` が1回発生し、対象の再選択・前面化と新たな観測の後に閉じる操作が成功したと報告されている。元の個別入力ログ・対象座標・内部処理は確認できないため、前面化が原因を解消したと断定できない。
2. 今回は親の実行結果によれば、`list_windows` から対象の exe パス・タイトルで一意に絞った対象を `get_window` で取得し、`get_window_state` のアクセシビリティにある閉じるボタン index 20 を `sky.click` に指定したところ、同じメッセージが返った。直前の取得は `include_screenshot:false, include_text:true` であり、画面の画像・対象要素の座標は観測していない。API がこの構成で座標を得られるかどうかは本資料だけでは不明。
3. 同梱 `docs/api.md` は `click` に最新のアクセシビリティツリーの index を渡せること、入力メソッドは対象ウィンドウを自動的にアクティブにすることを記載する。`activate_window` は任意の前面化手段とされる。上記エラーの条件や、対象要素の座標を内部でどのように取得するかは記載されていない。
4. `docs/guidance.md` は入力・再観測の順序、古い index・座標を再利用しないこと、および他ウィンドウ上への入力と報告された場合の再観測手順を示す。今回のエラーは、その「他ウィンドウ上への入力」という明示報告と同一とは確認できない。

## 仮説と次の対応

- 対象の前面・遮蔽、アクセシビリティ要素の矩形、ウィンドウの DPI や座標変換、ヘルパー側での geometry 取得などは候補だが、今回の記録ではいずれも確定できない。
- 当該クリックの結果はエラーであり、実際に入力が届いたか、アプリが終了したかは別途確認する必要がある。古い PID・ウィンドウ ID を現存の証明に使わない。
- 次の操作は親が所有者・対象・実際の状態を再確認し、既存の画像不一致やブラウザ inventory の失敗歴も考慮して判断する。同じクリックを漫然と繰り返さず、対象に限定した新しい観測、または別途妥当性を確認した代替手順を検討する。前面化は公式に提供された操作だが、今回の原因が前面状態と判明したわけではなく、成功の保証もない。
- ユーザーの指定に従い、この独立調査の後に同種の失敗がさらに2回発生した場合は停止する。調査中に同種の試行は行っていない。

## 実施範囲と教訓

依頼、過去の結果と method、ローカルの Computer Use API・guidance を読み取った。UI 操作、アプリ起動・終了、外部通信、製品・既存証拠の変更は行っていない。独立した過去の入力ログ、現時点のウィンドウ状態、内部例外と要素矩形は未確認。

1. アクセシビリティにボタンが表示されても入力に必要な geometry の取得成功を意味しないため、入力エラー時は結果を成功扱いせず、最新の対象・表示状態と原因候補を切り分ける。
