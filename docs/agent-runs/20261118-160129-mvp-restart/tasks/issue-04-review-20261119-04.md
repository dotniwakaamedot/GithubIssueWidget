## 残る制約・改善候補

1. 非 blocking: `record_cooldown` で共有ファイルの保存に失敗した場合、その process 内の `AtomicU64` は更新されエラーが返るが、他プロセスがその期限を読める保証はない。`rate-limit.json` の読書き失敗や期限記録中の異常終了、時計変更時の実挙動は未検証。共有抑止を保証できない状態を説明し、障害注入と再起動を含めて対策を検討する。
2. 非 blocking: 二次制限が繰り返された際、現実装は新たな応答ごとに `Retry-After` または既定60秒等から期限を計算するが、連続回数に応じた指数的待機・回数上限は持たない。GitHub の [レート制限の説明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) が案内する継続制限時の待機延長との整合を、実 API を濫用しない模擬テストで確認する。HTTP-date 形式の `Retry-After` も未検証。
3. 非 blocking: pagination は検証済み repository ID、許可 host/path とカーソルを持つ next URL、訪問済み URL と上限を用いる。作者の公開リポジトリ2ページ目 smoke は直前のページ処理版の報告であり、本版の実 PAT、対象リポジトリの全ページ完走や取得中の同時変更時の一貫性は未検証。重複の除去だけで欠落がないとは判断できない。
