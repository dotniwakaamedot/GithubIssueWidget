## R01: 別操作の確認記録を読んだ場合、直前の作成済み Issue を表示しない（blocking）

- 発生し得る順序: ウィンドウ A が Issue を作成して結果を受領後、A の `pending_creation` 再読込より先にウィンドウ B が A の記録を確認・消去し、別の Issue を作成して新しい確認記録を保存する。A がその別 ID を読むと、不一致エラーは表示されるが、A が受け取った作成済み番号・元リポジトリは隠れ、B の記録だけが表示される。`create_issue` と `pending_creation` は別 IPC 呼出しであり、`creation.rs` 36〜47行と138〜149行のロックはそれぞれの呼出し中にしか保持されないため、この区間を一つの排他操作としては保護していない。
- 影響: 失敗時・部分失敗時に判明済み Issue を表示する Issue #5 の条件が、確認記録の**不一致**で成立しない。別の記録だけを表示すると、ユーザーが直前の作成結果と混同するおそれもある。上記は複数プロセスと UI の静的な制御フローに基づく障害経路で、実機でその時系列を再現したとは主張しない。前回 B02 の「判明済み番号が隠れる」という同じ完了条件が未解決であることを管理へ通知する。
