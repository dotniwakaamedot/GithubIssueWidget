## Blocking B01: `rel` に複数の値がある next を終端と誤認する

`parse_response` は `rel` の値が文字列として正確に `next` でなければそのリンクを無視する。例えば他の検証条件を満たす URL に `rel="next last"` が付くと、`next` を含むにもかかわらず `next_page` が `None` のままになり、`collect` はページ探索完了・一致０件を返し得る。実際の GitHub 応答でその形式が発生したという事実はなく、今回の実ヘッダーも保存されていない。だが異常または想定外の継続情報を終端と誤認しないという前回 B01 の完了条件を、現在のコードと合成８件では証明できない。

修正案: relation のトークンを解析して `next` を認識するか、対応しない複数値を安全に拒否する。`rel="next last"` と `rel="last next"`、next が複数回ある場合、正しく next を含まない link を合成試験し、途中失敗・不正なら成功扱いしない。再取得と実書込みは今回のレビューに含まれず、ユーザーの停止条件を優先する。
