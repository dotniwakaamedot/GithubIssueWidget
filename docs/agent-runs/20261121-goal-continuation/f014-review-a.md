# F-014 再発の独立分析 A

- 担当: `/root/failure_a`。進行上の再発防止を検討した。元のパッチは再実行せず、アプリの合否は判定していない。
- 事実: `docs/failure-log-001.md` の発生7では、実際の見出しを確認せず想定した見出しをパッチのアンカーに指定した結果、検証で拒否され、変更は適用されなかった。発生6でも同様に見出し未確認による拒否が記録されている。過去の対象版・完全な前後ハッシュやツール内部処理は未確認。
- 評価: 今回の記録はアンカーの事前未確認を示す。なぜ既存の教訓が実施されなかったかの心理的・手順上の原因は証拠から特定できない。`docs/recurring-lessons.md` には直前の実ファイルでアンカーの内容・順序・一意性を確認する対策が既にあるが、２度の実行に適用されなかったため、記載の存在だけで再発防止は証明できない。

## P01: パッチ適用直前のアンカー確認を明文化する

- 優先度: 高。根拠は F-014 発生6・7。次担当: パッチを作る各担当と進行管理。
- `AGENTS.md` の追記案: 「既存ファイルへのパッチは、適用直前に対象パスと変更箇所の現行内容を読み、使用するアンカーの正確な文字列・順序・一意性を確かめてから作成する。並行編集または適用拒否があった場合は現行内容を再確認する。未確認の見出しを推測で使用しない。失敗回数の集計とユーザーの停止条件を優先する。」
- 効果: 想定と現行版の不一致による拒否を減らす。費用: 読取り・確認の時間。リスク: 読取りと適用の間に他者が変更する可能性が残り、事前確認を排他保証とみなせない。
- 効果確認: 次回の既存ファイルへのパッチで直前確認の対象箇所と適用結果を記録し、文脈不一致の発生を観察する。一回の成功だけで長期的な効果は証明しない。

Skill 提案なし。既存の作業手順と教訓の具体化であり、専用 Skill の追加が必要な根拠は確認できない。P01 の採否・反映と Issue 登録時の権限確認は管理者が判断する。
