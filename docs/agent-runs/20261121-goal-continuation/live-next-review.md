## 優先する次作業

1. **blocking：実行制御の設計と独立レビュー。** Job・監視プロセス・起動直後から保持する対象ハンドルの所有者、生存確認、OS 呼出し停滞、監視消失、登録・再開・終了・close 失敗時の状態遷移と復旧手順を定義する。同期 OS 呼出しや監視自身が停止する場合は時間上限・終了を無条件保証できないことを明記し、そのとき後続書込みと再起動を禁止する。対象ハッシュと設計版を固定して再レビューする。
2. **blocking：偽データだけの合成検証。** 最小環境・ローカル通信だけの専用試験で正常・タイムアウト・中断・各 API 失敗・監視消失・子孫や breakaway の挙動とログのダミー秘密非露出を試験する。親終了コード、プロセス固有の保持ハンドル、終了の独立観測を分け、実 OS 障害と模擬戻り値、制限下の列挙と本体の実行を混同しない。試験対象と証拠は SHA で固定し、未検証は残す。
3. **blocking：不明結果の復旧と重複防止。** 一度だけの実行予約と POST 前後の状態記録を合成試験で確認し、結果不明時は process/Job の停止を証明できるまで書込みを禁止。停止後も全ページでマーカー・対象番号・状態を照合し、POST を自動再送しない。識別不能なら保留する。実 Issue 作成や変更は独立レビューと承諾範囲の再照合後のみ。
4. **blocking：実対象への適合と秘密。** 固定した Rust 試験本体と `gh auth token` について、子生成や認証ヘルパーの必要性を秘密を取得せずに調べる。実体・バージョン・設定ごとの不確実性を明示し、単一プロセス Job が適さない場合は設計を見直す。トークンや応答生データはログ・ファイル・コマンド引数へ出さず、例外・後片付けでも同様に扱う。
