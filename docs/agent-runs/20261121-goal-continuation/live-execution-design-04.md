# 実 GitHub 検証の実行方式案 04

状態: 提案・未実装・未承認。外部書込みを有効にしない。ユーザーが承諾した対象、固定マーカー、Issue １件、非ステータスラベルの保持、各移動後の検証、既存 Issue 保護と秘密管理は `../20261120-current-review/live-plan-02.md` を変更しない。

## 原則

- 書込みの開始前に一意な予約を永続化する。予約は一度でも作成されたら、成功・失敗・不明を問わず同じ POST を再実行しない。予約と検証結果のデータにはトークン、API 本文、非公開情報を含めない。保存障害や未確認は後続書込みを禁止する。
- 外側監督者と書込み実行子を分離し、実行子は起動直後からハンドルを保持したうえで Windows Job に登録・再開する。単一プロセス制限を適用する案は、対象バイナリの実行経路が実際に適合すると合成データで確認できる場合に限る。`--list` の成功はテスト本体の証拠にならない。
- 制限時間内に正常終了・管轄 Job が空であること・保持したプロセスハンドルの終了をそれぞれ確認できなければ、`unknown` とする。強制終了・Job 操作・照会・ハンドル操作の失敗や同期 API が停滞する場合も `unknown` とし、後続書込みと自動再起動を禁止する。OS 障害時に時間内に停止できることやリモート側で処理が完了しないことは保証しない。
- 実行子が終了しても、既に送られた要求のサーバー処理が未完了である可能性を区別する。結果が不明な POST は自動再送しない。監督者の停止・死亡、プロセス識別不能、Job 終了不明のどれかが残る間は外部書込みを再開しない。

## 状態と復旧

1. `reserved`: 読取り専用の対象・権限・ラベル・全ページ確認が成功した後、排他的に予約を作成する。予約の保存・読戻しが失敗すれば終了する。競合作業はローカルだけでなく GitHub 側も確認し、別環境との完全排他を主張しない。
2. `started`: 実行子を停止状態で生成し、PID に加え OS の生成時刻等で対象を識別できる値を安全に記録する。Job 登録と状態の永続化が成功しなければ実行を再開しない。どこかの状態の記録が不明なら `unknown` とみなす。
3. `running`: 実行子が固定対象を再確認し、テスト用 POST を最大１回だけ送る。後続の移動前に毎回対象番号・マーカー・状態を読戻し、不一致や応答不明なら止める。トークンと API 応答は子環境とメモリーに限定し、標準出力・例外は固定の非機密結果に変換する。
4. `finished`: 親と Job が終了し、各ステップの固定結果と終了コードを照合し、最後に GitHub 上の実状態が期待どおりと確認できたときのみ記録する。ステップの不足、部分成功、確認失敗はいずれも `unknown` または明示した未完了とする。
5. `unknown`: ローカル予約を残し、処理が動いていないことを PID 再利用を区別できる証拠で確認する。識別・停止が確認できない場合は復旧を保留する。停止確認後もマーカーの全ページ照合と既知番号の個別読戻しを行い、結果と未確認を記録する。POST を再送せず、後続操作の可否は状態とユーザーの停止指示に従う。

## 検証と未解決

- 偽トークン・ローカル合成データのみで、予約失敗、子生成・Job 登録・再開の失敗、監督者停止、通常終了、期限超過、kill・照会・close の模擬失敗、標準出力に偽秘密を含む場合、子孫・breakaway、重複 POST の拒否を検証する。模擬エラーを実 OS 障害の証拠としない。
- 生成時刻を使う識別の API、永続化とクラッシュ時の耐久性、監督者自身の強制終了時の Job ハンドルの生存、パイプと出力サイズの制限、複数端末の競合は未実装・未検証。認証用 `gh auth token` のプロセス構成と秘密保護も未検証。
- 具体的な設計・実装・テストの対象 SHA を固定し、独立レビューを受ける。既存 `run-live.py` の無条件停止は、検証とレビューが完了するまで維持する。停止条件発生時はユーザーの指示を優先する。
