## 確認と原因の確度

1. F-001: 既存分析によれば、複数結果とツール説明の一括表示と、長い JSX 行を含む検索の表示で切り詰めが発生。行数制限はバイト数・トークン数を保証せず、複数結果も合算される。欠落内容と上限を適用した層は未確認。現行 `AGENTS.md` は合計量・行長・内外上限の考慮を求めるが、守られたことを確認する具体的手順は不足する。
2. F-073: 2ログとも同一合成試験の親プロセスが期待の0でなく1だった。2回目の stderr は `uv trampoline failed to spawn Python child process`、`os error 1816`。単一プロセス制限とランチャー内部の子生成が干渉した可能性はあるが、この記録だけでは因果関係を確定できず、Rust / gh の実行構成や breakaway の防止は証明されない。
3. F-016: `state-review-02.md` の担当は Issue 番号をタイトル検索語にして空結果を得た後、番号による直接取得で Issue #5 を確認したと記録。タイトル検索に番号を指定したことが誤った探索条件であるのは報告上の事実。検索索引や connector 内部の動作は未確認。過去累計は照合途中で確定しない。

## ルール追記案

- F-001: 説明の大量列挙を避け、まずツール名だけを限定し、必要な定義だけ取得する。検索では、長行や複数結果があり得る場合、まず行番号・件数・最大行長等の短いメタ情報を取得し、結果を個別に適切な範囲で読む。取り出し対象は必要な範囲に限定し、切り詰めを確認したら欠落を証拠としない。機密があり得る出力の保存は別途保護条件を確認する。後続の結果で効果を観測し、既存対策として実施しただけで防止済みとしない。
- F-073: Job 等のプロセス数・子生成制限を使う試験は、制限適用前に実行ファイルの実体・起動ラッパーと予想される子プロセス構成を特定する。合成試験を用い、制限なしの起動確認と制限ありの結果を分け、親終了コード・子生成・標準エラーを安全に確認する。実体の切替や取得結果を元の再現と混同せず、終了・時間制限を証明できるまでは実書込みを無効に保つ。試験実行は当該処理の停止条件と承認済み計画を優先する。
- F-016: 既知の Issue 番号はリポジトリと番号で直接取得し、タイトルの全文検索語に番号を代用しない。検索が必要なら検索対象フィールドと構文を先に確認し、空結果と不存在を区別する。テスト名の場合も終了コードに加えて実行件数を確認する。

上記は具体的な運用追記案であり、登録・採用や対象資料の更新は管理者が判断する。既存手順を廃止・緩和せず、ユーザーの同種２回停止を優先する。追加の Skill 提案なし。再発防止の効果、F-073 の真の原因と全終了経路は未確認。
