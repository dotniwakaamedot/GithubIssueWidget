## P01: 出力量が不明な資料は分けて表示する

- 優先度: 高。F-001 発生42に基づく。次担当: 資料の取得担当。`AGENTS.md` 追記案: 「出力量が不明な資料は１回に１文書の必要な短い範囲を表示する。複数結果を一括表示するときは、各結果の最大長、包装の増加と内外上限を確認し、合計に余裕を設ける。」
- 期待効果は合計量の見積り漏れの低減。費用は呼出し回数の増加。分割で文脈を失うリスクがあり、必要な全範囲・元の終了結果を別に確認する。次回の複数資料取得で対象・範囲・完全性を記録し、継続観察する。

## P02: 外部一覧の型・完全性・安全な失敗診断を確認する

- 優先度: 高。F-075 と F-064 に基づく。次担当: GitHub 検証担当。`AGENTS.md` 追記案: 「外部一覧を集計する前に、合成例で JSON の型・配列の階層・要素数とページ結合の形を確認し、実応答の集計では終了結果・ページ取得完了・項目数を別々に確認する。失敗時は認証情報や応答本文を出さず、取得可能なエラー種別と HTTP 状態等の安全な診断情報を残す。取得失敗や空結果を対象の不存在とみなさない。」
- 期待効果は誤集計と原因切り分け不能の低減。費用は合成試験とページ確認。診断情報自体も機密を含む可能性があるため明示的に選別し、完全性の確認は件数表示だけで代用しない。次回は既知２件以上の合成配列、ページ失敗、空結果を検証し、実応答の秘密を露出せず証跡を確認する。
