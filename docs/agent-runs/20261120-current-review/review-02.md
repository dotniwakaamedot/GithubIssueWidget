## 指摘

### B1: 移動時の並行更新で他者のラベルを上書きする

- 根拠: `widget/src-tauri/src/movement.rs:21-27` は Issue を GET して `updated_at` を照合した後、取得時点の非ステータスラベルを含む全ラベル配列を生成し、条件なしで PATCH する。PATCH 応答を検査する `:32-35` は、送信した配列との一致しか検査しない。
- 再現可能な順序: GET と PATCH の間に別の利用者が `bug` ラベルを追加すると、この PATCH は GET 時点の配列で置換するため、追加が失われ得る。取得時の `updated_at` 比較は GET より前の変更しか検出しない。アプリ内・同一ホストのロックは外部 GitHub 利用者を排他しない。この競合そのものは実 GitHub や試験サーバーで再現実行しておらず、コード上の条件付き帰結である。
- 影響: ユーザーが移動するだけで他者のラベル更新が消え、送信値どおりの応答なら成功と扱う。既存の6方向試験はラベル保持の正常系であり、この時間差競合の証拠ではない。
- 修正案: GitHub API が提供する対象操作の条件付き更新を調査して実際に有効なら採用し、同時更新を検出して中断する。利用できない場合、非ステータスラベルの全置換を避ける更新設計と部分失敗の明示を検討し、残る競合制約を明記する。GET と書込みの間に非ステータスラベルを追加する決定的な模擬試験で他者更新を失わないことを検証する。
