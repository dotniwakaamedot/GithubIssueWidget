# 実 GitHub 検証計画 01

- ユーザー原文: 「現在の進行状況を確認しアプリの完成まで進行してください。一度の処理で2度同じ失敗をした時は停止してください」「現在のリポジトリはダメですか」「書き込みを承諾します。」
- 対象: 公開リポジトリ dotniwakaamedot/GithubIssueWidget。追加する status:todo と status:done、検証用 Issue １件の作成・移動・クローズは承認済み。Issue と履歴、追加ラベルは公開されたまま残す。
- 準備: 既存ラベルを読み取り済みで、status:todo と status:done の追加・読戻しを実施済み。公開状態と認証権限を確認済み。検証用マーカーを固定し、同一マーカーの Issue がないことを確認してから１回だけ作成を試みる。
- 方法: アプリの Rust 作成処理で Todo を１件作成し、当該 Issue に既存の非ステータスラベルを１つ付け、同じ移動処理で６方向と最終 Done を検証する。各操作後に GitHub を読み戻し、状態・ステータスと非ステータスラベルを照合する。問題時は後続を停止し、Issue 番号またはマーカーで実際の状態を確認し、勝手に重複作成しない。テストは実 UI ではなく Rust 処理が対象。
- 認証: GitHub CLI の認証情報をプロセス内に一時的に読み取り、子に環境変数で渡す。秘密と Issue 本文を出力・ログ保存しない。未確認やタイムアウトを成功扱いせず、作成結果不明時は API の読戻しを優先し再投稿しない。
- 保護: 作成前記録と途中状態を一意の隔離フォルダーに保存し、終了時も保持する。既存 Issue、PR、資格情報、他 worktree、ログを変更・削除しない。確実な cleanup やユーザーの追加許可なしに fixture・ラベル・履歴を削除しない。
- 完了条件: アプリ作成処理・６方向・非ステータスラベル保持・最終クローズを GitHub の読戻しで確認し、対象版と Issue URL、途中失敗、未検証を記録する。実 UI や認証登録をこの試験で検証済みとしない。
