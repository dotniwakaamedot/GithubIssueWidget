# 実 GitHub 読み取り専用試験の計画・コードレビュー

判定: **指定コードと記載された計画の範囲を承認**。blocking なし。実行スクリプトそのものは提示されていないため、トークン取得・環境復元・ログ権限の実装は承認対象外であり、実行前に管理担当が確認する必要がある。

- `main.rs` SHA256 `021488C4C1615EBEFA3185EBDF024A43547657E357715957128F403541A67A97` は依頼値と一致。対象 ignored テストは指定された owner/repo に対して repository GET と Issue ページ GET のみ行う。`get_api_response_locked` は GET を使用し、リダイレクトは禁止される。対象操作は GitHub 状態や資格情報を変更しない。`RateCooldown::default()` は永続化を無効にするため、レート制限時の cooldown はメモリー内に限られる。
- owner/repo は構成文字種を制限し、ページ送りは HTTPS のホスト・ポートと対象リポジトリの Issue パスまたはその数値 ID のパスに制限される。テスト自体は指定の特定リポジトリを固定していないので、実行側は owner/repo を計画値に固定・確認する必要がある。
- HTTP 失敗時は固定メッセージで失敗し、成功時の出力は件数だけで、トークン・Issue タイトル・本文を出力するコードはない。トークンは子プロセス環境変数に一時存在するため、そのプロセス環境へアクセスできる主体からの秘匿は保証しない。パニックやビルドツールの予想外の診断を含む生ログに秘密がないことは実行後の安全な確認が必要。
- 指定ローカルログは 65 passed・10 ignored と URL 1 passed を示す。対象の実 GitHub 試験は ignored であり、通常テスト成功は本試験成功を意味しない。ログ自身はソース SHA256 を証明せず、対象版との対応は依頼記載に依存する。レビューでは試験再実行・実 GitHub・実資格情報へのアクセスはしていない。

non-blocking: 計画に具体的な実行スクリプトがないため、`gh auth token` 失敗時の処理、標準エラーやログへの漏出防止、環境変数の元値復元、ログのアクセス権・保持方法を独立に確認できない。管理担当は実行前に正確なコマンドを点検し、失敗時も `finally` で元の有無と値を復元し、出力を秘密を含まない最小限にすること。実行結果は対象 repo の GET 成功・解析範囲に限定し、実 UI・書込み・権限全般や非公開リポジトリの可視性の証明としない。
