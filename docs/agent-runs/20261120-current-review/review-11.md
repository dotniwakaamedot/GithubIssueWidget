# 実行スクリプト修正版のレビュー

判定: **要修正（blocking 1 件）**。前回指摘した PowerShell 5.1 の `2>&1` と `ErrorActionPreference=Stop` の組合せはなくなったが、タイムアウト時の子プロセス管理が未完了。

## blocking: タイムアウトで子孫プロセスが残り得る

- 根拠: `readonly-execute-09.ps1:17-20` は起動した `cargo.exe` または `gh.exe` だけに `Kill()` を送る。Cargo はテスト実行ファイルなどを子として起動するため、Windows のこの呼出しだけでは子孫の終了は保証されない。また `:24-25` のストリーム読取り完了待ちは、子孫がパイプを保持すると親の終了後も完了しない可能性がある。
- 影響: タイムアウトを報告し親の環境を復元した後も、子テストが認証情報を保持して GitHub GET を継続し得る。場合によっては読取り完了待ちがタイムアウトを超える。実際の Cargo・GitHub での残留は検証しておらず、コードに基づくリスクである。
- 修正案: 子孫を含めた終了と終了確認を保証する Windows のジョブオブジェクト等を検討し、標準出力・標準エラーの読取りも期限内に確定させる。外部通信を行わないダミー親子プロセスで、親正常終了時のパイプ保持、タイムアウト、子孫終了、待機上限と環境復元を検証する。終了未確認を成功扱いしない。

## 確認した範囲

- スクリプト SHA256 `F9FFDE180799EFB3A93A6B7B9DF04B69DA0CAD627D9548066525CE2CC22FC05E` は依頼値と一致。
- `ProcessStartInfo` は両ストリームを別々に非同期読取りし、固定された要約だけを表示する。標準エラーが通常出力された場合の前回の停止経路は解消される。ダミー Python 試験の成功は依頼者の報告であり、ログ・試験条件は提示されず独立確認していない。
- 対象 owner/repo は固定され、取得失敗は拒否、`finally` は3環境変数を元に戻し参照をクリアする。強制終了時や実行前からの子孫に対する保証ではない。トークンの完全一致検出は変形・分割された漏出を網羅せず、子プロセス環境にトークンは存在する。
- 生ログは保存しない。スクリプト全体、実認証、GitHub へのアクセスは実施していない。今回のレビューで失敗は発生していない。
