# F-001 発生29の独立検討

- 担当: `/root/failure_review`。対象: 依頼書 `request-01.md` に記載された発生29。
- 確認した事実: 依頼時点の失敗記録では F-001 は累計28回で、そのうち発生10・21・23は暫定集計。既存の教訓には長い行や複数結果の合計量、分割取得、切り詰め後の証拠の扱いがある。今回、複数のコマンド結果を JSON 形式でまとめた表示に、内側と外側の切り詰め表示がある。
- 原因の見立て: 結果全体をまとめて表示する際に、各結果の出力量と JSON の包装・エスケープを含む合計量に対して、出力上限の見積もりが不足した可能性がある。各層の欠落内容や詳細な切り詰め位置は未確認。
- 提案: 並列実行と結果表示を分け、各結果は終了コード、件数と必要な短い範囲だけを選んで個別に表示する。複数結果の合計に加え JSON 包装・エスケープ、見出しやエラーの増加分も内側・外側の出力上限に含めて見積もる。完全性が必要な場合は、既存ログを優先し、安全に再取得できる対象のみ小分けして確認する。失われた部分や省略表示を完全な証拠としない。
- 既存ルールとの差分: 合計量と分割は既存の原則であり、上記は複数ツール結果を JSON にまとめる場面の具体化である。新たなルールが再発を防げるかは未検証。
- 記録の提案: 失敗 ID・対象の発生・担当者ごとの意見・採否と理由・変更先・対象版を共有記録に残し、独立レビューと親の読戻しを経て確定する。
