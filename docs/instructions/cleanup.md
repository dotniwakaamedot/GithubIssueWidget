## 完了後の整理

詳細は [完了後整理](../task-cleanup-check.md) を参照する。

- 原則として別の担当に読み取り専用の確認を一度依頼し、結果を待つ。担当が利用できなければ親が同じ確認を行い報告する。
- 管理方式と GitHub 連携を確認し、該当する場合だけ Git の worktree・ブランチや GitHub の Issue・PR を調べる。非 Git の対象では Git/GitHub 固有の項目を該当外とし、適用可能な一時物の所有・使用・保管の必要性を確認する。
- 確認と削除は別に扱う。親は削除直前に対象の絶対パス、内容、所有者、使用状況、適用指示と各削除操作への認可を確認する。認可や内容が不明なら保留する。
- Git で閉じた Issue に関連する worktree の未コミット・未追跡・ignored を含む削除は、対象と未保存物の内容、作業終了、それらを含む削除の許可を個別に確認できた場合だけ行う。
- 現在の checkout、使用中、所有者不明、確認失敗は保留する。その他も保持が必要、未統合、利用予定不明、保護中または確認不能なら保留し、結果と理由を報告する。
