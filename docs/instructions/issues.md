## Issue とレビュー

詳細は [Issue 運用](../issue-workflow.md) と [Git/GitHub 連携](../adapters/git-github.md) を参照する。

- リポジトリと Issue 番号が既知の場合は番号を指定して取得する。番号をタイトル検索語として代用せず、空の検索結果や取得失敗を対象の不存在とみなさない。

- Issue の起票時は事実・根拠と提案・推測を分け、既知の対象版、再現手順、期待結果・実際の結果、未確認事項を記録する。起票後に既存実装・テスト・関連 Issue を調査し、目的、対応案と検証可能な完了条件を本文に整理する。着手前に範囲と検証が判断できるか確認し、不足時は保留理由と次の調査を記録する。
- 状態を調査・詳細化、着手待ち、着手中、PR 承認待ち、保留として記録し、設定された状態ラベル以外を保持する。ラベルとコメントは排他ロックではない。着手・再開前後に担当、関連 PR、既存 run を照合し、競合や記録・読戻しの不明を成功扱いにしない。
- Issue の完了を目的とする PR のマージと対応関係を確認後、未クローズなら権限を確認してクローズし、結果を読戻す。単なる言及・部分対応は対象外とする。PR の承認を偽装せず、マージは適用される指示と認可に従う。
